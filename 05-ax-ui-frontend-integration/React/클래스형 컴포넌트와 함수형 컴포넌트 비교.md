React의 **클래스 컴포넌트와 함수 컴포넌트는 모두 화면을 구성하는 방법**입니다. 핵심 차이는 **컴포넌트를 정의하는 문법과 상태·로직을 관리하는 방식**에 있습니다.

**클래스 컴포넌트는 클래스와 메서드**, **함수 컴포넌트는 함수와 Hooks**를 중심으로 작성합니다.

| 비교 항목 | 클래스 컴포넌트 | 함수 컴포넌트 |
|---|---|---|
| 정의 방법 | `class`로 정의하고 `Component` 상속 | 함수로 정의 |
| 화면 반환 | `render()` 메서드에서 JSX 반환 | 함수에서 JSX 반환 |
| props 접근 | `this.props` | 함수 매개변수 |
| 상태 관리 | `this.state`, `this.setState()` | `useState`, `useReducer` |
| `this` 사용 | 컴포넌트 인스턴스에 접근할 때 사용 | 컴포넌트 인스턴스의 `this` 불필요 |
| 생명주기 관련 처리 | 생명주기 메서드 사용 | 외부 시스템 동기화에는 `useEffect` 등 사용 |
| 로직 재사용 | HOC, Render Props 등의 패턴 | 커스텀 Hook |
| Hooks 사용 | 클래스 내부에서는 사용 불가 | 사용 가능 |
| 주된 학습 목적 | 기존 코드 이해·유지보수 | 새 컴포넌트 작성 |

**1. 가장 기본적인 문법 차이**

다음 두 코드는 모두 전달받은 이름을 화면에 표시합니다.

클래스 컴포넌트:

```jsx
import { Component } from "react";

class Greeting extends Component {
  render() {
    return <h1>안녕하세요, {this.props.name}님!</h1>;
  }
}

export default Greeting;
```

함수 컴포넌트:

```jsx
function Greeting({ name }) {
  return <h1>안녕하세요, {name}님!</h1>;
}

export default Greeting;
```

사용 방법은 같습니다.

```jsx
<Greeting name="심플" />
```

클래스에서는 **인스턴스의 `this.props`**를 통해 데이터를 읽습니다. 함수에서는 **매개변수로 props를 받으며**, 위 예제는 구조 분해 할당으로 `name`을 꺼낸 것입니다.

**2. 상태를 저장하고 변경하는 방식**

상태는 **클릭 횟수, 입력값, 로그인 여부처럼 화면에 영향을 주는 데이터**입니다.

클래스 컴포넌트:

```jsx
import { Component } from "react";

class Counter extends Component {
  state = { count: 0 };

  handleClick = () => {
    this.setState((prev) => ({
      count: prev.count + 1,
    }));
  };

  render() {
    return (
      <button onClick={this.handleClick}>
        클릭 횟수: {this.state.count}
      </button>
    );
  }
}
```

함수 컴포넌트:

```jsx
import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  function handleClick() {
    setCount((prev) => prev + 1);
  }

  return (
    <button onClick={handleClick}>
      클릭 횟수: {count}
    </button>
  );
}
```

두 코드의 대응 관계는 다음과 같습니다.

| 역할 | 클래스 | 함수 |
|---|---|---|
| 초기 상태 설정 | `state = { count: 0 }` | `useState(0)` |
| 상태 읽기 | `this.state.count` | `count` |
| 상태 변경 요청 | `this.setState(...)` | `setCount(...)` |
| 업데이트 시 UI 계산 | `render()` 실행 | 컴포넌트 함수 실행 |

여기서 중요한 점은 **함수가 다시 실행되어도 React가 상태를 보관한다**는 것입니다.

```jsx
const [count, setCount] = useState(0);
```

이 코드는 렌더링할 때마다 `count`를 무조건 `0`으로 초기화한다는 뜻이 아닙니다. 같은 컴포넌트가 유지되는 동안 React는 이전에 저장한 상태를 돌려줍니다.

또한 두 방식은 **객체 상태를 갱신하는 규칙**이 다릅니다.

```jsx
// 클래스: 전달한 속성을 기존 state에 얕게 병합
this.setState({ name: "김철수" });

// 함수: 기존 객체의 다른 속성을 유지하려면 직접 복사
setUser((prev) => ({
  ...prev,
  name: "김철수",
}));
```

**3. 생명주기와 외부 작업을 처리하는 방식**

두 종류의 컴포넌트 모두 **화면에 추가되고, 업데이트되고, 제거되는 과정**을 거칩니다.

클래스에서는 그 시점에 맞는 메서드를 정의합니다.

| 시점 | 클래스 메서드 | 활용 예 |
|---|---|---|
| 마운트: 화면에 추가됨 | `componentDidMount()` | 타이머 시작, 연결 설정 |
| 업데이트: 변경 사항이 반영됨 | `componentDidUpdate()` | 변경된 props에 맞춰 연결 갱신 |
| 언마운트: 화면에서 제거됨 | `componentWillUnmount()` | 타이머 해제, 연결 종료 |

예를 들어 1초마다 숫자를 증가시키는 타이머는 다음과 같습니다.

클래스 컴포넌트:

```jsx
import { Component } from "react";

class Timer extends Component {
  state = { seconds: 0 };

  componentDidMount() {
    this.timerId = setInterval(() => {
      this.setState((prev) => ({
        seconds: prev.seconds + 1,
      }));
    }, 1000);
  }

  componentWillUnmount() {
    clearInterval(this.timerId);
  }

  render() {
    return <p>{this.state.seconds}초 경과</p>;
  }
}
```

함수 컴포넌트:

```jsx
import { useEffect, useState } from "react";

function Timer() {
  const [seconds, setSeconds] = useState(0);

  useEffect(() => {
    const timerId = setInterval(() => {
      setSeconds((prev) => prev + 1);
    }, 1000);

    // 정리 함수: 타이머 해제
    return () => {
      clearInterval(timerId);
    };
  }, []);

  return <p>{seconds}초 경과</p>;
}
```

클래스에서는 **타이머 시작과 해제가 서로 다른 메서드에 나뉘어** 있습니다. 함수에서는 **관련된 설정과 정리를 하나의 Effect에 함께 작성**할 수 있습니다.

다만 **`useEffect`를 생명주기 메서드의 단순한 대체 이름으로 이해하면 부정확합니다.** 목적은 타이머, 네트워크 연결 같은 외부 시스템과 컴포넌트를 동기화하는 것입니다. 의존성이 바뀌면 이전 작업을 정리한 뒤 다시 설정할 수 있습니다. [react.dev](https://react.dev/reference/react/Component?utm_source=chatgpt.com)

**4. 함수 컴포넌트에서 Hooks가 중요한 이유**

함수 컴포넌트는 Hooks를 이용해 React의 기능을 사용합니다.

| Hook | 주요 역할 |
|---|---|
| `useState` | 상태 저장 및 변경 |
| `useReducer` | 복잡한 상태 변경 로직 관리 |
| `useEffect` | 외부 시스템과 동기화 |
| `useContext` | 상위에서 제공한 공통 값 읽기 |
| `useRef` | DOM 참조 또는 렌더링 사이에 값 보관 |

따라서 **“함수 컴포넌트는 화면만 표시하고 상태를 가질 수 없다”는 설명은 Hooks 도입 이전의 설명**입니다.

또한 상태와 Effect를 묶어 **커스텀 Hook**으로 추출하면 여러 컴포넌트에서 같은 로직을 재사용하기 쉽습니다. 이때 공유하는 것은 로직이며, 각 호출의 상태가 자동으로 하나로 공유되는 것은 아닙니다.

**5. 학생들에게 설명할 때의 핵심**

> **클래스 컴포넌트는 객체에 상태를 두고 메서드로 UI를 계산하는 방식이고, 함수 컴포넌트는 React가 보관하는 상태를 Hooks로 사용하면서 함수로 UI를 계산하는 방식입니다.**

새로운 코드를 배우는 경우에는 **함수 컴포넌트 → props → `useState` → 이벤트 처리 → `useEffect` → 커스텀 Hook** 순서로 학습하면 연결이 자연스럽습니다. 클래스 컴포넌트는 위 개념을 익힌 후 기존 코드를 읽을 수 있는 수준으로 비교하면 이해하기 쉽습니다.
