# 기술 스택 선정

기술 스택 선정에서 익숙한 환경을 선택하는 것도 생산성과 숙련도 면에서 좋은 방법이다. 하
지만 AI 에이전트를 제대로 활용하려면 관점을 달리해야 한다. 핵심은 시장에 빠르게 MVP를
출시하는 것, 그리고 에이전트를 통해 오류를 빠르게 디버깅하는 것이다. 따라서 단순히 익숙
하거나 최신이라는 이유보다는 다음 기준으로 기술을 선정해야 한다.

• AI 친화성: 학습 데이터가 풍부하여 AI가 정확한 코드를 생성하는가?

• 타입 안정성: 런타임 에러를 코드 작성 시점에 잡아낼 수 있는가?

• 배포 용이성: 무료 또는 저비용으로 빠르게 배포할 수 있는가?

결론적으로 AI 친화적인 기술 선정, 타입 체킹을 통한 런타임 에러 최소화, 무료 배포가 가능
한 생태계 등을 고려해서 기술 스택을 선정하기를 추천한다.


## 1. 프런트엔드: React + TypeScript

AI 코딩에서 간단한 타입 오류도 누적되면 시간 소모와 스트레스 요인이 된다. 기술 스택 선정
단계에서 이런 문제를 미리 제거하는 것이 중요하다. 프런트엔드는 React + TypeScript 조
합을 추천한다. 깃허브 저장소 수가 압도적으로 많아 가장 방대한 자료를 갖추고 있으며, IDE
지원, 타입 안정성, Vercel 무료 호스팅까지 고려하면 JavaScript보다 TypeScript가 유리
하다.

## 2. 백엔드: ㅜNode.js + Express/Next.js API Routers

파이썬 + FastAPI가 적합한 경우

데이터 분석, 머신러닝, AI 모델 개발이 핵심인 프로젝트라면 파이썬 + FastAPI가 더 적합하
다. 판다스Pandas, 넘파이NumPy, 파이토치PyTorch, 사이킷런Scikit-learn 등 파이썬의 데이터 과학 생태
계는 대체 불가능하다. FastAPI는 파이썬 백엔드 중 타입 힌트를 가장 잘 활용하며, 자동 API
문서 생성 기능도 제공한다. 다만 타입이 런타임에 강제되지 않는 파이썬의 근본적인 한계는
여전히 존재한다.
