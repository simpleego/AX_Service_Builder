# 3. 사용자 스토리 정의

사용자 스토리User Story는 요구사항을 사용자의 관점에서 서술하는 기법이다. 기능/비기능 요구사항이 어떤 기능을 처리하는가와 시스템이 무엇을 처리하는가에 초점을 맞추었다면, 사용자스토리는 '사용자가 왜 그 기능을 필요로 하는가'를 드러낸다. 형식은 다음과 같다.

- [역할]로서, [행동]을 할 수 있다. 그래서 [가치/목적]을 달성한다

이 형식에서 가장 중요한 부분은 마지막의 가치/목적이다. '사용자는 할 일을 추가할 수 있다'에서 한 걸음 더 나아가 '왜 추가해야 하는가'를 밝히면, 기능의 우선순위를 판단하는 기준이 된다.   
또한 AI에게 프롬프트를 줄 때 '사용자가 이 기능으로 무엇을 얻는지' 컨텍스트를 함께 전달하면 더 적절한 UI와 흐름을 설계한다.  
- 사용자 스토리 → 기능 요구사항 → 테스트 케이스 매핑

테스트 케이스는 TEST_CASES.md에 별도로 정의하였으므로 깃허브를 참고하기 바란다.
