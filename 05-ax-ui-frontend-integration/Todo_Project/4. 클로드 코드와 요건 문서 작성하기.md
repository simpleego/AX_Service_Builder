# 4.3 클로드 코드와 함께 요건 문서 작성하기

이제 정의한 내용들을 실제 프로젝트의 문서 체계(마크다운)로 구체화할 차례다. 이번 절에서는 클로드 코드와 대화하며 프로젝트 구조를 잡고, 오류사항을 점검한 뒤 개발 문서를 작성하고, TDD 방식의 개발 흐름을 만들어가는 과정을 다룬다.

## 4.3.1 프로젝트 구조 및 실제 개발 계획 수립하기

4장에서 전반적으로 설명한 기술 스택과 요건 정의를 토대로 다음과 같이 프로젝트 구조를 설계하였다. 여기서 중요한 점은 개발자가 판단해서 선택하는 것이 우선이고, 만약 택이 어렵다면 클로드 코드에게 택지 중에 현재 프로젝트에 더 적합한 기술이 무엇인지 물어보거나, 선택하고자 하는 기술이 앱의 구조, 화면 구성과 기능, 배포 환경 등을 고려해서 추천해줄 수 있는 기술인지를 체크하면 된다.
