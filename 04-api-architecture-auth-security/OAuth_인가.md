# 웹개발에서 OAuth 2.0은 어느 부분에 이용되나?

현대 웹 개발에서 OAuth 2.0은 선택이 아닌 필수적인 표준(Standard)에 가깝습니다. 단순히 "편리한 로그인 기능"을 제공하는 것을 넘어, 서비스 간 안전한 권한 위임(Delegation)과 **분산 인증 아키텍처**를 구축하는 핵심 메커니즘이기 때문입니다.

만약 서비스가 완전히 독립되어 있고 외부 연동이나 소셜 로그인이 전혀 필요 없다면 직접 구현한 세션/토큰 방식으로 대체할 수 있지만, 현대 웹 생태계에서는 거의 모든 서비스가 OAuth 2.0 기반의 인증/인가 체계를 활용합니다.

---

### 1. 웹 개발에서 OAuth 2.0이 반드시 필요한 이유 (필요성)

* **비밀번호 노출 방지 (Credential Sharing 방지):** 사용자가 타 서비스(예: 내 앱)에 구글이나 네이버 비밀번호를 직접 제공하지 않고도, 인증된 토큰(Access Token)만을 받아 안전하게 자원에 접근할 수 있습니다.
* **사용자 경험(UX) 극대화:** 사용자가 서비스마다 새로운 ID/PW를 만들고 기억해야 하는 번거로움을 없애 가입 전환율을 크게 높여줍니다.
* **표준화된 보안 프로토콜:** 인증 및 권한 부여 과정을 직접 설계하면 보안 취약점이 발생하기 쉽지만, OAuth 2.0은 검증된 표준 사양(RFC 6749)을 따르므로 보안 리스크를 크게 줄여줍니다.

---

### 2. OAuth 2.0이 주로 이용되는 영역 (활용처)

#### ① 소셜 로그인 (Social Login / 간편 로그인)

가장 흔하게 쓰이는 용도로, "Google로 로그인", "카카오 로그인", "Naver 로그인", "GitHub 로그인" 등을 구현할 때 사용됩니다.

* *원리:* 사용자가 소셜 계정으로 인증을 마치면, 서비스는 소셜 플랫폼으로부터 사용자 식별자(UID)와 프로필 정보를 받아 자체 회원 관리 시스템과 연동합니다. (실제 인증 정보 확인은 OpenID Connect(OIDC)가 결합되어 수행됩니다.)

#### ② 제3자 서비스의 외부 API 접근 및 권한 위임 (Delegation)

내 웹 서비스가 사용자의 동의를 받아 **외부 플랫폼의 데이터나 기능을 조작**해야 할 때 사용합니다.

* *예시:*
* 사용자의 동의를 받아 **Google Drive API**를 통해 파일 목록을 읽어오거나 업로드하는 웹앱
* 사용자의 **GitHub 계정**에 접근해 레포지토리 목록을 가져오거나 자동으로 코드를 푸시하는 CI/CD 서비스
* 사용자의 **Slack API**를 이용해 채널에 자동으로 알림 메시지를 보내는 서비스



#### ③ SPA(Single Page Application)와 마이크로서비스 아키텍처(MSA)의 인증 체계

React, Vue 같은 프론트엔드와 Spring Boot, FastAPI 등의 백엔드 API 서버가 분리된 구조에서 API 서버의 보안을 보호할 때 사용됩니다.

* 클라이언트(브라우저/앱)는 OAuth 2.0 / OIDC 기반으로 인증을 거쳐 **Access Token과 Refresh Token**을 발급받고, 이후 모든 API 요청 시 `Authorization: Bearer <token>` 헤더를 실어 보내 안전하게 자원을 요청합니다.
