# 토큰 기반 인증(Token-Based Authentication)
> 토큰 기반 인증(Token-Based Authentication)은 인증 방식의 한 종류이고, JWT(JSON Web Token)는 그 방식에서 사용할 수 있는 여러 토큰 형식 중 하나입니다.

즉, 토큰 = JWT는 아닙니다. JWT 이외에도 다양한 토큰 형식이 존재합니다.

참고로 세션과 토큰은 완전히 배타적인 개념은 아닙니다. 세션 기반 인증에서도 세션 ID라는 토큰을 쿠키로 전달할 수 있습니다. 실제 시스템에서는 두 기술을 조합하기도 합니다.

## 2. 대표적인 토큰 형식 비교

| 구분        | JWT              | Opaque Token        | PASETO           |
| --------- | ---------------- | ------------------- | ---------------- |
| 토큰 형태     | 구조화된 JSON 데이터    | 의미 없는 임의 문자열        | 구조화된 보안 토큰       |
| 사용자 정보 포함 | 가능               | 일반적으로 포함하지 않음       | 가능               |
| 검증 방법     | 서명·클레임 검증        | 서버 조회 또는 검증 서비스 호출  | 서명 검증 또는 인증된 복호화 |
| 서버 상태 저장  | 필수 아님            | 보통 필요               | 필수 아님            |
| 즉시 무효화    | 별도 관리 필요         | 상대적으로 용이            | 별도 관리 필요         |
| 대표 활용     | REST API, 분산 서비스 | 웹 로그인, OAuth 액세스 토큰 | 보안 중심 애플리케이션     |

JWT와 Opaque Token은 OAuth 2.0에서도 사용되는 대표적인 액세스 토큰 형식입니다.&#x20;

## 4. OAuth2, Access Token, Refresh Token과 JWT는 어떤 관계인가?

이 부분도 구분해야 합니다.

| 기술 용어                | 역할                                |
| -------------------- | --------------------------------- |
| OAuth 2.0            | 접근 권한을 위임받고 액세스 토큰을 발급·사용하는 프레임워크 |
| OpenID Connect(OIDC) | OAuth 2.0 기반 사용자 인증 계층            |
| Access Token         | API 접근 권한을 나타내는 토큰                |
| Refresh Token        | 새로운 Access Token 발급에 사용하는 토큰      |
| JWT                  | 토큰 데이터를 표현하는 형식                   |
| Bearer               | 토큰을 소지한 주체가 제시해 사용하는 방식           |

예를 들어 OAuth 2.0을 사용하면서 Access Token을 JWT로 발급할 수도 있고, Opaque Token으로 발급할 수도 있습니다.&#x20;

## 5. 교육과정에서는 어떻게 설명하는 것이 좋은가?

FastAPI 기반 웹 인증을 학습한다면 다음 순서가 명확합니다.

1. 세션 기반 인증 — 서버가 로그인 정보를 보관하는 원리
2. Opaque Token — 토큰을 서버에 저장하고 조회하여 검증하는 방식
3. JWT — 서명된 토큰을 서버가 직접 검증하는 방식
4. Access / Refresh Token — 만료와 재발급 정책
5. OAuth 2.0 / OIDC — 외부 인증·인가 및 소셜 로그인

핵심 결론: JWT는 토큰 인증 자체를 의미하는 것이 아니라, 토큰을 표현하고 보호하기 위한 표준 형식입니다. 따라서 JWT를 사용하지 않아도 토큰 기반 인증을 충분히 구현할 수 있습니다.
