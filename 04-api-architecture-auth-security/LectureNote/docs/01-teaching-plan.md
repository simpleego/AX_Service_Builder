# 전체 과정 연결과 48시간 진행안

## 전체 커리큘럼에서 4과목의 위치

제공된 전체 과정은 ① AX 프로젝트 기획·UX(72H) → ② AI-Augmented 백엔드 개발(40H) → ③ 관계 데이터 모델링·데이터 아키텍처(40H) → ④ API 아키텍처·인증 보안(48H) → ⑤ React UI·프런트엔드(56H) → ⑥ AI Native 개발·품질 자동화(48H) → ⑦ LLM·RAG(56H)로 이어집니다.

4과목에서는 새 서비스와 프런트를 동시에 만드는 부담을 줄이고, 2과목의 FastAPI·DI·예외 처리, 3과목의 MySQL·SQLAlchemy·인덱스·트랜잭션을 **개인 Todo API의 계약과 보안**에 적용합니다. 5과목에서는 이 API를 React에 연결하고, 6과목에서는 아래 Postman 검증을 CI로 확장할 수 있습니다. ORM 모델 변경과 Alembic 자체 교육은 3과목 영역이므로 이 자료는 명시적 SQL 초기화 스크립트를 제공합니다.

## 학습 목표와 범위

- 리소스 중심 URI, 메서드 의미, 201/204/401/404/409/422를 설명하고 구현한다.
- 자연어 요구사항을 DTO·상태코드·오류·인증 계약으로 바꾼다.
- JWT 서명/만료/발급자/대상을 검증하고 사용자별 데이터 접근을 제한한다.
- 리프레시 토큰을 DB에 해시로 저장하고 회전·재사용 탐지·로그아웃을 구현한다.
- OAuth2 인가와 OIDC 인증을 구분하고 Google 신원을 앱 사용자와 연결한다.
- HTTP·업무·데이터 접근 책임을 분리하고 자동 생성 OpenAPI/Swagger를 검증한다.
- 성공 사례뿐 아니라 타인 접근·잘못된 토큰·입력 오류까지 Postman으로 재현한다.

## 학생이 구현할 권장 순서

1. ERD 확인 → MySQL 계정/스키마 → `.env` → `/health`.
2. `schemas.py` 입력/출력 정의 → `todos.py`의 생성/목록 → 상세/수정/삭제.
3. 상태코드와 오류 규격을 먼저 합의하고 `/openapi.json`을 읽는다.
4. 비밀번호 해시 → 회원가입 → 로그인 JWT 발급 → 검증 의존성 → owner 조건.
5. refresh 저장 → 정상 회전 → 이전 토큰 재사용 차단 → 로그아웃.
6. Google 콘솔 → state/cookie → PKCE 코드 교환 → ID 토큰 검증 → 신원 연결 → 앱 토큰.
7. 한 파일의 Todo 로직을 repository/service/controller로 추출하고 동작이 같은지 확인한다.
8. 수동 Postman 요청을 변수와 검증 스크립트가 있는 실행 가능한 시나리오로 만든다.

처음부터 v06 전체를 복사하기보다 단계별 README의 목표를 구현한 뒤 완성 소스와 비교합니다. 3과목 경험이 부족하면 DB 준비 1시간을 v01 실습 시간에 포함합니다.
