# OIDC와 OAuth 2.0 프로토콜

<img width="1024" height="559" alt="image" src="https://github.com/user-attachments/assets/24335003-b3a1-41dc-8164-4fa6851b4603" />


OIDC(OpenID Connect)는 OAuth 2.0 프로토콜을 기반으로 만들어진 **인증(Authentication) 표준 프로토콜**입니다.

쉽게 말해, 웹이나 모바일 애플리케이션에서 사용자가 누구인지(신원)를 안전하게 확인(로그인)할 수 있도록 해주는 개방형 표준입니다.

---

## 1. 인증(Authentication) vs 인가(Authorization)의 차이로 이해하기

* **OAuth 2.0**: "이 앱이 내 구글 드라이브 파일에 접근해도 돼"처럼 권한(인가, Authorization)을 위임하기 위한 표준입니다. 하지만 사용자가 누구인지 정확히 증명하는 기능 표준은 부족했습니다.
* **OIDC**: OAuth 2.0의 뼈대(인증 서버, 토큰 등)를 그대로 활용하되, "이 사용자의 이름은 홍길동이고, 이메일은 a@b.com이며, 로그인이 완료되었다"는 신원 정보(인증, Authentication)를 안전하게 전달하는 기능이 추가된 상위 레이어입니다.

## 2. 핵심 구성 요소

OIDC는 신원 확인을 위해 기존의 액세스 토큰(Access Token) 외에 ID 토큰(ID Token)이라는 것을 추가로 발급합니다.

* **ID Token**: JWT(JSON Web Token) 형식으로 이루어져 있으며, 사용자의 고유 식별자, 이메일, 이름, 발행 시간 등 사용자의 프로필 정보(Claims)가 암호화되거나 서명되어 들어 있습니다. 애플리케이션은 이 토큰을 까보아서 사용자가 누구인지 신뢰성 있게 알 수 있습니다.

## 3. 우리가 흔히 쓰는 "소셜 로그인"의 원리

우리가 웹사이트에서 **"구글로 로그인"**, **"카카오로 로그인"**, **"Apple로 로그인"** 버튼을 눌러 로그인할 때 백그라운드에서 동작하는 표준 기술이 바로 OIDC입니다.

1. 사용자가 "구글로 로그인"을 클릭합니다.
2. 우리 서비스가 구글 인증 서버로 사용자를 보냅니다.
3. 사용자가 구글 계정으로 로그인하면, 구글(인증 서버)은 우리 서비스로 **ID 토큰**과 **Access Token**을 전달합니다.
4. 우리 서비스는 ID 토큰을 검증하여 "아, 이 사람이 구글의 누구구나!" 하고 파악한 뒤 자체 세션을 열어줍니다.

## 요약

OIDC는 "OAuth 2.0 위에 사용자 인증(ID Token) 기능을 얹어, 여러 서비스 간에 안전하고 표준화된 방식으로 로그인을 처리할 수 있게 해주는 프로토콜"입니다.
