# 강사 운영안 및 평가

## 수업 전 준비

학습자가 함수, 배열 map/filter, 구조 분해, 삼항 연산자, 화살표 함수, 모듈 import/export를 알고 있는지 짧게 확인한다. 배열을 직접 수정하는 코드와 새 배열을 반환하는 코드를 구분하게 한다. 환경 설치는 강의 시간 전에 완료한다.

원본은 reference에서 읽고, 추가 예제는 examples에서 실행한다. 화면 왼쪽에 소스, 오른쪽에 브라우저를 두고 클릭 직전 상태와 클릭 직후 상태를 학생이 먼저 예측하게 한다. 결과를 보기 전에 최소 한 명이 상태·props·화면 변화를 설명하도록 한다.

## 핵심 시연과 질문

1. 08: `onClick={handler()}`로 잠시 바꾸고 렌더 중 호출되는 문제를 설명한다. 무한 갱신을 일으킬 수 있으므로 수정 후 정상 코드를 복구한다. 질문: “disabled가 되면 다음 클릭은 어디서 발생하는가?”
2. 09: user가 null일 때와 객체일 때 같은 JSX가 어떻게 달라지는지 표시한다. 질문: “Toolbar 안에 로그인 상태를 또 만들면 어떤 불일치가 생기는가?”
3. 10: 체크한 뒤 검색과 역순 정렬을 한다. 질문: “표시 순서와 학생의 정체성은 같은가?” 원본은 이미 id key를 사용한다는 점을 분명히 한다.
4. 11: 빈 값, 공백, 미체크, 정상값을 차례로 제출한다. Enter 제출도 확인한다. 질문: “checkbox 값을 value로 읽으면 왜 틀리는가?”
5. 12: 100°C, 212°F, 빈 값, `12abc`, `-`, `99.9999`를 입력한다. 질문: “표시를 반올림한 값으로 끓는점을 판정하면 어떤 경계 오류가 생기는가?”
6. 13: Card에 문단 대신 목록을 넣는다. 질문: “Card가 사용자 이름이나 저장 로직을 알아야 하는가?”
7. 14: Layout에는 Context 관련 코드가 없음을 보여준다. 질문: “Context 객체와 실제 상태 값은 어디에 있는가?” Provider 밖 소비 오류는 개발 설명용으로만 보여주고 복구한다.
8. 15: 좁은 화면에서 줄바꿈과 여백 모드를 바꾼다. 질문: “CSS 변수값 전달과 React key는 각각 누구를 위한 정보인가?”

## 통합 과제: 테마가 있는 수강 신청 관리 화면

기본 범위는 브라우저 메모리에 저장하는 수업 데모다. 실제 인증, 서버 저장, 결제는 범위에 포함하지 않는다. 90~120분을 별도로 배정한다.

요구사항:

- 신청 이름과 과정 선택을 제어 폼으로 받는다. 공백 이름을 거부한다.
- 신청 때 한 번 생성한 안정적인 id를 사용한다. 렌더 중 id를 다시 생성하지 않는다.
- 신청 목록을 Card로 표시하고 검색·삭제한다. 삭제는 filter로 새 배열을 만든다.
- 접수 확인 버튼을 누르면 해당 신청만 확인 상태로 바뀐다.
- 공통 부모가 신청 배열을 소유하고 자식에는 값과 콜백을 전달한다.
- Context를 이용해 밝은/어두운 테마를 제공한다.
- styled-components의 스타일 전용 prop은 `$` 접두사를 사용한다.
- 신청 수, 빈 목록 안내, 검색 결과 없음 안내를 조건부 렌더링한다.

권장 구조: `App → ThemeProvider → EnrollmentPage → EnrollmentForm + EnrollmentList → EnrollmentCard`. EnrollmentPage에 신청 배열, EnrollmentForm에 편집 중 입력값을 둔다. 서로 공유할 필요가 없는 입력값까지 Context에 넣지 않는다.

## 채점 기준

| 평가 항목 | 점수 | 충족 조건 |
|---|---:|---|
| 이벤트와 조건 | 15 | 핸들러 전달, 빈 화면·확인 상태 정확 |
| 폼과 검증 | 20 | value/checked 제어, 공백·미선택 처리, Enter 제출 |
| 상태 설계 | 20 | 단일 소유자, 불변 업데이트, 중복 파생 상태 없음 |
| 리스트 | 15 | 안정적 key, 검색·삭제 후 대상 유지 |
| 합성과 Context | 15 | Card 재사용, Provider 범위 적절 |
| 스타일·접근성 | 10 | label, 키보드, 좁은 화면 대응 |
| 설명 | 5 | 데이터 흐름과 상태 위치의 이유 설명 |

오답 지도: “작동했다”로 끝내지 않고, 새로고침·입력 삭제·목록 재정렬·컴포넌트 교체 시의 상태를 묻는다. 학생이 오류를 수정한 뒤 원인과 예방 방법을 한 문장씩 기록하게 한다.
