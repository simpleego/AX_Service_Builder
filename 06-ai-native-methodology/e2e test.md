# E2E 테스트(End-to-End Test)
E2E 테스트(End-to-End Test)는 애플리케이션의 시작부터 끝까지, **사용자의 실제 시나리오와 동일한 조건에서 전체 시스템의 흐름을 검증하는 소프트웨어 테스트 방법**입니다.

단순히 특정 함수나 컴포넌트(단위 테스트) 또는 여러 컴포넌트 간의 상호작용(통합 테스트)을 확인하는 것을 넘어, **실제 사용자 관점**에서 브라우저나 기기에서 직접 앱을 조작하듯 전체 흐름이 정상적으로 동작하는지 확인합니다.

### 1. E2E 테스트의 핵심 특징

* **실제 환경 시뮬레이션:** 프론트엔드, 백엔드 서버, 데이터베이스, 외부 API, 네트워크 등 실제 서비스 운영에 필요한 모든 구성 요소가 연동된 상태에서 테스트를 진행합니다.
* **사용자 시나리오 중심:** 사용자가 앱을 이용하는 대표적인 흐름(예: 로그인 $\rightarrow$ 상품 검색 $\rightarrow$ 장바구니 담기 $\rightarrow$ 결제 완료)을 그대로 재현합니다.
* **블랙박스 테스트:** 내부 소스코드의 구조를 보지 않고, 사용자가 보거나 입력하는 UI와 결과값을 기준으로 테스트합니다.

---

### 2. 다른 테스트와의 비교 (단위 vs 통합 vs E2E)

| 구분 | 단위 테스트 (Unit Test) | 통합 테스트 (Integration Test) | E2E 테스트 (End-to-End Test) |
| --- | --- | --- | --- |
| **검증 범위** | 개별 함수, 클래스, 컴포넌트 | 여러 모듈/컴포넌트 간의 연동 | 사용자 관점의 전체 시스템 흐름 |
| **속도** | 매우 빠름 (밀리초 단위) | 비교적 빠름 | 느림 (실제 브라우저 구동 필요) |
| **비용 및 관리** | 낮음 | 중간 | 높음 (유지보수 비용이 큼) |
| **목적** | 개별 로직의 정확성 검증 | 모듈 간 통신 및 데이터 흐름 검증 | 실제 서비스 운영 가능 여부 최종 확인 |

---

### 3. E2E 테스트의 장단점

#### **장점**

* **실제 사용자 경험 보장:** 단위 테스트로는 잡아내지 못하는 프론트엔드와 백엔드 간의 데이터 불일치, 라우팅 오류, UI 깨짐 등 전체적인 통합 문제를 사전에 발견할 수 있습니다.
* **배포 신뢰성 향상:** 핵심 비즈니스 로직(예: 결제, 회원가입 등)이 문제없이 작동함을 보장하므로 프로덕션 배포 시 불안감을 크게 줄여줍니다.

#### **단점**

* **느린 실행 속도:** 실제 브라우저를 띄우거나 네트워크 통신을 수반하는 경우가 많아 테스트 실행에 오랜 시간이 걸립니다.
* **높은 유지보수 비용 (Flaky Test):** UI나 디자인, 텍스트가 조금만 바뀌어도 테스트가 깨지기 쉽습니다. 또한 네트워크 지연이나 외부 API 상태에 따라 테스트가 간헐적으로 실패(Flaky)할 수 있습니다.

---

### 4. 주요 E2E 테스트 도구

현대 웹 개발 환경에서는 주로 다음과 같은 브라우저 자동화 기반의 프레임워크를 사용합니다.

* **Playwright:** 마이크로소프트에서 만든 최신 도구로, 속도가 빠르고 크롬, 파이어폭스, 사파리(WebKit) 등 멀티 브라우저를 완벽하게 지원해 최근 가장 널리 쓰입니다.
* **Cypress:** 개발자 친화적인 인터페이스와 강력한 디버깅 도구를 제공하여 프론트엔드 개발자들에게 인기가 높습니다.
* **Selenium:** 오랜 역사와 방대한 생태계를 가진 전통적인 웹 자동화 도구입니다.
