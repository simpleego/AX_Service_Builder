# 도커 핵심 개념 8가지

React 화면, FastAPI 서버, MariaDB 데이터베이스로 구성된 서비스에 도커를 적용한다고 생각하면 각 용어의 역할을 쉽게 구분할 수 있습니다.

| 용어 | 쉬운 설명 | 풀스택 예시 |
|---|---|---|
| **Dockerfile** | **이미지를 만드는 설명서**입니다. 어떤 기본 이미지에서 시작할지, 어떤 파일을 복사하고 라이브러리를 설치할지, 컨테이너를 시작할 때 기본으로 어떤 명령을 실행할지 적습니다. | Python 기본 이미지에 FastAPI 코드와 라이브러리를 넣고, 시작할 때 Uvicorn을 실행하도록 적습니다. |
| **Docker Image** | **앱과 앱 실행에 필요한 파일을 묶은 패키지**입니다. 같은 이미지로 여러 컨테이너를 만들 수 있고, `v1`, `v2` 같은 태그로 버전을 구분할 수 있습니다. | FastAPI 코드와 Python 실행 환경이 들어 있는 `my-api:v1` 이미지를 만듭니다. |
| **Docker Container** | **이미지로 만든 독립된 실행 환경**입니다. 시작하면 그 안에서 앱이 실행되고, 중지한 뒤 다시 시작할 수도 있습니다. | `my-api:v1` 이미지로 컨테이너를 시작하면 그 안에서 FastAPI 서버가 실행됩니다. |
| **Docker Registry** | **이미지를 올리고 내려받는 저장소 서비스**입니다. Docker Hub가 대표적이며, 팀 전용 비공개 레지스트리도 운영할 수 있습니다. | 개발자가 `my-api:v1`을 올려두면 배포 서버가 같은 이미지를 내려받아 실행합니다. |
| **Docker Volume** | **데이터를 컨테이너와 별도로 보관하는 공간**입니다. 볼륨을 유지하면 컨테이너를 삭제하고 새로 만들어도 데이터를 다시 연결해 사용할 수 있습니다. 필요하면 여러 컨테이너에 같은 볼륨을 연결할 수도 있습니다. | MariaDB의 데이터 파일을 볼륨에 저장하면 DB 컨테이너를 교체해도 회원과 주문 데이터가 남습니다. |
| **Docker Network** | **컨테이너들이 서로 통신하는 가상 네트워크**입니다. 어떤 컨테이너를 같은 네트워크에 연결할지 정할 수 있습니다. 호스트 PC에서 컨테이너의 서비스에 접속할 수 있도록 포트를 공개할 수도 있습니다. | 같은 네트워크에서 FastAPI가 `db:3306`으로 MariaDB에 접속하고, 개발자는 공개된 포트로 FastAPI에 접속합니다. |
| **Docker Compose** | **여러 컨테이너와 연결 설정을 한 파일에 정의하고 함께 실행하는 도구**입니다. 서비스별 이미지, 포트, 볼륨, 네트워크 등을 `compose.yaml`에 적습니다. | React, FastAPI, MariaDB를 정의해 두고 `docker compose up -d`로 한꺼번에 시작합니다. |
| **Docker CLI** | **터미널에서 도커를 조작하는 명령어 도구**입니다. 이미지 만들기, 컨테이너 실행, 실행 상태 확인 등을 할 수 있습니다. | `docker build`로 이미지를 만들고, `docker run`으로 컨테이너를 시작하고, `docker ps`로 실행 중인 컨테이너를 확인합니다. |

### 처음에는 세 가지부터 구분하면 됩니다

1. **Dockerfile을 작성합니다.** FastAPI 앱을 어떤 환경에서 어떻게 실행할지 적습니다.
2. **이미지를 빌드합니다.** Dockerfile의 지시에 따라 앱과 실행 환경을 하나로 묶습니다.
3. **컨테이너를 시작합니다.** 이미지를 바탕으로 실행 환경을 만들고 그 안에서 FastAPI 서버를 띄웁니다.

풀스택 프로젝트에서는 여기에 **네트워크**로 FastAPI와 MariaDB를 연결하고, **볼륨**에 DB 데이터를 보관합니다. 이 구성을 **Compose**에 적어두면 팀원도 같은 명령으로 실습 환경을 시작할 수 있습니다.
