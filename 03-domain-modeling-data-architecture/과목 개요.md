# 서비스 도메인 모델링 & 데이터 아키텍처 (40H)

Sep 27, 2026 · @Jong Cheon Park

## 1. 과목 개요

이 과목의 목표는 하나입니다. **서비스 요구사항을 읽고, 스스로 검증 가능한 데이터 모델을 설계·구현·튜닝할 수 있는 개발자**를 만드는 것입니다. AI가 테이블과 쿼리를 대신 써 주는 시대에도, 그 결과가 맞는지 판단하는 기준은 사람이 갖고 있어야 합니다.

**과정 내 위치** — AX Service Fullstack Builder 과정의 3번째 과목(40H)입니다.

- **선수**: 1과목(기능 명세·요구사항 정의), 2과목(파이썬 OOP, FastAPI 구조, 의존성 주입)
- **후속**: 4과목(REST API·JWT·계층형 아키텍처), 5과목(React API 연동), 7과목(RAG — 벡터 DB와 관계형 DB의 역할 비교)
- 이 과목에서 만드는 LearnMate 스키마와 ORM 모델은 4과목 API 실습의 출발점이 됩니다.

**최종 학습 목표** — 과목을 마친 훈련생은 다음을 할 수 있다.

1. 이상 현상이 있는 테이블을 찾아 3NF(필요시 BCNF)까지 분해하고, 반정규화 여부를 근거로 설명한다.
2. 자연어 요구사항에서 엔터티·관계·카디널리티를 도출해 dbdiagram.io로 ERD를 작성한다.
3. ERD를 SQLAlchemy 2.0 모델로 옮기고 Alembic으로 스키마 변경 이력을 관리한다.
4. AI에게 스키마를 제공해 쿼리를 생성시키고, 결과·정확성·성능 측면에서 검증한다.
5. `EXPLAIN ANALYZE`로 느린 쿼리의 원인을 찾고 인덱스로 개선한 뒤 전후를 수치로 비교한다.

## 3. 실습 환경

모든 실습은 Docker로 띄운 PostgreSQL 16 한 대와 파이썬 가상환경 하나로 진행합니다. 1일차 시작 전(또는 첫 30분)에 완료합니다.

| 도구 | 버전(권장) | 용도 |
| --- | --- | --- |
| Docker Desktop | 최신 | PostgreSQL·pgAdmin 컨테이너 실행 |
| PostgreSQL | 16 | 실습 DB (모듈 전체) |
| Python | 3.12 | ORM·마이그레이션·데이터 생성 스크립트 |
| SQLAlchemy / Alembic | 2.0.x / 1.13+ | ORM 모델, 스키마 마이그레이션 (3-3) |
| psycopg | 3.x | PostgreSQL 드라이버 |
| FastAPI | 2과목과 동일 | ORM 모델 연동 확인 (3-3 마지막 차시) |
| dbdiagram.io | 웹 | ERD 작성 (DBML) (3-2) |
| DBeaver 또는 pgAdmin | 최신 | SQL 실행, 실행 계획 확인 |
| 생성형 AI 도구 | 기관 제공 도구 | 쿼리·모델 초안 생성 및 리뷰 (3-2\~3-5) |

프로젝트 루트의 `docker-compose.yml`:

```yaml
# docker-compose.yml — 실습용 PostgreSQL 16
services:
  db:
    image: postgres:16
    container_name: learnmate-db
    environment:
      POSTGRES_USER: learnmate      # 실습용 계정 (운영에서는 .env로 분리)
      POSTGRES_PASSWORD: learnmate
      POSTGRES_DB: learnmate
    ports:
      - "5432:5432"
    volumes:
      - pgdata:/var/lib/postgresql/data   # 컨테이너를 지워도 데이터 유지
volumes:
  pgdata:
```

파이썬 환경 준비:

```bash
# 가상환경 생성 및 패키지 설치
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install "sqlalchemy>=2.0" alembic "psycopg[binary]" fastapi uvicorn faker
docker compose up -d                # DB 기동
docker exec -it learnmate-db psql -U learnmate -c "SELECT version();"   # 접속 확인
```

## 4. 공통 실습 도메인: LearnMate

5개 모듈은 모두 같은 서비스 \*\*LearnMate(AI 학습 Q&A 커뮤니티)\*\*를 다룹니다. 정규화 → ERD → ORM → 쿼리 → 인덱스로 같은 스키마를 키워 가기 때문에, 훈련생은 매일 전날 산출물 위에서 작업합니다.

**서비스 한 줄 소개** — 강좌별로 학생이 질문을 올리면, 강사·다른 학생·AI 조교가 답변하고, 좋은 답변에 추천을 누르는 커뮤니티.

**요구사항 명세 (3-2 ERD 작성의 입력 자료)**

1. R1. 회원은 이메일(중복 불가), 닉네임, 역할(학생/강사/관리자), 가입일을 갖는다.
2. R2. 강좌는 제목, 설명, 담당 강사 1명, 개설일을 갖는다.
3. R3. 학생은 여러 강좌를 수강할 수 있고, 강좌에는 여러 학생이 있다. 수강 신청일과 진도율(%)을 기록한다.
4. R4. 수강 중인 회원만 해당 강좌에 질문을 올릴 수 있다. 질문은 제목, 본문, 작성일, 조회수, 해결 여부를 갖는다.
5. R5. 질문에는 태그를 여러 개 붙일 수 있고, 하나의 태그는 여러 질문에 쓰인다. (예: `python`, `sql`, `fastapi`)
6. R6. 답변은 회원 또는 AI 조교가 작성한다. AI 답변은 사용 모델명과 사용 토큰 수를 함께 남긴다.
7. R7. 질문 작성자는 답변 1개를 ‘채택’할 수 있다. 채택되면 질문은 해결 상태가 된다.
8. R8. 회원은 답변에 추천을 누를 수 있으며, 같은 답변에 두 번 누를 수 없다.
9. R9. 강좌 화면에는 ‘미해결 질문 최신순 20개’, ‘추천 많은 답변 Top 10’이 표시된다. (3-4, 3-5 쿼리·성능 실습 대상)
10. R10. 탈퇴한 회원의 질문·답변은 삭제하지 않고 ‘탈퇴한 회원’으로 표시한다.

**완성 스키마 미리보기 (강사용 정답, 3-2 종료 후 공개)** — `users`, `courses`, `enrollments`, `questions`, `tags`, `question_tags`, `answers`, `answer_votes`, `ai_answer_meta` 9개 테이블. R6의 AI 메타데이터를 `answers`에 넣을지 별도 테이블로 분리할지는 3-2의 토론 주제입니다.

## 5. 평가와 운영

평가는 ‘만들었는가’보다 \*\*‘왜 이렇게 설계했는지 설명할 수 있는가’\*\*에 비중을 둡니다. AI로 만든 산출물도 허용하되, 검증 기록이 없으면 감점합니다.

| 평가 항목 | 비중 | 연결 모듈 | 평가 방법 |
| --- | --- | --- | --- |
| 정규화 분해 워크시트 | 15% | 3-1 | 함수 종속 표기, 단계별 분해 근거 |
| LearnMate ERD | 20% | 3-2 | 요구사항 R1\~R10 반영도, 카디널리티 정확성 |
| ORM 모델 + 마이그레이션 | 25% | 3-3 | `alembic upgrade head` 성공, 제약조건 반영, downgrade 가능 여부 |
| AI 쿼리 검증 리포트 | 15% | 3-4 | AI 오류 발견·수정 기록 3건 이상 |
| 성능 개선 종합 과제 | 25% | 3-5 | 실행 계획 전후 비교, 인덱스 선택 이유 |

**전공 / 비전공 트랙 운영**

- **공통**: 모든 훈련생은 LearnMate 같은 스키마를 다루고, 같은 산출물을 제출합니다.
- **비전공 트랙**: 각 모듈 탭의 ‘비전공 보충’ 박스를 먼저 진행하고, 실습은 뼈대 코드(빈칸 채우기)로 시작합니다. 정규화는 BCNF 대신 3NF까지를 필수로 합니다.
- **전공 트랙**: ‘전공 심화’ 문제(BCNF, 격리 수준, 부분 인덱스 등)를 추가로 수행하고, 비전공 훈련생과 페어로 리뷰를 맡습니다.
- **AI 사용 규칙**: AI는 ‘초안 작성자’, 훈련생은 ‘검토자’입니다. AI가 만든 코드·쿼리는 반드시 실행해 보고, 무엇을 확인했는지 주석으로 남깁니다.

**모듈별 교안** — 이 탭 아래에 3-1 \~ 3-5 탭이 있습니다. 각 탭은 학습 목표 → 차시표 → 핵심 개념 → 예제 코드 → 실습 → 확인 문제 순서로 구성됩니다.
