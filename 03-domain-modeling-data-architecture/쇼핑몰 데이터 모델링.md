# 쇼핑몰 도메인으로 **서비스 도메인 모델링 & 데이터 아키텍처
> 쇼핑몰 도메인으로 **서비스 도메인 모델링 & 데이터 아키텍처 (40H)** 5일 완성 커리큘럼입니다.  
> 마스터 시트의 3-1 ~ 3-5 학습목표를 그대로 커버하면서, 하루 8시간씩 실습 위주로 재구성했습니다.  

### 전체 프로젝트: Mini-Shop Mall
5일간 하나의 DB를 계속 확장합니다.

**핵심 엔티티:** `User / Category / Product / Cart / CartItem / Order / OrderItem / Payment / Review / Coupon`
**확장 포인트:** 재고 동시성, N+1, 검색/필터, 통계 쿼리

> 사용 스택: MySQL 8 or PostgreSQL 16 / dbdiagram.io / SQLAlchemy 2.0 / Alembic / DBeaver / AI (ChatGPT, Cursor, Claude)

---

### DAY 1. RDB 설계 원칙과 정규화 [3-1] - 8H
**목표: 쇼핑몰 요구사항을 보고 테이블을 쪼갤 수 있다**

- **09:00-10:30 이론** RDBMS vs NoSQL, 왜 쇼핑몰은 RDB인가? PK/FK, 1:1/1:N/M:N, 참조무결성
- **10:30-12:00 요구사항 분석 워크숍**
  - 유저스토리: "회원가입, 상품목록/검색, 장바구니, 주문, 결제, 리뷰"
  - AI 프롬프트: "쇼핑몰 PRD를 보고 도메인 명사/동사 추출해줘" 로 후보 엔티티 도출
- **13:00-15:00 정규화 실습**
  - 비정규형 주문 테이블(주문자+상품목록이 한 컬럼에) -> 1NF -> 2NF -> 3NF 분해
  - 반정규화 트레이드오프: `products.review_count` 같은 카운터 컬럼은 언제 넣는가?
- **15:00-17:00 테이블 설계 실습**
  - `users, categories(자기참조), products, product_options` 1차 설계
  - 제약조건: UNIQUE(email), CHECK(price>0), ON DELETE 전략
- **17:00-18:00 과제** 내 쇼핑몰의 테이블 명세서 작성 (컬럼, 타입, 제약조건)

> 산출물: `mini_shop_v1.sql`

### DAY 2. ERD 작성 [3-2] - 8H
**목표: 도메인 분석을 ERD로 시각화하고 팀과 합의한다**

- **09:00-10:30 이론** ERD 기호, 식별/비식별 관계, dbdiagram.io DBML 문법
- **10:30-12:00 도메인 모델링 심화**
  - 쇼핑몰 핵심 플로우: Cart -> Order -> OrderItem -> Payment 상태 전이
  - M:N 해소 테이블: `product_categories, cart_items, order_items`
- **13:00-15:00 ERD Live Modeling**
  ```dbml
  Table users { id bigint [pk] email varchar [unique]... }
  Table orders { id bigint [pk] user_id bigint [ref: > users.id] status enum... }
  ```
  - AI 활용: "위 테이블 명세서로 dbdiagram DBML 만들어줘" 후 검수
- **15:00-17:00 고급 모델링**
  - 자기참조: 카테고리 트리
  - 다형성 고민: 쿠폰(정률/정액) -> Single Table vs Class Table Inheritance
  - 이력 관리: `order_status_logs` 설계
- **17:00-18:00 ERD 리뷰** 팀별 ERD 크로스 리뷰, 정규화 위반 찾기

> 산출물: `mini_shop ERD 링크 + DBML 파일`

### DAY 3. ORM 기반 데이터 모델 구현 [3-3] - 8H
**목표: SQLAlchemy로 ERD를 코드로 옮기고 마이그레이션을 관리한다**

- **09:00-10:30 SQLAlchemy ORM 기초**
  - Declarative Base, mapped_column, relationship, back_populates
- **10:30-12:00 모델 구현 실습 1**
  - `User, Product, Category` 모델 구현, 1:N, M:N with association object
- **13:00-14:30 Alembic**
  - `alembic init`, `revision --autogenerate`, upgrade/downgrade
  - AI 활용: "Alembic revision conflict 났는데 해결해줘"
- **14:30-16:30 모델 구현 실습 2**
  - `Cart, Order, OrderItem, Payment` 구현, `cascade="all, delete-orphan"`, `lazy='selectin'`으로 N+1 예방
  - FastAPI 연동 맛보기: `Session` Dependency
- **16:30-18:00 시드 데이터 & 트랜잭션**
  - faker로 상품 10,000개 넣기, 장바구니 -> 주문 생성 트랜잭션 구현

> 산출물: `models.py + alembic versions + seed.py`

### DAY 4. AI 활용 쿼리 작성 및 검증 [3-4] - 8H
**목표: AI가 짠 쿼리를 맹신하지 않고 검증한다**

- **09:00-10:30 AI 쿼리 생성**
  - Prompt 패턴: "쇼핑몰 DB에서 카테고리별 매출 Top5, 재고 10개 이하 상품 찾기 쿼리 짜줘"
  - JOIN, GROUP BY, HAVING, Window Function (랭킹), CTE
- **10:30-12:00 쿼리 검증 체크리스트**
  - 1) 의도 일치? 2) NULL/중복 처리? 3) 인덱스 타는가? 4) SQL Injection 안전한가?
  - AI가 틀리는 대표 케이스: `COUNT(*) vs COUNT(DISTINCT)`, `LEFT JOIN + WHERE`로 INNER JOIN 되는 실수
- **13:00-15:00 쇼핑몰 핵심 쿼리 8선 구현**
  1. 상품 검색 + 필터(카테고리, 가격, 키워드)
  2. 장바구니 합계
  3. 주문 생성 (재고 차감 원자성)
  4. 내 주문 목록 + 주문 상세
  5. 베스트셀러 TOP 10
  6. 리뷰 평점 집계
  7. 쿠폰 적용 가능 검증
  8. 월별 매출 통계
- **15:00-18:00 ORM 쿼리 최적화**
  - SQLAlchemy `select()`, `joinedload` vs `selectinload`로 N+1 해결
  - AI 코드 리뷰: AI가 짠 Repository 코드를 함께 리팩터링

> 산출물: `queries.sql + repositories.py` + 쿼리 검증 리포트

### DAY 5. 인덱스와 성능 최적화 [3-5] - 8H + 최종 통합
**목표: 10만건에서도 100ms 안에 나오는 쇼핑몰을 만든다**

- **09:00-10:30 인덱스 원리**
  - B-Tree, Composite Index 순서, Covering Index, Cardinality
- **10:30-12:00 실행 계획 분석**
  - `EXPLAIN ANALYZE`, `Slow Query Log`로 병목 찾기
  - 실습: `WHERE category_id + price` 검색에 `(category_id, price)` 인덱스 걸기 전/후 비교
- **13:00-15:00 쇼핑몰 성능 튜닝 배틀**
  - Case 1: 상품 검색 LIKE '%키워드%' -> Full-Text Index (MySQL) / pg_trgm (PG)
  - Case 2: `orders(user_id, created_at)` 정렬 최적화
  - Case 3: 재고 동시성 - `SELECT... FOR UPDATE` vs 낙관적 락
  - Case 4: 페이지네이션 - OFFSET vs 커서 기반
- **15:00-17:00 최종 프로젝트**
  - Day1~5 통합: ERD 최종본 + 마이그레이션 + 시드 10만건 + 핵심 쿼리 8개 + 인덱스 설계서
  - AI로 부하테스트 스크립트 생성 후 100 RPS 테스트
- **17:00-18:00 발표 & 회고** 팀별 "우리 쇼핑몰 DB가 느렸던 이유와 해결"

> 최종 산출물: **Mini-Shop DB 포트폴리오 1개** (ERD 이미지, DDL, ORM 코드, 쿼리집, 성능개선 보고서)
