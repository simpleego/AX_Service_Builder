심플님, **“재고가 10개인 상품을 두 사람이 동시에 구매하는 상황”**으로 실습하면 동시성 제어를 쉽게 이해할 수 있습니다.

아래 실습은 **잠금 → 다른 연결의 대기 → COMMIT 또는 ROLLBACK → 대기하던 작업 실행** 과정을 확인합니다.

**1. 실습 환경 준비**

HeidiSQL 프로그램을 **두 개 실행**하고 동일한 MariaDB 서버에 접속하세요.

- **연결 A**: 고객 A의 구매 처리
- **연결 B**: 고객 B의 구매 처리

단순히 쿼리 탭만 나누면 같은 연결을 공유할 수 있으므로, 각각 다음 명령으로 **연결 번호가 다른지** 확인합니다.

```sql
SELECT CONNECTION_ID();
```

**아래 코드는 전체를 한꺼번에 실행하지 말고, 안내 순서대로 블록별로 실행하세요.**

**2. 예시 테이블 생성 — 연결 A에서 한 번 실행**

```sql
CREATE DATABASE IF NOT EXISTS concurrency_lab;
USE concurrency_lab;

CREATE TABLE IF NOT EXISTS stock_demo (
    product_id   INT PRIMARY KEY,
    product_name VARCHAR(50) NOT NULL,
    stock        INT NOT NULL
) ENGINE = InnoDB;

INSERT INTO stock_demo (product_id, product_name, stock)
VALUES
    (1, '키보드', 10),
    (2, '마우스', 20)
ON DUPLICATE KEY UPDATE
    product_name = VALUES(product_name),
    stock = VALUES(stock);

SELECT * FROM stock_demo;
```

| product_id | product_name | stock |
|---:|---|---:|
| 1 | 키보드 | 10 |
| 2 | 마우스 | 20 |

`InnoDB`를 사용하는 이유는 트랜잭션과 행 잠금을 실습하기 위해서입니다.

**두 연결 모두에서** 다음을 실행합니다. 격리 수준은 결과를 이해하기 쉽도록 `READ COMMITTED`로 통일합니다.

```sql
USE concurrency_lab;

SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;

-- 실습 중 잠금 대기 시간을 120초로 설정
SET SESSION innodb_lock_wait_timeout = 120;
```

**3. 실습 ① — 같은 상품을 수정하면 대기한다**

**① 연결 A: 키보드 3개 구매, 아직 확정하지 않기**

```sql
START TRANSACTION;

UPDATE stock_demo
SET stock = stock - 3
WHERE product_id = 1;

SELECT * FROM stock_demo WHERE product_id = 1;
-- A에서는 재고가 7개로 보임

-- 아직 COMMIT을 실행하지 마세요.
```

현재 A가 **키보드 행의 수정 잠금**을 보유하고 있습니다.

**② 연결 B: 일반 조회**

```sql
SELECT * FROM stock_demo WHERE product_id = 1;
-- 재고: 10
```

A의 수정은 아직 확정되지 않았으므로 B에는 기존 재고 **10개**가 보입니다. 이 실습의 일반 `SELECT`는 A의 수정 잠금 때문에 대기하지 않습니다.

**③ 연결 B: 키보드 2개 구매 시도**

```sql
START TRANSACTION;

UPDATE stock_demo
SET stock = stock - 2
WHERE product_id = 1;
-- 여기서 대기합니다!
```

**실행이 끝나지 않는 것이 정상입니다.** A가 같은 행을 수정하고 있기 때문입니다.

**④ 연결 A: 구매 확정**

```sql
COMMIT;
```

A의 잠금이 해제되면서 **B의 UPDATE가 실행 완료**됩니다.

**⑤ 연결 B: 결과 확인 및 확정**

```sql
SELECT * FROM stock_demo WHERE product_id = 1;
-- 재고: 5

COMMIT;
```

| 시점 | 처리 | 재고 |
|---|---|---:|
| 시작 | 초기 재고 | 10 |
| A 확정 | 3개 구매 | 7 |
| B 확정 | 확정된 7개에서 2개 구매 | 5 |

**핵심:** `UPDATE ... SET stock = stock - 2`는 잠금을 얻은 후 최신 값을 기준으로 차감하므로 두 구매가 모두 반영됩니다.

**4. 실습 ② — ROLLBACK하면 취소된 값을 기준으로 이어서 처리한다**

실습 ①의 두 연결에서 모두 `COMMIT`을 마친 후 진행합니다.

**① 연결 A: 재고 초기화 후 3개 구매**

```sql
START TRANSACTION;

UPDATE stock_demo
SET stock = 10
WHERE product_id = 1;

COMMIT;


START TRANSACTION;

UPDATE stock_demo
SET stock = stock - 3
WHERE product_id = 1;

-- 아직 확정하지 않음
```

**② 연결 B: 2개 구매 시도**

```sql
START TRANSACTION;

UPDATE stock_demo
SET stock = stock - 2
WHERE product_id = 1;
-- A의 잠금 때문에 대기
```

**③ 연결 A: 구매 취소**

```sql
ROLLBACK;
```

A의 3개 구매가 취소되어 재고가 10개로 복원되고, 잠금이 해제됩니다. 이어서 B의 UPDATE가 실행됩니다.

**④ 연결 B: 결과 확인 및 확정**

```sql
SELECT * FROM stock_demo WHERE product_id = 1;
-- 재고: 8

COMMIT;
```

**핵심:** `COMMIT`과 `ROLLBACK`은 모두 트랜잭션을 종료하고 잠금을 해제하지만, **변경 내용을 저장하는지 취소하는지**가 다릅니다. [MariaDB Documentation](https://mariadb.com/docs/server/reference/sql-statements/transactions/start-transaction?utm_source=chatgpt.com)

**5. 실습 ③ — 조회할 때부터 잠그기: SELECT … FOR UPDATE**

이번에는 **“재고를 먼저 확인하고, 확인한 재고를 바탕으로 구매 처리”**하는 상황입니다.

**① 연결 A: 재고 초기화**

```sql
START TRANSACTION;

UPDATE stock_demo
SET stock = 10
WHERE product_id = 1;

COMMIT;
```

**② 연결 A: 재고 확인과 동시에 잠금**

```sql
START TRANSACTION;

SELECT *
FROM stock_demo
WHERE product_id = 1
FOR UPDATE;

-- 재고: 10
-- 아직 수정하지 않았지만 키보드 행의 잠금을 확보함
```

**③ 연결 B: 같은 상품을 잠그고 조회하려고 시도**

```sql
START TRANSACTION;

SELECT *
FROM stock_demo
WHERE product_id = 1
FOR UPDATE;

-- 여기서 대기
```

**④ 연결 A: 3개 구매 후 확정**

```sql
UPDATE stock_demo
SET stock = stock - 3
WHERE product_id = 1;

COMMIT;
```

이제 B의 조회가 완료되며, **재고 7개**가 표시됩니다.

**⑤ 연결 B: 확인한 재고에서 2개 구매**

```sql
UPDATE stock_demo
SET stock = stock - 2
WHERE product_id = 1;

COMMIT;

SELECT * FROM stock_demo WHERE product_id = 1;
-- 최종 재고: 5
```

`FOR UPDATE`는 **“조회한 데이터를 나중에 수정할 예정이니 다른 트랜잭션이 먼저 바꾸지 못하도록 잠그는 기능”**입니다. InnoDB에서는 위처럼 명시적인 트랜잭션 안에서 사용해야 합니다. [MariaDB Documentation](https://mariadb.com/docs/server/reference/sql-statements/data-manipulation/selecting-data/for-update?utm_source=chatgpt.com)

> `FOR UPDATE`가 모든 조회를 막는 것은 아닙니다. 이 실습에서는 다른 연결의 일반 `SELECT`는 가능하지만, 같은 행의 수정이나 `SELECT ... FOR UPDATE`는 대기합니다.

**6. 응용 — 재고 부족까지 한 번에 방지하는 SQL**

단순히 재고를 차감하는 기능이라면 다음과 같이 **조건 검사와 차감을 하나의 UPDATE로 처리**할 수 있습니다.

```sql
-- 예: 키보드 3개 구매
START TRANSACTION;

UPDATE stock_demo
SET stock = stock - 3
WHERE product_id = 1
  AND stock >= 3;

-- UPDATE 바로 다음에 실행
SELECT ROW_COUNT() AS purchase_success;
-- 1: 구매 성공
-- 0: 재고 부족 또는 상품 없음

COMMIT;
```

두 연결이 동시에 실행하더라도 같은 행의 수정은 잠금으로 조정되고, **재고가 3개 이상일 때만 차감**됩니다. 여러 단계의 판단이 필요한 경우에는 `FOR UPDATE`, 단순 조건부 차감에는 위 방식을 사용할 수 있습니다.

| 구문 | 실습에서 확인할 역할 |
|---|---|
| `START TRANSACTION` | 여러 작업을 하나의 트랜잭션으로 시작 |
| `UPDATE` | 값을 수정하며 해당 행의 수정 잠금 확보 |
| 일반 `SELECT` | 다른 연결의 미확정 변경을 읽지 않음 |
| `SELECT ... FOR UPDATE` | 조회하면서 수정용 잠금 확보 |
| `COMMIT` | 변경 확정 후 잠금 해제 |
| `ROLLBACK` | 변경 취소 후 잠금 해제 |

실습 중 **`Lock wait timeout exceeded`**가 발생했다면, 대기하던 연결에서 `ROLLBACK;`을 실행하고 잠금을 가진 연결도 `COMMIT;` 또는 `ROLLBACK;`으로 정리한 뒤 해당 실습을 다시 시작하세요.
