# 클로드 작업환경 설정
> claude.md 파일은 AI 어시스턴트(특히 Claude)가 특정 프로젝트나 작업 환경을 완벽하게 이해하고 개발자를 보조할 수 있도록 지침을 제공하는 맞춤형 가이드라인 문서입니다.  
> 이 문서를 작성할 때 적용해야 하는 일반적인 원칙과 기본적으로 기술해야 하는 핵심 내용을 정리해 드립니다.
------------------------------
## 1. 작성의 일반적인 원칙 (General Principles)

* 명확성과 간결성 (Clarity & Conciseness): AI가 오해 없이 빠르게 컨텍스트를 파악할 수 있도록 불필요한 미사여구를 빼고 구체적이고 명확한 문장으로 작성합니다. 단어 선택은 모호하지 않아야 합니다.
* 구조화된 형식 (Structured Format): 마크다운(Markdown) 문법을 적극적으로 활용하여 헤더, 글머리 기호, 코드 블록 등으로 정보를 위계에 맞게 정리합니다. AI는 구조화된 데이터를 훨씬 더 잘 이해합니다.
* 실행 가능성 (Actionability): 추상적인 지침(예: "코드를 깨끗하게 짜줘")보다는 구체적인 규칙(예: "모든 함수는 TypeScript 타입을 명시하고 20줄을 넘지 않도록 해줘")을 제시해야 합니다.
* 지속적인 업데이트 (Continuous Update): 프로젝트의 아키텍처가 바뀌거나 사용하는 라이브러리가 변경되면 claude.md도 즉시 업데이트하여 AI가 과거의 기준을 학습하지 않도록 해야 합니다.

------------------------------
## 2. 기본적으로 기술해야 하는 내용 (Core Contents)
claude.md 파일은 대략 아래와 같은 5가지 핵심 영역을 포함하는 것이 좋습니다.
## ① 프로젝트 개요 및 컨텍스트 (Project Overview & Context)
AI가 내가 지금 무엇을 만들고 있는지 전체적인 그림을 그리게 합니다.

* 프로젝트 이름 및 목적: 이 애플리케이션/서비스가 해결하고자 하는 문제와 핵심 기능
* 타겟 사용자: 주 사용자가 누구인지 (예: 일반 대중, 사내 관리자, 개발자 등)
* 현재 개발 단계: 초기 프로토타입 단계인지, 상용 운영 중인 서비스인지 명시

## ② 기술 스택 및 환경 (Tech Stack & Environment)
AI가 엉뚱한 라이브러리나 호환되지 않는 문법을 추천하는 것을 방지합니다.

* 주요 언어 및 프레임워크: 프론트엔드/백엔드 기술 (예: React 18, Next.js 14, FastAPI, PostgreSQL)
* 상태 관리 및 데이터베이스: 사용하는 도구 명시 (예: Zustand, Prisma, Supabase)
* 버전 정보: 중요한 언어나 패키지의 버전 (예: Node.js v20, Python 3.11)

## ③ 디렉토리 구조 및 주요 파일 (Directory Structure)
AI가 새로운 코드를 생성할 때 어디에 파일을 위치시켜야 할지 알 수 있도록 가이드합니다.

* 전체적인 폴더 구조: 프로젝트의 주요 디렉토리 맵 (예: /src/components, /src/hooks, /src/types)
* 아키텍처 패턴: MVVM, Clean Architecture, Feature-driven 단원 등 프로젝트가 따르는 구조적 규칙

## ④ 코딩 컨벤션 및 스타일 가이드 (Coding Conventions & Rules)
가장 중요한 부분으로, 팀이나 개인의 개발 스타일을 일치시키는 지침입니다.

* 언어별 스타일 규칙: (예: "JavaScript/TypeScript 작성 시 함수형 컴포넌트와 Arrow Function을 사용할 것")
* 네이밍 규칙: 변수, 함수, 컴포넌트, 파일 이름 짓는 법 (예: "컴포넌트는 PascalCase, 일반 함수는 camelCase")
* 에러 핸들링 및 로깅: 예외 처리를 어떻게 통일할 것인지에 대한 지침

## ⑤ 워크플로우 및 제약 사항 (Workflow & Constraints)
AI가 작업을 수행하고 제안할 때 지켜야 할 행동 강령입니다.

* Git 브랜치 및 커밋 가이드: 커밋 메시지 컨벤션 (예: Conventional Commits 형식 준수)
* 답변 시 주의사항: (예: "코드를 수정할 때는 바뀐 부분만 주석으로 생략하지 말고, 전체 코드를 온전하게 보여줘", "성능이나 보안상 취약점이 있다면 코드 제안 시 함께 지적해줘")

------------------------------
## 💡 claude.md 템플릿 예시

# Project: [프로젝트 이름]
## 1. Overview- 목적: [간단한 프로젝트 설명]
- 주요 기능: [기능 1, 기능 2]
## 2. Tech Stack- Frontend: Next.js (App Router), TailwindCSS, TypeScript- State Management: Zustand- Database: Supabase
## 3. Coding Principles- 모든 UI 컴포넌트는 오직 클라이언트 컴포넌트(`'use client'`)가 꼭 필요한 경우를 제외하고 서버 컴포넌트로 작성합니다.- 데이터 페칭은 가능한 한 최상단 서버 컴포넌트에서 수행하세요.
- 타입 정의는 `types/` 폴더 내에 별도로 분리합니다. `any` 타입 사용을 절대 금지합니다.
## 4. Response Guidelines (For Claude)- 코드 변경 사항을 제안할 때는 생략 없이 전체 파일 코드를 제공해 주세요.- 코드 작성 후, 해당 코드의 시간 복잡도와 발생 가능한 예외 상황을 2줄 이내로 요약해 주세요.

------------------------------
앞으로 진행하실 프로젝트의 구체적인 성격(웹, 앱, 데이터 분석 등)을 알려주시면, 그 환경에 딱 맞춘 맞춤형 claude.md 템플릿 코드를 직접 작성해 드릴 수 있습니다. 어떤 프로젝트를 준비 중이신가요?
