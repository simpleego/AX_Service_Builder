# 파이썬 디버깅 명령어 운영 방법

## 1. 개발 환경과 운영 환경의 차이

예를 들어 다음과 같은 코드가 있다고 가정하겠습니다.

```
import logginglogging.basicConfig(    level=logging.DEBUG,    format="%(levelname)s: %(message)s")def login(username):    logging.debug("로그인 함수 진입")    logging.info(f"로그인 요청: {username}")    if not username:        logging.warning("사용자 이름 누락")        return False    logging.info("로그인 처리 완료")    return Truelogin("hong")
```

로그 수준을 바꾸면 소스 코드를 수정하지 않고도 출력 내용을 제어할 수 있습니다.

| 로그 명령어               | 개발 환경 DEBUG | 운영 환경 WARNING |
| -------------------- | ----------- | ------------- |
| `logging.debug()`    | 출력          | 출력 안 함        |
| `logging.info()`     | 출력          | 출력 안 함        |
| `logging.warning()`  | 출력          | 출력            |
| `logging.error()`    | 출력          | 출력            |
| `logging.critical()` | 출력          | 출력            |

즉, 소스 코드에 `logging.debug()`가 100개 있어도 운영 환경에서 `WARNING`으로 설정하면 DEBUG 로그는 출력되지 않습니다.

## 2. 실무에서는 환경변수로 제어

```
import loggingimport osLOG_LEVEL = os.getenv("LOG_LEVEL", "INFO").upper()logging.basicConfig(    level=LOG_LEVEL,    format="%(asctime)s [%(levelname)s] %(message)s")def process():    logging.debug("데이터 처리 시작")    logging.info("정상 실행")    logging.warning("데이터 일부 누락")process()
```

실행할 때 환경에 따라 로그 수준을 변경합니다.

개발 환경 (PowerShell)

```
$env:LOG_LEVEL = "DEBUG"
python main.py
```

운영 환경 (PowerShell)

```
$env:LOG_LEVEL = "WARNING"
python main.py
```

이렇게 하면 동일한 소스 코드를 개발과 운영 환경에서 사용할 수 있습니다.

## 3. 그렇다면 모든 logging 코드를 남겨두는 것이 좋을까?

그렇지는 않습니다.

- `logging.debug()` : 장애 분석에 도움이 되는 디버깅 로그는 유지하되, 임시로 추가한 불필요한 로그는 정리합니다.
- `logging.info()` : 중요한 업무 처리 과정은 유지합니다.
- `logging.warning()` : 잠재적인 문제를 기록하므로 유지합니다.
- `logging.error()` 및 `logging.exception()` : 장애 분석을 위해 유지합니다.
- 비밀번호, 인증 토큰, 개인정보 등은 로그에 기록하지 않습니다.

또한 DEBUG 로그가 출력되지 않더라도 로그 메시지에 전달하는 인자 계산에는 비용이 발생할 수 있습니다. 따라서 다음처럼 작성하는 것을 권장합니다.

```
# 권장logging.debug("사용자 ID: %s", user_id)# 상대적으로 비권장logging.debug(f"사용자 ID: {user_id}")
```

첫 번째 방식은 DEBUG 출력이 비활성화되어 있으면 문자열 포맷팅을 생략할 수 있습니다.

정리하면, `print()`는 개발 중 임시 확인용으로 사용하고, `logging`은 프로그램의 일부로 설계하여 유지하는 것이 좋습니다.

특히 FastAPI에서는 일반적으로 `logging.getLogger(__name__)`으로 모듈별 로거를 만들고, 로그 출력 정책은 애플리케이션 차원에서 중앙 관리하는 방식이 적합합니다.
