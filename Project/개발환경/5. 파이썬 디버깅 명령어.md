# 파이썬 디버깅 명령어 정리
> `print()` 대신 `logging` 모듈을 사용하는 것이 일반적입니다.   
> 또한 프로그램 실행 중 변수와 코드 흐름을 추적하려면 `breakpoint()`, 예외 발생 위치를 추적하려면 \*\*`traceback`\*\*을 사용할 수 있습니다.


## 1. 에러 추적에 사용하는 대표적인 방법

| 방법             | 주요 목적         | 특징                               |
| -------------- | ------------- | -------------------------------- |
| `print()`      | 변수 값 출력       | 단순 출력, 로그 수준 구분 불가               |
| `logging`      | 실행 과정 및 오류 기록 | DEBUG, INFO, WARNING, ERROR 등 구분 |
| `breakpoint()` | 실행 중단 및 디버깅   | 변수 확인, 단계별 실행                    |
| `traceback`    | 예외 발생 경로 추적   | 에러 발생 함수와 호출 위치 확인               |
| `pdb`          | 대화형 디버깅       | 중단점, 한 줄 실행, 변수 검사               |

### 로그 수준 구분

| 명령어                   | 용도                      |
| --------------------- | ----------------------- |
| `logging.debug()`     | 변수 값, 실행 흐름 추적          |
| `logging.info()`      | 정상적인 실행 정보              |
| `logging.warning()`   | 잠재적인 문제 알림              |
| `logging.error()`     | 오류 메시지 기록               |
| `logging.exception()` | 오류 메시지와 Traceback 함께 기록 |

특히 `logging.exception()`은 예외 처리 블록 안에서 에러 발생 경로까지 출력하므로 오류 추적에 유용합니다.

## 3. breakpoint() — 코드 실행을 멈추고 추적

파이썬에는 별도 설치 없이 사용할 수 있는 `breakpoint()` 내장 함수가 있습니다.

```
def calculate(a, b):
    total = a + b

    breakpoint()  # 여기서 실행 중단

    result = total * 2
    return result

calculate(10, 20)
```

iframe

터미널에서 실행하면 해당 위치에서 멈추고 디버깅 명령을 입력할 수 있습니다.

```
(Pdb) p total
30

(Pdb) n
# 다음 줄 실행

(Pdb) p result
60

(Pdb) c
# 프로그램 계속 실행
```

자주 사용하는 명령은 `p`(변수 출력), `n`(다음 줄), `s`(함수 내부 진입), `c`(계속 실행), `q`(종료)입니다.

## 4. traceback — 에러 발생 위치 추적

```
import traceback

try:
    x = 10 / 0
except Exception:
    traceback.print_exc()
```

iframe

출력:

```
Traceback (most recent call last):
  File "main.py", line 4, in <module>
    x = 10 / 0
ZeroDivisionError: division by zero
```

`traceback.print_exc()`는 예외가 발생한 함수 호출 경로를 확인할 때 유용합니다.

## 5. 실무에서 권장하는 사용 기준

- 개발 중 변수 및 처리 흐름 확인: `logging.debug()`
- 일반적인 프로그램 실행 기록: `logging.info()`
- 예외 발생 원인과 호출 경로 확인: `logging.exception()`
- 특정 코드에서 실행 중단 후 조사: `breakpoint()`
- VS Code 사용 환경: Python 디버거를 이용한 중단점 및 변수 추적

특히 FastAPI와 같은 백엔드 프로그램에서는 `print()`보다 `logging`을 권장합니다. 로그 수준을 조절하거나 파일로 저장할 수 있고, 서버 운영 중 발생하는 오류도 체계적으로 추적할 수 있기 때문입니다.

결론: `print()`를 대체하는 명령을 하나만 선택한다면 `logging.debug()`가 가장 적합하고, 실제 예외의 발생 위치까지 확인하려면 `logging.exception()`을 사용하면 됩니다.
