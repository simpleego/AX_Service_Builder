알겠습니다. 이번에는 **인포그래픽을 만들지 않고**, 위 그림의 내용을 실제로 따라 하면서 Git의 핵심 개념을 경험할 수 있도록 **최소 실습 과정**으로 정리하겠습니다.

# Git 최소 실습

## 1. 실습 목표

이 실습에서는 다음 4가지만 직접 경험하면 됩니다.

1. 파일을 수정하고 변경 내용을 확인한다.
2. 변경 내용을 Git에 버전으로 저장한다.
3. 이전 버전과 현재 상태를 확인한다.
4. 브랜치를 만들어 별도로 작업한 후 병합한다.

전체 흐름은 다음 정도만 이해하면 충분합니다.

```text
파일 수정
   ↓
git status
   ↓
git add
   ↓
git commit
   ↓
필요하면 git push
```

---

# 2. 실습 폴더 만들기

터미널에서 다음과 같이 진행합니다.

```bash
mkdir git-practice
cd git-practice
```

Git 저장소로 초기화합니다.

```bash
git init
```

확인합니다.

```bash
git status
```

대략 다음과 같이 표시됩니다.

```text
On branch main
No commits yet
```

여기서 `git init`은

> "이 폴더의 파일 변경 이력을 Git으로 관리하겠다."

라는 의미입니다.

---

# 3. 첫 번째 파일 만들기

`README.md` 파일을 만듭니다.

내용은 간단하게 작성합니다.

```markdown
# Git 실습

Git 버전관리 연습입니다.
```

현재 상태를 확인합니다.

```bash
git status
```

결과에는 대략 다음과 같이 나타납니다.

```text
Untracked files:

README.md
```

즉,

> Git은 README.md 파일이 생긴 것은 알고 있지만 아직 관리 대상으로 등록하지 않은 상태입니다.

---

# 4. git add 실습

README.md를 Git의 저장 대상으로 선택합니다.

```bash
git add README.md
```

다시 확인합니다.

```bash
git status
```

이번에는 다음과 비슷하게 나타납니다.

```text
Changes to be committed:

new file: README.md
```

여기서 중요한 개념은 다음입니다.

```text
작업 디렉터리
      ↓
   git add
      ↓
스테이징 영역
```

`git add`는 저장 자체가 아니라

> **이번 버전에 포함할 파일을 선택하는 작업**

입니다.

---

# 5. 첫 번째 commit 만들기

이제 실제 버전으로 저장합니다.

```bash
git commit -m "첫 번째 Git 실습"
```

커밋 기록을 확인합니다.

```bash
git log
```

간단하게 보고 싶다면 다음 명령이 좋습니다.

```bash
git log --oneline
```

예:

```text
a31f245 첫 번째 Git 실습
```

이 시점에 첫 번째 버전이 만들어졌습니다.

```text
README.md 작성
      ↓
git add
      ↓
git commit
      ↓
버전 1 생성
```

---

# 6. 파일을 다시 수정해 보기

README.md에 한 줄을 추가합니다.

```markdown
# Git 실습

Git 버전관리 연습입니다.

Git은 파일의 변경 이력을 관리합니다.
```

상태를 확인합니다.

```bash
git status
```

이번에는

```text
modified: README.md
```

와 같이 나타납니다.

어떤 내용이 변경되었는지 확인합니다.

```bash
git diff
```

이 명령은 매우 중요합니다.

```text
git status
→ 어떤 파일이 변경되었나?

git diff
→ 파일 내용이 어떻게 변경되었나?
```

---

# 7. 두 번째 버전 저장

다시 저장합니다.

```bash
git add README.md
```

```bash
git commit -m "Git 설명 추가"
```

기록을 확인합니다.

```bash
git log --oneline
```

예:

```text
83ab123 Git 설명 추가
a31f245 첫 번째 Git 실습
```

이것이 Git의 가장 중요한 기능입니다.

```text
버전 1
  ↓
버전 2
  ↓
버전 3
  ↓
...
```

즉 Git은 단순 파일 저장 프로그램이 아니라 **변경 이력을 관리하는 시스템**입니다.

---

# 8. 브랜치 만들어 보기

AI 에이전트 시대에는 특히 브랜치 개념이 중요합니다.

예를 들어 AI에게 새로운 기능을 작성하게 했다고 가정하겠습니다.

바로 `main`에서 작업하지 않고 새로운 브랜치를 만듭니다.

```bash
git branch feature
```

브랜치를 확인합니다.

```bash
git branch
```

다음과 같이 보일 수 있습니다.

```text
* main
  feature
```

feature 브랜치로 이동합니다.

```bash
git switch feature
```

과거 방식은 다음과 같습니다.

```bash
git checkout feature
```

현재 브랜치를 확인합니다.

```bash
git branch
```

```text
  main
* feature
```

---

# 9. feature 브랜치에서 수정

README.md에 다음 내용을 추가합니다.

```markdown
## AI와 Git

AI가 생성한 코드는 브랜치에서 먼저 테스트합니다.
```

변경 내용을 확인합니다.

```bash
git status
```

```bash
git diff
```

저장합니다.

```bash
git add README.md
```

```bash
git commit -m "AI 작업 설명 추가"
```

현재 상태는 개념적으로 다음과 같습니다.

```text
main
 ──●────●

          \
feature    ●
```

즉 main에는 영향을 주지 않고 별도의 공간에서 작업한 것입니다.

---

# 10. main에 병합하기

main으로 이동합니다.

```bash
git switch main
```

feature의 작업을 main에 합칩니다.

```bash
git merge feature
```

확인합니다.

```bash
git log --oneline --graph --all
```

이 명령은 브랜치 구조를 확인할 때 매우 유용합니다.

개념적으로는 다음과 같습니다.

```text
main
 ──●────●────────●
          \      /
feature    ──●───
```

---

# 11. 실습이 끝나면 feature 삭제

병합한 브랜치는 삭제할 수 있습니다.

```bash
git branch -d feature
```

브랜치를 다시 확인합니다.

```bash
git branch
```

```text
* main
```

---

# 12. GitHub까지 연결한다면

여기까지는 **Git 자체 실습**입니다.

GitHub 저장소까지 연결하면 다음 단계가 추가됩니다.

```text
내 컴퓨터
Git 저장소
     ↓
 git push
     ↓
GitHub
원격 저장소
```

이미 GitHub 저장소를 만들었다면 보통 다음과 같이 연결합니다.

```bash
git remote add origin 저장소주소
```

그리고

```bash
git push -u origin main
```

이후부터는 보통

```bash
git push
```

만 사용하면 됩니다.

다른 사람이 변경한 내용을 가져올 때는

```bash
git pull
```

을 사용합니다.

---

# 13. 이 실습에서 반드시 이해해야 할 명령어

| 명령어 | 의미 |
|---|---|
| `git init` | Git 저장소 시작 |
| `git status` | 현재 변경 상태 확인 |
| `git diff` | 무엇이 변경되었는지 확인 |
| `git add` | 커밋할 변경 선택 |
| `git commit` | 하나의 버전으로 저장 |
| `git log` | 과거 버전 확인 |
| `git branch` | 브랜치 확인/생성 |
| `git switch` | 브랜치 이동 |
| `git merge` | 브랜치 작업 병합 |
| `git push` | GitHub에 변경 내용 전송 |
| `git pull` | GitHub의 변경 내용 가져오기 |

학생들에게는 처음부터 명령어를 많이 알려주기보다 **`status → add → commit`** 세 개를 먼저 확실히 이해시키는 것이 좋습니다.

---

# 14. AI 에이전트 시대에 연결해서 이해하기

예를 들어 Codex, Claude Code, Copilot 같은 AI가 코드를 수정했다고 가정하면 가장 안전한 작업 방식은 다음입니다.

```text
1. main에서 직접 AI에게 대규모 수정시키지 않는다.

main
 ↓

2. AI 작업용 브랜치를 만든다.

git switch -c ai-feature

 ↓

3. AI에게 코드 수정 요청

 ↓

4. 사람이 변경 내용을 확인

git status
git diff

 ↓

5. 테스트

 ↓

6. 정상이라면 저장

git add .
git commit -m "AI 기능 추가"

 ↓

7. main으로 병합
```

즉 Git은 AI가 잘못 작성한 코드를 막아주는 도구라기보다는,

> **AI가 만든 변경을 추적하고, 검토하고, 문제가 있으면 되돌릴 수 있도록 만드는 안전장치**

라고 이해하면 좋습니다.

---

# 15. 수업용 최소 실습 시나리오

30~40분 정도라면 다음 순서만 수행해도 충분합니다.

```text
① git init

② README.md 작성

③ git status

④ git add README.md

⑤ git commit -m "첫 번째 버전"

⑥ README.md 수정

⑦ git diff

⑧ git add README.md

⑨ git commit -m "내용 수정"

⑩ git log --oneline

⑪ git switch -c feature

⑫ README.md 수정

⑬ git add .
⑭ git commit -m "feature 작업"

⑮ git switch main

⑯ git merge feature
```

이 실습 하나만 제대로 해도 학생들은 **작업 디렉터리 → 스테이징 → 커밋 → 브랜치 → 병합**이라는 Git의 핵심 구조를 실제로 경험하게 됩니다.

특히 현재 과정에서 AI Coding Agent까지 연결한다면, **2차 실습으로 `AI에게 README 또는 간단한 Python 코드를 수정시키고 → git diff로 사람이 검토 → commit → 문제가 있으면 이전 상태로 복구`하는 실습**을 붙이는 것이 가장 효과적입니다.
