# 1차 프로젝트 최종 발표 구성 가이드

AX 풀스택 빌더 과정 | 세미프로젝트 | 비전공자 중심

1차 프로젝트는 프론트엔드·백엔드·데이터베이스를 연동하여 하나의 웹 서비스를 직접 구현하는 경험에 중점을 둔 프로젝트입니다.

따라서 최종 발표에서는 단순히 구현한 기능을 보여주는 것보다 무엇을 만들었고, 어떻게 설계했으며, 팀원들이 어떤 역할을 수행했고, 어떤 문제를 해결했는지를 설명하는 것이 중요합니다.

특히 2차·3차 프로젝트에서는 AI 협업 및 에이전트 기반 개발 역량을 점진적으로 강화한다는 점을 고려하여, 1차 프로젝트는 기본 개발 역량을 확인하는 방향으로 구성하는 것을 권장합니다.

## 3. 기술적인 발표에서 반드시 포함할 내용

단순히 사용 기술을 나열하는 대신 다음 세 가지를 중심으로 설명하도록 지도하는 것이 좋습니다.

### ① 전체 시스템의 데이터 처리 흐름

예시 기술 스택이며, 팀별 실제 사용 기술로 변경합니다.

설명 예시: 사용자가 회원 등록 버튼을 클릭하면 프론트엔드에서 데이터를 JSON으로 전송합니다. FastAPI 서버가 유효성을 검증한 후 SQL을 통해 MariaDB에 저장하고, 처리 결과를 JSON 응답으로 반환합니다.

### ② DB 설계 설명

테이블 이름만 설명하는 것이 아니라 다음과 같은 설계 의도를 설명해야 합니다.

- 회원과 주문 테이블을 분리한 이유
- 기본키와 외래키를 사용한 이유
- 1:N 관계를 적용한 이유
- 데이터 중복을 줄이기 위한 설계 내용

### ③ 구현 기능과 담당자 역할

| 기능       | 담당자  | 구현 내용                |
| -------- | ---- | -------------------- |
| 회원 관리    | 팀원 A | 회원 등록·조회·수정          |
| 상품 관리    | 팀원 B | 상품 CRUD 및 검색         |
| 주문 관리    | 팀원 C | 주문 데이터 저장 및 조회       |
| 통합 및 테스트 | 공동   | API 연동, 오류 수정, 기능 검증 |

실제 역할에 맞게 수정하고, 각 담당자가 자신이 구현하거나 기여한 부분을 직접 설명하도록 하는 것이 좋습니다.

## 4. 프로젝트 발표 평가 기준 예시

| 평가 항목       | 배점   | 주요 평가 내용           |
| ----------- | ---- | ------------------ |
| 기획 및 요구사항   | 15점  | 목표와 기능의 명확성        |
| 시스템 및 DB 설계 | 20점  | 아키텍처 이해, ERD 적절성   |
| 기능 구현 완성도   | 25점  | 실제 동작, 프론트·백·DB 연동 |
| 시연 및 테스트    | 15점  | 핵심 시나리오 동작, 오류 대응  |
| 팀 협업 및 역할   | 15점  | 참여도와 담당 업무 이해      |
| 발표 및 질의응답   | 10점  | 설명의 명확성, 기술 이해도    |
| 합계          | 100점 |                    |

이 기준은 발표 평가뿐 아니라 프로젝트 결과물의 완성도를 함께 평가하는 예시입니다. 팀별 평가와 개인별 기여도 평가는 별도로 구분할 수 있습니다.

## 5. 발표할 때 강조할 사항

1차 프로젝트가 비전공자 중심의 기초 풀스택 프로젝트라는 점을 고려하면, 다음 네 가지를 우선적으로 평가하는 것이 적절합니다.

- 동작 원리 이해: 내가 개발한 기능에서 데이터가 어떤 경로로 이동하고 처리되는지 설명할 수 있는가?
- 기술 이해: 단순히 FastAPI, MariaDB 등의 이름을 아는 것이 아니라 각 기술의 역할을 이해하고 있는가?
- 문제 해결: 오류가 발생했을 때 원인을 확인하고 수정한 경험을 설명할 수 있는가?
- 협업 경험: GitHub를 통한 소스 통합, 역할 분담, 공동 테스트 등에 참여했는가?

특히 AI를 사용해 개발한 경우에는 AI가 작성한 코드를 본인이 이해하고 검증했는지도 확인하면 좋습니다.

초기화

강사 관점에서 가장 중요한 것은 1차 프로젝트 발표를 통해 학생들이 자신이 만든 프로그램의 구조와 데이터 흐름을 설명할 수 있는지를 확인하는 것입니다.

1차 프로젝트에서는 직접 구현하고 이해한 경험, 2차에서는 AI와 협업하여 개발하는 경험, 3차에서는 설계 문서를 바탕으로 AI 에이전트를 통제하고 검증하는 경험으로 발전시키면 교육 과정 전체의 연계성이 높아집니다.
