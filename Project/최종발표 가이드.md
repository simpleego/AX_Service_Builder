# 1차 프로젝트 최종 발표 구성 가이드

- 1차 프로젝트는 프론트엔드·백엔드·데이터베이스를 연동하여 하나의 웹 서비스를 직접 구현하는 경험에 중점을 둔 프로젝트입니다.
- 단순히 구현한 기능을 보여주는 것보다 무엇을 만들었고, 어떻게 설계했으며, 팀원들이 어떤 역할을 수행했고, 어떤 문제를 해결했는지를 설명하는 것이 중요합니다.
- 특히 2차·3차 프로젝트에서는 AI 협업 및 에이전트 기반 개발 역량을 점진적으로 강화한다는 점을 고려하여, 1차 프로젝트는 기본 개발 역량을 확인하는 방향으로 구성하는 것을 권장합니다.

## 1. 발표 시간 및 전체 구성

# 1차 프로젝트 최종 발표 시간표 (30분)

| 3  | 시스템 아키텍처 및 DB 설계 | 5분  |

| 5  | 실제 프로그램 시연       | 10분  |
| 6  | 문제 해결 및 성과·회고    | 2분  |

| 합계 |                  | 30분 |

## 항목별 발표 세부 내용

| 발표 내용           | 세부 구성                                               |
| --------------- | --------------------------------------------------- |
| 1. 프로젝트 소개      | 프로젝트명, 개발 목적, 개발 기간, 팀원별 역할과 기여 내용                  |
| 2. 기획 및 요구사항    | 기획 배경, 해결하려는 문제, 주요 사용자, 기능 요구사항, 화면 설계             |
| 3. 아키텍처 및 DB 설계 | 전체 시스템 구성도, 기술 스택, 프론트엔드↔백엔드↔DB 데이터 흐름, ERD, 테이블 관계 |

| 5. 프로그램 시연      | 실제 서비스 실행, 핵심 CRUD 기능, 사용자 시나리오, 프론트엔드와 DB 연동 확인    |
| 6. 문제 해결 및 회고   | 개발 과정의 오류와 해결 사례, 프로젝트 성과, 부족한 점, 향후 개선 방향          |
| 7. 질의응답 및 추가 시연 | 기술 관련 질문, 팀원별 담당 기능 확인, 필요시 특정 기능 추가 시연             |

## 발표 운영 권장사항

- PPT 분량: 12\~15장 내외
- 발표 참여: 모든 팀원이 자신의 담당 기능이나 작업 결과를 최소 1개 이상 설명
- 코드 설명: 전체 소스가 아니라 주요 API, 비즈니스 로직, DB 처리 코드 중심
- 시연 방식: 미리 준비한 데이터로 등록 → 조회 → 수정 → 삭제까지 실제 실행
- 질의응답: 강사가 임의의 기능에 대해 데이터 처리 흐름, 설계 이유, 오류 해결 방법 등을 질문

특히 1차 프로젝트는 화려한 UI나 기능 개수보다, 학생들이 직접 구현한 웹 서비스의 전체 동작 원리를 얼마나 이해하고 설명할 수 있는지가 핵심 평가 기준이 되어야 합니다.

## 2. PPT 슬라이드별 발표 내용

슬라이드 1. 프로젝트 소개

프로젝트명, 개발 목적, 개발 기간, 팀명, 팀원 및 담당 역할을 소개합니다. 프로젝트를 한 문장으로 설명할 수 있도록 준비합니다.

슬라이드 2. 기획 배경 및 목표

기존 서비스나 일상생활의 문제점, 프로젝트 기획 동기, 주요 사용자, 해결하고자 하는 목표를 설명합니다.


슬라이드 3. 주요 요구사항 및 기능

로그인, 등록, 조회, 수정, 삭제, 검색 등 핵심 기능을 정리합니다. 구현 완료 여부를 기능별로 표시하면 좋습니다.

슬라이드 4. 전체 시스템 아키텍처

사용자가 웹브라우저에서 요청한 데이터가 프론트엔드, API, 백엔드, 데이터베이스를 거쳐 처리되는 과정을 설명합니다.

슬라이드 5. 데이터베이스 설계

ERD를 보여주며 핵심 테이블, 기본키(PK), 외래키(FK), 테이블 간 관계 및 설계 이유를 설명합니다.

슬라이드 6. 주요 화면 및 기능 구현

실제 개발한 화면을 보여주면서 프론트엔드 입력, 백엔드 처리, DB 저장 및 조회의 연동 과정을 설명합니다.

슬라이드 7. 실제 프로그램 시연

슬라이드 설명에서 벗어나 실행 중인 프로그램에서 주요 기능을 직접 시연합니다. 등록 → 조회 → 수정 → 삭제와 같은 연속 시나리오가 적합합니다.

슬라이드 8. 개발 중 발생한 문제와 해결 과정

실제 발생한 오류 1\~2개를 선정하고 원인, 해결 방법, 결과를 설명합니다. 예: API 405 오류, CORS 문제, 데이터베이스 연동 오류 등.

슬라이드 9. 프로젝트 성과 및 향후 개선 방향

구현 완료 기능, 아쉬웠던 점, 새롭게 학습한 기술, 2차 프로젝트에서 보완하고 싶은 내용을 설명합니다.

## 3. 기술적인 발표에서 반드시 포함할 내용

단순히 사용 기술을 나열하는 대신 다음 세 가지를 중심으로 설명하도록 지도하는 것이 좋습니다.

### ① 전체 시스템의 데이터 처리 흐름

예시 기술 스택이며, 팀별 실제 사용 기술로 변경합니다.

설명 예시: 사용자가 회원 등록 버튼을 클릭하면 프론트엔드에서 데이터를 JSON으로 전송합니다. FastAPI 서버가 유효성을 검증한 후 SQL을 통해 MariaDB에 저장하고, 처리 결과를 JSON 응답으로 반환합니다.

### ② DB 설계 설명

테이블 이름만 설명하는 것이 아니라 다음과 같은 설계 의도를 설명해야 합니다.

- 회원과 주문 테이블을 분리한 이유
- 기본키와 외래키를 사용한 이유
- 1:N 관계를 적용한 이유
- 데이터 중복을 줄이기 위한 설계 내용

### ③ 구현 기능과 담당자 역할

| 기능       | 담당자  | 구현 내용                |
| -------- | ---- | -------------------- |
| 회원 관리    | 팀원 A | 회원 등록·조회·수정          |
| 상품 관리    | 팀원 B | 상품 CRUD 및 검색         |
| 주문 관리    | 팀원 C | 주문 데이터 저장 및 조회       |
| 통합 및 테스트 | 공동   | API 연동, 오류 수정, 기능 검증 |

실제 역할에 맞게 수정하고, 각 담당자가 자신이 구현하거나 기여한 부분을 직접 설명하도록 하는 것이 좋습니다.

## 4. 발표할 때 강조할 사항

1차 프로젝트가 비전공자 중심의 기초 풀스택 프로젝트라는 점을 고려하면, 다음 네 가지를 우선적으로 평가하는 것이 적절합니다.

- 동작 원리 이해: 내가 개발한 기능에서 데이터가 어떤 경로로 이동하고 처리되는지 설명할 수 있는가?
- 기술 이해: 단순히 FastAPI, MariaDB 등의 이름을 아는 것이 아니라 각 기술의 역할을 이해하고 있는가?
- 문제 해결: 오류가 발생했을 때 원인을 확인하고 수정한 경험을 설명할 수 있는가?
- 협업 경험: GitHub를 통한 소스 통합, 역할 분담, 공동 테스트 등에 참여했는가?

특히 AI를 사용해 개발한 경우에는 AI가 작성한 코드를 본인이 이해하고 검증했는지도 확인하면 좋습니다.

## 발표 준비 현황

아래에 제시된 10개중에서 몇개를 완료했는지 파악한다.

```
1. 프로젝트 목적과 핵심 기능을 명확히 설명할 수 있다.

2. 팀원별 역할 및 실제 수행 작업을 정리했다.

3. 전체 시스템 구조도를 준비했다.

4. 데이터베이스 ERD와 테이블 관계를 설명할 수 있다.

5. 주요 API 요청과 응답 흐름을 이해하고 있다.

6. 프로젝트의 핵심 기능이 정상 실행된다.

7. 3분 이내의 시연 시나리오를 준비했다.

8. 개발 중 오류 및 해결 사례를 정리했다.

9. 팀원 모두 본인의 담당 업무를 발표할 수 있다.

10. 발표 30분에 맞춰 리허설을 완료했다.
```
