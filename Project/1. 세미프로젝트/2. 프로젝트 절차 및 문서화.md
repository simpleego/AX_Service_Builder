# 1차 세미프로젝트에서 포함해야 할 기술

PDF를 기준으로 첫 프로젝트에서 활용 가능한 내용은 크게 세 영역입니다.

### ① 서비스 기획

PDF에서는 문제 정의, 사용자 리서치, 페르소나, 사용자 여정, 기능 명세, Figma, 와이어프레임 등을 먼저 학습합니다. :chatgpt-content-reference{index="4"}

따라서 프로젝트에서도 이를 활용합니다.

```text
문제 정의
→ 사용자 정의
→ 요구사항
→ 핵심 기능
→ 화면 설계
```

### ② Python/FastAPI 백엔드 기초

FastAPI 구조, 라우팅, Dependency Injection, 데이터 처리 파이프라인, 예외처리·로깅까지 학습합니다. :chatgpt-content-reference{index="5"}

따라서:

```text
Python 데이터 처리
FastAPI
라우팅
데이터 입출력
예외처리
로깅
```

까지 사용할 수 있습니다.

### ③ DB

첫 프로젝트에서 가장 중요하게 평가할 부분입니다.

PDF에 다음 내용이 명확하게 들어 있습니다. :chatgpt-content-reference{index="6"}

```text
RDB
정규화
ERD
SQL Query
인덱스
성능 최적화
```

따라서 첫 프로젝트의 중심은 **DB 중심 데이터 서비스**가 되어야 합니다.

# 1차 세미프로젝트의 목표

> **관심 도메인(부동산·금융·커머스 등)의 실제 데이터를 수집·가공하고, 서비스 요구사항에 맞는 관계형 데이터베이스를 설계·구축하여 FastAPI 기반으로 데이터를 등록·조회·수정·삭제하고 분석 결과를 제공하는 데이터 중심 서비스를 구현한다.**

핵심 키워드는:

```text
실제 데이터
+
Python 데이터 처리
+
DB 모델링
+
SQL
+
FastAPI
```

입니다.

예:

```text
지역에 여러 아파트가 있다.
아파트에는 여러 거래정보가 존재한다.
```

```text
지역
아파트

```

↓

```text

```

↓

관계:

```text
Region 1 ─── N Apartment

Apartment 1 ─── N Transaction
```

이 단계가 중요한 이유는 학생들이

> “ERD는 갑자기 그리는 그림이 아니다.”

라는 것을 이해하게 하기 때문입니다.

# 문서 ⑤ ERD 및 DB 설계서

이번 프로젝트의 **핵심 문서**로 두는 것이 좋습니다.

PDF에서도 별도 단원으로 ERD, 인덱스를 다룹니다. :chatgpt-content-reference{index="10"}

학생에게 다음을 작성하게 합니다.

### ① ERD

```text
Region
---------
region_id PK
name


Apartment
---------
apartment_id PK
region_id FK
name
address


Transaction
---------
transaction_id PK
apartment_id FK
price
area
floor
contract_date
```

### ② 관계

```text
Region
   │1
   │
   │N
Apartment
   │1
   │
   │N
Transaction
```

### ③ 정규화

간단하게라도 설명하게 합니다.

```text
1NF
반복되는 데이터를 분리

2NF
부분 함수 종속 제거

3NF
이행적 종속 제거
```

그리고

> 왜 Region과 Apartment를 하나의 테이블로 만들지 않았는가?

같은 질문에 답할 수 있어야 합니다.

# 문서 ⑥ FastAPI 기능 정의서

여기서는 “RESTful API 아키텍처”를 깊게 요구하면 안 됩니다.

그 내용은 다음 단계의 학습내용이기 때문입니다.

1차 프로젝트에서는 **FastAPI에서 어떤 URL을 제공할 것인가** 정도로 제한합니다.

예:

| Method | URL | 기능 |
|---|---|---|
| GET | `/regions` | 지역조회 |
| GET | `/apartments` | 아파트조회 |
| GET | `/transactions` | 거래조회 |
| POST | `/transactions` | 거래등록 |
| PUT | `/transactions/{id}` | 거래수정 |
| DELETE | `/transactions/{id}` | 거래삭제 |
| GET | `/statistics` | 거래통계 |

요청/응답 예시 정도만 추가합니다.

```json
{
    "apartment_id": 10,
    "price": 350000000,
    "area": 84.5
}
```

# 프로젝트 평가도 DB 중심

예를 들어 100점이라면 다음처럼 설계할 수 있습니다.

| 평가영역 | 배점 |
|---|---:|
| 문제 정의 및 기획 | 10 |
| 데이터 확보·전처리 | 15 |
| 도메인 모델링 | 15 |

| DB 구현 및 SQL | 20 |
| SQLAlchemy/FastAPI | 15 |
| 테스트 | 5 |

| **합계** | **100** |

특히 **DB 관련 영역을 약 50% 가까이** 두는 것이 이번 프로젝트 시점과 잘 맞습니다.
