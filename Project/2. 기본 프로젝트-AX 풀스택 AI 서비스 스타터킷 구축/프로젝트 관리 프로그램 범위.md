# 프로젝트 관리 프로그램 범위 

## 1. 필수 구현 범위 (MVP - 1~9일 차 목표)

프로젝트의 뼈대가 되는 기능들로, 이 기능들만 완벽히 돌아가도 포트폴리오로서 충분한 가치를 가집니다.
- 회원가입 및 로그인 (인증)
	- 이메일 기반 기본 로그인 또는 소셜 로그인(Kakao, Google 등 OAuth 1개)을 구현합니다.
	- 로그인한 사용자만 자신의 프로젝트에 접근할 수 있도록 권한을 제어합니다.
- 워크스페이스(프로젝트) 관리
	- 프로젝트를 생성, 수정, 삭제(CRUD)할 수 있는 대시보드 화면을 제공합니다.
	- 초대 코드나 이메일 검색을 통해 팀원을 프로젝트에 초대하는 기능을 넣습니다.
- 칸반 보드 (핵심 UI/UX)
	- 상태 컬럼(예: 할 일(To Do), 진행 중(In Progress), 완료(Done))을 구성합니다.
	- 드래그 앤 드롭(Drag & Drop)으로 카드의 순서를 바꾸거나 다른 상태로 이동시킵니다. (dnd-kit이나 react-beautiful-dnd 같은 라이브러리와 AI를 활용하면 수월합니다.)
- 업무 카드(Task) 상세 관리
	- 카드 생성 시 제목, 상세 설명(텍스트), 담당자 지정, 마감일(Due Date), 우선순위(높음/보통/낮음)를 설정합니다.
	- 카드 클릭 시 모달(Modal) 창이 열리며 내용을 수정하거나 삭제할 수 있습니다.
- 기본 댓글 및 활동 로그
	- 카드 내부에서 팀원 간 의견을 남길 수 있는 간단한 댓글 작성/삭제 기능을 구현합니다.

## 2. 추가 구현 추천 범위 (시간 여유 시 - 10~12일 차 목표)

AI의 도움을 받아 비교적 적은 공수로 시각적 완성도와 퀄리티를 크게 높일 수 있는 기능들입니다.
- 대시보드 요약 (통계 차트)
	- 전체 업무 중 완료된 비율이나 담당자별 업무 할당량을 막대/도넛 차트로 보여줍니다. (Chart.js 또는 Recharts 활용)
- 필터링 및 검색 기능
	- '내 업무만 보기', '마감 임박순 정렬', '키워드 검색' 등 프론트엔드 단에서 빠르게 처리 가능한 조회 기능을 추가합니다.
- 캘린더 뷰 (Calendar View)
	- 등록된 카드의 마감일(Due Date) 데이터를 연동해 월간 달력 형태로 일정을 한눈에 보여줍니다. (FullCalendar 라이브러리 활용)

## 3. 과감히 제외해야 할 기능 (Out of Scope)

14일이라는 짧은 기간 동안 시도했다가 프로젝트 전체의 완성도를 떨어뜨릴 수 있는 기능들입니다.
- 실시간 동시 편집 (WebSocket / CRDT)
	- 여러 명이 동시에 같은 카드를 수정할 때 실시간으로 반영되는 기능은 동시성 제어와 서버 부하 이슈로 디버깅 시간이 기하급수적으로 늘어납니다. (새로고침이나 페이지 전환 시 데이터 갱신으로 대체하세요.)
- 노션(Notion) 스타일의 블록 에디터
	- 텍스트, 표, 토글 등을 자유롭게 조립하는 에디터 구현은 난이도가 매우 높습니다. 기본 <textarea>나 가벼운 마크다운 에디터 라이브러리로 대체하는 것이 좋습니다.
- 복잡한 계층형 권한 및 알림 시스템
	- 이메일 발송, 실시간 푸시 알림 등은 외부 API 연동 및 설정에 시간을 많이 뺏기므로 제외하는 것을 권장합니다.

## 4. 14일(112시간) 권장 개발 로드맵

- 1~2일 차: 기획 및 설계
	- 와이어프레임(화면 설계서) 작성, ERD(데이터베이스 테이블) 설계, API 명세서 작성 및 Git 레포지토리 세팅을 완료합니다.
- 3~5일 차: 백엔드 API 및 인증 구현
	- AI를 활용해 기본 CRUD API와 로그인 로직을 빠르게 구축하고 Postman 등으로 테스트합니다.
- 6~9일 차: 프론트엔드 핵심 기능 연동
	- 프로젝트 목록, 칸반 보드 드래그 앤 드롭, 카드 상세 모달의 UI를 구성하고 백엔드 API와 연동합니다.
- 10~12일 차: 서브 기능 추가 및 예외 처리
	- 통계 차트나 필터링 기능을 추가하고, 빈 값 입력이나 권한 없는 접근 등 예외 상황을 처리합니다.
- 13~14일 차: 배포, 버그 수정 및 발표 준비
	- 클라우드 환경(Vercel, AWS, Render 등)에 실제 배포하고, 시연 시나리오에 맞춰 치명적인 버그를 잡습니다.

💡 AI 활용 및 개발 팁

- BaaS(Backend as a Service) 고려: 만약 백엔드 개발 인원이 부족하거나 프론트엔드 비중이 높다면, Supabase나 Firebase를 활용하세요. 인증, DB, API를 AI와 함께 하루 만에 세팅할 수 있어 UI와 UX 완성도에 훨씬 많은 시간을 쏟을 수 있습니다.
- AI에게 '설계'를 먼저 검토받기: 코드를 짜달라고 하기 전에 학생들이 직접 짠 DB 테이블 구조(ERD)나 컴포넌트 구조를 AI에게 보여주고 *"14일 안에 구현하기에 과하거나 빠진 부분이 있는지 리뷰해 줘"*라고 질문하면 시행착오를 크게 줄일 수 있습니다.
팀 구성이나 기술 스택에 맞춰 더 구체적인 가이드를 드릴 수 있습니다. 아래 내용을 알려주실 수 있을까요?
- 팀 인원 및 역할 분담 (예: 프론트엔드 2명, 백엔드 2명 등)
- 학습한 주요 기술 스택 (예: React, Node.js, Spring Boot, Python 등)
알려주시면 해당 스택에 딱 맞는 추천 라이브러리 목록과 초기 DB 테이블(ERD) 구조 예시를 짜드리겠습니다.
