# Claude Code로 풀스택 웹개발을 할 때의 핵심 정리

## 1. 기본 원칙

역할은 이렇게 나뉩니다. 개발자는 무엇을 왜 만들지 정하고, 결과를 판단하고 책임집니다. Claude Code는 정해진 방향을 빠르게 구현하고, 반복 작업과 탐색을 대신합니다.

코드는 AI가 쓰더라도 이해하고 승인하는 사람은 개발자여야 합니다. "설명할 수 없는 코드는 머지하지 않는다"가 가장 중요한 규칙입니다.

## 2. 개발 단계별 역할 구분

| 단계 | 개발자가 할 일 | Claude Code가 할 일 |
|---|---|---|
| **기획·요구사항** | 문제 정의, 사용자·기능 범위 결정, 우선순위 설정 | 요구사항 문서 초안 작성, 누락된 케이스 질문, 유저 스토리 정리 |
| **설계** | 기술 스택 선택, 아키텍처 결정, DB 스키마·API 구조 최종 확정 | 설계 대안 비교, ERD·API 명세 초안, 폴더 구조 제안 |
| **환경 세팅** | 프로젝트 규칙 정의(CLAUDE.md 작성), 권한·환경변수 관리 | 프로젝트 스캐폴딩, 패키지 설치, 설정 파일 생성(ESLint, tsconfig 등) |
| **프론트엔드** | 화면 흐름·UX 판단, 디자인 기준 제시, 결과 화면 확인 | 컴포넌트 구현, 상태관리, API 연동 코드, 반응형 스타일링 |
| **백엔드·API** | 비즈니스 로직 규칙 정의, 인증·권한 정책 결정 | 라우터·컨트롤러·서비스 코드 작성, 유효성 검사, 에러 처리 |
| **데이터베이스** | 데이터 모델 확정, 마이그레이션 적용 승인, 운영 DB 접근 통제 | 모델·마이그레이션 작성, 쿼리 작성·최적화, 시드 데이터 생성 |
| **테스트** | 무엇을 반드시 검증할지 기준 설정, 테스트 결과 해석 | 단위·통합 테스트 작성 및 실행, 실패 원인 분석 |
| **디버깅** | 재현 조건과 증상을 정확히 전달, 수정 방향 승인 | 로그·스택트레이스 분석, 관련 코드 탐색, 수정안 적용 |
| **보안** | 인증·결제·개인정보 코드 직접 검토, 비밀키 관리 | 취약점 점검(SQL 인젝션, XSS 등), 의존성 이슈 확인 |
| **버전관리·리뷰** | diff 검토, 머지·배포 승인 | 커밋 메시지 작성, 변경사항 요약, PR 설명 작성 |
| **배포·운영** | 배포 시점·환경 결정, 장애 대응 판단 | Dockerfile·CI/CD 설정 작성, 배포 스크립트, 문서화 |

## 3. Claude Code를 잘 쓰기 위한 핵심 습관

- **CLAUDE.md를 먼저 쓴다.** 기술 스택, 폴더 구조, 코딩 컨벤션, 실행·테스트 명령어를 적어두면 매번 설명할 필요가 없고 결과가 일관됩니다.
- **계획 먼저, 구현은 나중에.** 큰 기능은 Plan 모드로 계획을 받아 검토한 뒤 실행시킵니다.
- **작은 단위로 요청한다.** "쇼핑몰 만들어줘"가 아니라 "상품 목록 API를 페이지네이션 포함해서 만들어줘"처럼 요청합니다.
- **기능 하나마다 커밋한다.** AI가 잘못 가도 바로 되돌릴 수 있습니다.
- **테스트로 검증한다.** "구현 후 테스트를 돌려서 통과할 때까지 수정해줘"처럼 검증 루프를 맡기면 품질이 크게 올라갑니다.
- **필요한 도구를 연결한다.** MCP로 DB, 브라우저, 문서 등을 연결하면 AI가 실제 결과를 확인하며 작업할 수 있습니다.

## 4. 반드시 개발자가 직접 해야 하는 것

1. 요구사항과 우선순위 결정
2. 데이터 모델과 아키텍처의 최종 결정
3. 인증·권한·결제·개인정보 관련 코드 검토
4. API 키·비밀번호 등 민감정보 관리 (AI 프롬프트나 코드에 노출 금지)
5. 운영 DB 변경과 배포 승인
6. 생성된 코드를 읽고 이해했는지 확인

## 5. 교육과정으로 운영할 때의 포인트

- **기초는 AI 없이 먼저.** HTML/CSS/JS, HTTP, SQL 기본기가 없으면 AI가 만든 코드를 검토할 수 없습니다.
- **"쓰는 능력"보다 "읽는 능력" 비중을 높인다.** 코드 리딩, diff 리뷰, 디버깅 실습이 더 중요해집니다.
- **프롬프트 작성 = 명세 작성 훈련.** 요구사항을 구체적으로 쓰는 능력이 결과 품질을 좌우합니다.
- **평가 방식도 바뀌어야 한다.** 결과물만 보지 말고 "이 코드가 왜 이렇게 동작하는지" 설명하게 하는 구술·리뷰 평가를 넣는 것이 효과적입니다.
