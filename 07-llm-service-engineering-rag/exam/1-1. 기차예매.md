가능합니다. 다만 코레일 약관에는 **자동 반복 명령 프로그램으로 다른 고객의 구매를 방해하거나 서비스 제공을 방해하는 행위**가 이용 제한 사유로 명시되어 있고, 코레일은 반복 조회 등을 탐지하는 매크로 탐지 시스템도 운영한다고 밝히고 있습니다. 따라서 아래 예제는 **일반적인 1회성 브라우저 자동화 + 사용자 최종 승인 방식**으로 구성하는 것이 적절합니다. :chatgpt-content-reference{index="0"}

브라우저 제어는 Playwright를 쓰겠습니다. Playwright는 `get_by_role()`, `get_by_label()` 같은 사용자 중심 locator를 권장하며, 화면 변경에도 긴 CSS/XPath보다 상대적으로 견고합니다. :chatgpt-content-reference{index="1"}

```python
from langchain_core.tools import tool

_playwright = None
_browser = None
_page = None


def get_page():
    global _playwright, _browser, _page

    if _page is None:

        _playwright = sync_playwright().start()

        _browser = _playwright.chromium.launch(
```

# 6. 출발역 입력 Tool

여기부터가 Browser/Computer Use의 핵심입니다.

```python
@tool
def input_departure_station(
    station: str
) -> str:
    """
    승차권 조회 화면에서 출발역을 입력한다.
    """

    page = get_page()

    candidates = [

        page.get_by_label("출발역"),

        page.get_by_placeholder("출발역"),

        page.locator(
            'input[name*="departure"]'
        )
    ]

    for locator in candidates:

        try:
            if locator.count() > 0:

                locator.first.fill(station)

                return (
                    f"출발역을 "
                    f"{station}으로 입력했습니다."
                )

        except Exception:
            continue

    return "출발역 입력창을 찾지 못했습니다."
```

여기서 일부러 여러 locator를 사용했습니다.

```python
get_by_placeholder()

```

순으로 탐색합니다.

```python
@tool
def read_train_results() -> str:
    """
    현재 화면의 열차 조회 결과를 읽는다.
    """

    page = get_page()

    try:

        tables = page.locator("table")

        result = []

        for i in range(
            min(tables.count(), 5)
        ):

            text = tables.nth(i).inner_text()

            result.append(text)

        if result:

            return "\n\n".join(result)

    except Exception:
        pass

    return page.locator(
        "body"
    ).inner_text()[:15000]
```

# 11. 특정 열차 행 선택

Agent가

```text
09:04 KTX
```

를 골랐다고 가정합니다.

```python
@tool
def select_train(
    departure_time: str
) -> str:
    """
    특정 출발시간을 포함하는 열차 행을 선택한다.
    """

    page = get_page()

    try:

        row = page.locator(
            "tr"
        ).filter(
            has_text=departure_time
        )

        if row.count() == 0:

            return (
                f"{departure_time} 열차를 "
                "찾지 못했습니다."
            )

        row = row.first

        reserve_buttons = [

            row.get_by_role(
                "button",
                name="예매"
            ),

            row.get_by_role(
                "link",
                name="예매"
            ),

            row.get_by_text(
                "예매",
                exact=True
            )
        ]

        for button in reserve_buttons:

            try:

                if button.count() > 0:

                    button.first.click()

                    return (
                        f"{departure_time} "
                        "열차 예매 화면으로 이동했습니다."
                    )

            except Exception:
                continue

    except Exception as e:

        return str(e)

    return "예매 버튼을 찾지 못했습니다."
```

이것은 API 호출이 아닙니다.

실제로

```text
HTML 화면에 있는
예매 버튼
```

을 클릭하는 겁니다.

## 수업 관점에서 아주 중요한 차이

이전 API 버전에서는:

```python
search_train(
    "대전",
    "광주송정"
)
```

한 줄이면 됐습니다.

Browser Agent에서는:

```text
사이트 열기
↓
화면 파악
↓
출발역 찾기
↓
값 입력
↓
도착역 찾기
↓
값 입력
↓
날짜 입력
↓
조회 클릭
↓
페이지 변경 기다리기
↓
결과 분석
```

이 필요합니다.

그래서 현실의 Agent 개발에서 **LLM보다 Tool 설계가 더 어려운 경우가 많습니다.**

그리고 여기서 MCP나 Computer Use가 등장하는 이유도 자연스럽게 이해할 수 있습니다.

```text
LLM
= 판단

LangGraph
= 업무 흐름 / 상태 관리

Playwright
= 브라우저 손

Vision
= 화면을 보는 눈

MCP / Tool
= 외부 기능 연결 규격
```

즉 심플님이 처음 지적한 **“API가 없으면 Agent가 실제 일을 어떻게 하지?”**라는 질문에서 출발해서, 바로 **Browser Agent → Computer Use Agent** 개념으로 연결됩니다. 이 예제를 교육에 사용한다면 ReAct를 설명한 다음 단계 실습으로 상당히 적합합니다.
