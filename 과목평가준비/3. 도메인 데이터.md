전체 문제는 **관계형 데이터베이스의 기본 개념 → 테이블 관계 설계 → SQL 활용 → 성능 개선 → 트랜잭션**까지 단계적으로 이해했는지를 확인하는 구성입니다. 시험 대비용으로 정리하면 다음과 같습니다.

- **테이블(Table)**: 고객, 상품, 주문처럼 관리하려는 대상을 행과 열의 형태로 저장하는 구조입니다. 예를 들어 `Customer`, `Product`, `Orders`와 같은 테이블을 만들 수 있습니다.
- **행(Row, Record)**: 테이블에서 하나의 실제 데이터 항목을 의미합니다. 고객 테이블에서는 한 행이 고객 한 명의 정보를 나타냅니다.
- **기본키(Primary Key, PK)**: 테이블의 각 행을 유일하게 구분하는 값입니다. 예를 들어 `customer_id`처럼 중복되지 않는 값을 사용합니다.
- **외래키(Foreign Key, FK)**: 다른 테이블의 기본키를 참조하여 테이블 간의 관계를 연결하는 컬럼입니다. 예를 들어 주문 테이블의 `customer_id`가 고객 테이블의 `customer_id`를 참조할 수 있습니다.
- **1:N 관계**: 하나의 데이터가 여러 데이터와 연결되는 관계입니다. 예를 들어 고객 한 명이 여러 주문을 할 수 있으므로 `고객 1 : 주문 N` 관계입니다.
- **N:M 관계**: 양쪽의 데이터가 서로 여러 개씩 연결되는 관계입니다. 예를 들어 학생은 여러 과목을 수강하고, 하나의 과목에도 여러 학생이 등록할 수 있습니다. 관계형 데이터베이스에서는 이를 직접 표현하기 어렵기 때문에 `수강(학생ID, 과목ID)`과 같은 **중간 테이블(연결 테이블)**을 만들어 두 개의 1:N 관계로 변환합니다.
- **ERD(Entity Relationship Diagram)**: 테이블, 컬럼, 기본키·외래키, 테이블 간 관계를 그림으로 표현한 설계도입니다. 데이터베이스를 실제로 구현하기 전에 구조를 파악하는 데 사용합니다.
- **정규화(Normalization)**: 동일한 데이터를 여러 곳에 반복 저장해서 발생하는 중복과 수정 오류를 줄이기 위한 데이터베이스 설계 방법입니다. 예를 들어 주문마다 고객 주소를 반복 저장하기보다 고객 테이블에서 관리하고 주문 테이블에서는 고객 ID만 참조하는 방식입니다.
- **ORM(Object-Relational Mapping)**: 프로그램의 객체와 관계형 데이터베이스의 테이블을 연결해서 SQL을 직접 많이 작성하지 않고도 데이터를 처리할 수 있도록 하는 기술입니다. Python에서는 SQLAlchemy 등이 대표적인 ORM 도구입니다.
- **WHERE 절**: SQL 조회 시 특정 조건에 맞는 행만 선택하는 데 사용합니다. 예: `SELECT * FROM customer WHERE name='홍길동';`
- **JOIN**: 여러 테이블의 데이터를 공통 컬럼을 기준으로 연결해서 조회하는 SQL 연산입니다. 고객 정보와 주문 정보를 함께 조회할 때 주로 사용합니다.
- **UNIQUE 제약조건**: 특정 컬럼에 중복된 값이 저장되지 않도록 하는 제약조건입니다. 회원 이메일처럼 중복을 허용하면 안 되는 컬럼에 적용할 수 있습니다.
- **인덱스(Index)**: 검색이 자주 발생하는 컬럼의 조회 속도를 향상시키기 위한 데이터 구조입니다. 회원 이메일이나 상품명처럼 자주 검색되는 컬럼에 적용할 수 있습니다. 다만 인덱스가 많으면 INSERT·UPDATE·DELETE 성능과 저장공간에 부담이 생길 수 있습니다.
- **상품 검색 성능 개선**: 상품명이 자주 검색된다면 상품명 컬럼에 인덱스를 생성하는 방법을 먼저 고려할 수 있습니다. 또한 `SELECT *` 대신 필요한 컬럼만 조회하고, 불필요한 전체 테이블 검색을 줄이며, 실행 계획을 확인하여 쿼리를 최적화할 수 있습니다. 검색 방식이 `%노트북%`처럼 앞에 와일드카드가 붙는 경우에는 일반 인덱스의 효과가 제한될 수 있으므로 전문검색(Full-Text Search) 등의 방법도 고려할 수 있습니다.
- **트랜잭션(Transaction)**: 여러 개의 데이터 변경 작업을 하나의 논리적인 작업 단위로 묶어 처리하는 것입니다. 예를 들어 주문을 등록하면서 동시에 재고를 감소시키는 작업은 함께 성공하거나 함께 취소되는 것이 안전합니다.
- **COMMIT**: 트랜잭션에서 수행한 변경 내용을 데이터베이스에 최종적으로 확정합니다.
- **ROLLBACK**: 트랜잭션 도중 문제가 발생했을 때 변경 내용을 취소하고 이전 상태로 되돌립니다.

쇼핑몰을 예로 들면 **회원 테이블**은 `회원ID, 이름, 이메일, 주소`, **상품 테이블**은 `상품ID, 상품명, 가격, 재고수량`, **주문 테이블**은 `주문ID, 회원ID, 주문일자, 주문상태` 등의 컬럼으로 설계할 수 있습니다. 여기서 회원과 주문은 **1:N 관계**이며, 주문 테이블의 `회원ID`가 회원 테이블의 기본키를 참조하는 외래키가 됩니다.

전체 흐름을 한 문장으로 정리하면 **“관리 대상을 테이블로 정의하고 → 기본키와 외래키로 관계를 설정하고 → ERD와 정규화로 구조를 설계한 뒤 → SQL·JOIN·ORM으로 데이터를 처리하고 → 인덱스로 성능을 개선하며 → 트랜잭션으로 데이터의 일관성을 보장한다.”**라고 이해하면 됩니다.
