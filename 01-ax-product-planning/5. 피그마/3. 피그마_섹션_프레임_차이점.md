# 피그마의 섹션과 프레임 차이점.md

> **Frame은 실제 UI를 만드는 “디자인 컨테이너”이고, Section은 여러 디자인을 정리하는 “캔버스 관리 영역”입니다.**

- Figma 공식 설명에서도 Frame은 버튼, 카드, 모바일 화면, 웹페이지 같은 실제 디자인을 구성하는 컨테이너이고,
- Section은 관련된 프레임과 아이디어를 묶어 캔버스를 정리하고 협업 흐름을 보여주는 용도로 설명합니다. ([Figma 도움말 센터][1])

## 1. 가장 쉬운 구분

예를 들어 쇼핑몰을 Figma로 디자인한다고 하겠습니다.

```text
[ Section : 쇼핑몰 프로젝트 ]

    [ Frame : 메인 화면 ]
    [ Frame : 상품 상세 화면 ]
    [ Frame : 장바구니 화면 ]
    [ Frame : 결제 화면 ]
```

여기서:

```text
Section
= 여러 화면을 묶는 폴더/챕터

Frame
= 실제로 사용자가 보는 화면
```

이라고 이해하면 됩니다.

조금 더 비유하면,

```text
Section = 책의 "장(Chapter)"
Frame   = 장 안에 들어 있는 "페이지"
```

와 비슷합니다.

---

## 2. 가장 중요한 기능 차이

| 구분                     | Section       | Frame                          |
| ---------------------- | ------------- | ------------------------------ |
| 주요 목적                  | 정리, 분류        | 실제 UI 디자인                      |
| 실제 화면 제작               | △ 거의 사용 안 함   | O                              |
| 다른 요소 포함               | O             | O                              |
| Frame 포함               | O             | O                              |
| Auto Layout            | X             | O                              |
| Constraints            | X             | O                              |
| Layout Grid            | X             | O                              |
| Fill/Stroke/Shadow 디자인 | 제한적 조직 목적     | O                              |
| 반응형 설계                 | X             | O                              |
| 프로토타입 화면               | 보조적 목적지 가능    | O 핵심                           |
| 개발 전달                  | 화면들을 묶어 상태 표시 | 실제 구현 대상                       |
| HTML/CSS 대응            | 거의 직접 대응 없음   | `div`, `section`, `main` 등과 대응 |

특히 Frame은 **Auto Layout, Constraints, Layout Guides, Clip Content, Fill, Stroke, Effects 등의 기능을 가진 실제 디자인 객체**입니다. ([Figma 도움말 센터][1])

# 3. 예제 1 — 로그인 화면

로그인 페이지 하나를 만든다고 하겠습니다.

이때는 이렇게 해야 합니다.

```text
Frame : Login Page

 ├─ Logo
 ├─ ID Input
 ├─ Password Input
 └─ Login Button
```

여기서 Login Page는 **Frame**입니다.

왜냐하면 이것은 실제 웹페이지로 구현될 화면이기 때문입니다.

HTML로 가면 대략:

```html
<main class="login-page">

    <h1>My Service</h1>

    <input type="text">

    <input type="password">

    <button>로그인</button>

</main>
```

이 됩니다.

따라서

```text
Figma Frame
      ↓
HTML/CSS 구현 대상
```

입니다.

로그인 화면 하나만 있다면 굳이 Section을 만들 필요는 없습니다.

---

# 4. 예제 2 — 여러 로그인 관련 화면

이번에는 로그인과 관련된 화면이 여러 개 있다고 하겠습니다.

```text
로그인
회원가입
아이디 찾기
비밀번호 찾기
```

이때는 다음 구조가 적절합니다.

```text
Section : 회원 인증

 ├─ Frame : 로그인
 ├─ Frame : 회원가입
 ├─ Frame : 아이디 찾기
 └─ Frame : 비밀번호 찾기
```

여기서 역할 차이가 명확해집니다.

```text
Section
"회원 인증이라는 업무 영역"

Frame
"실제로 구현해야 할 각각의 화면"
```

---

# 5. 예제 3 — 쇼핑몰

쇼핑몰 프로젝트라면 Section이 특히 유용합니다.

```text
Section : 상품

 ├─ Frame : 상품 목록
 └─ Frame : 상품 상세


Section : 주문

 ├─ Frame : 장바구니
 ├─ Frame : 주문서
 └─ Frame : 주문 완료


Section : 회원

 ├─ Frame : 로그인
 ├─ Frame : 회원가입
 └─ Frame : 마이페이지
```

이것이 Section의 대표적인 사용법입니다.

즉 Section은 프로그램의 **업무 영역이나 사용자 흐름**을 나타내는 데 매우 적합합니다.

실제로 Figma도 프로토타입에서 전자상거래 앱의 예로 `Browse`, `Cart`, `Checkout` 같은 사용자 흐름별로 Section을 나누는 방법을 제시합니다. ([Figma 도움말 센터][2])

---

# 6. 예제 4 — 쇼핑몰 메인 페이지 내부 영역

여기서 많이 혼동하는 부분이 있습니다.

쇼핑몰 메인 페이지가 다음과 같다고 하겠습니다.

```text
Header

Banner

추천 상품

신상품

Footer
```

이것들을 Figma Section으로 만들어야 할까요?

보통은 **아닙니다.**

전체 메인 페이지가 하나의 Frame이고, 내부 영역도 Frame으로 구성하는 것이 적절합니다.

```text
Frame : Main Page

 ├─ Frame : Header
 ├─ Frame : Banner
 ├─ Frame : Recommended Products
 ├─ Frame : New Products
 └─ Frame : Footer
```

왜냐하면 Header, Banner, 상품 영역은 **실제 화면 안의 레이아웃 요소**이기 때문입니다.

특히 Auto Layout을 사용하려면 Frame이 필요합니다. Figma의 Auto Layout은 Frame을 기반으로 작동합니다. ([Figma 도움말 센터][3])

---

# 7. 여기서 HTML의 `<section>`과 혼동하면 안 됩니다

학생들이 가장 많이 혼동하는 부분입니다.

Figma에 `Section`이라는 이름이 있으니까 HTML의

```html
<section>
```

과 대응된다고 생각하기 쉽습니다.

하지만 **거의 관계가 없습니다.**

예를 들어 웹페이지에

```html
<section class="products">
    ...
</section>
```

가 있다고 하겠습니다.

Figma에서는 보통 이것을

```text
Frame : Products
```

로 만드는 것이 적절합니다.

즉:

```text
HTML <section>
        ≠
Figma Section
```

입니다.

오히려 다음과 같습니다.

```text
HTML <section>
       ↕
Figma Frame

Figma Section
       ↕
프로젝트 정리/분류
```

이 구분은 매우 중요합니다.

---

# 8. 예제 5 — 반응형 웹

PC, Tablet, Mobile 디자인을 만들었다고 하겠습니다.

잘 구성하면 다음과 같습니다.

```text
Section : Main Page

 ├─ Frame : Desktop 1440
 ├─ Frame : Tablet 768
 └─ Frame : Mobile 375
```

여기에서:

* Section = `Main Page`라는 하나의 기능/화면군
* Frame = 각각의 실제 해상도 디자인

입니다.

따라서 Frame에는 실제로

```text
1440 × 1024
768 × 1024
375 × 812
```

같은 크기를 설정할 수 있습니다.

이것은 Frame이 자체적인 dimensions와 레이아웃 속성을 가진 실제 디자인 컨테이너이기 때문입니다. ([Figma 도움말 센터][1])

---

# 9. 예제 6 — 앱 전체 설계

배달 앱을 만든다고 하겠습니다.

좋은 구조는 다음과 같습니다.

```text
Section : 인증

 ├─ Frame : 로그인
 ├─ Frame : 회원가입
 └─ Frame : 비밀번호 찾기


Section : 음식 주문

 ├─ Frame : 음식점 목록
 ├─ Frame : 음식점 상세
 ├─ Frame : 메뉴 선택
 └─ Frame : 장바구니


Section : 결제

 ├─ Frame : 주문 확인
 ├─ Frame : 결제 방법 선택
 └─ Frame : 결제 완료


Section : 사용자

 ├─ Frame : 마이페이지
 ├─ Frame : 주문 내역
 └─ Frame : 개인정보 수정
```

이 경우 Section은 거의

```text
기능 영역
업무 영역
User Flow
```

의 역할을 합니다.

# 10. 예제 7 — 디자인 진행 상태 관리

Section은 개발 과정에서도 유용합니다.

예를 들어:

```text
Section : 작업 중

 ├─ Frame : 메인 화면
 ├─ Frame : 상품 상세


Section : 리뷰 필요

 ├─ Frame : 장바구니
 └─ Frame : 주문서


Section : 개발 전달 완료

 ├─ Frame : 로그인
 └─ Frame : 회원가입
```

처럼 사용할 수도 있습니다.

Figma는 Section을 이용해 디자인 영역을 구성하고, 협업자가 파일을 탐색하기 쉽게 만들거나 개발 준비 상태를 표시할 수 있도록 지원합니다. ([Figma 도움말 센터][4])

따라서 Section은 단순히 화면 종류를 묶는 용도뿐 아니라

```text
업무 단계
디자인 상태
담당자
버전
사용자 흐름
```

별로 나누는 것도 가능합니다.

# 11. Frame 안에 Frame이 들어가는 경우

Frame은 반드시 화면 전체만 의미하는 것은 아닙니다.

아주 작은 UI도 Frame이 될 수 있습니다.

예를 들어:

```text
Frame : Main Page

 ├─ Frame : Header
 │     ├─ Logo
 │     ├─ Frame : Navigation
 │     │      ├─ 메뉴1
 │     │      ├─ 메뉴2
 │     │      └─ 메뉴3
 │     │
 │     └─ Frame : Login Buttons
 │
 ├─ Frame : Banner
 │
 └─ Frame : Product List
        │
        ├─ Frame : Product Card
        ├─ Frame : Product Card
        └─ Frame : Product Card
```

Frame은 이런 식으로 계속 중첩할 수 있습니다.

Figma는 Frame 내부에 또 다른 Frame을 넣어서 복잡한 UI 구조를 구성할 수 있도록 합니다. ([Figma 도움말 센터][1])

---

# 12. Section 안에는 무엇을 넣는가?

Section은 좀 더 상위 개념입니다.

예:

```text
Section : 상품 관리
│
├─ Frame : 상품 목록 화면
├─ Frame : 상품 등록 화면
├─ Frame : 상품 수정 화면
│
├─ 메모
├─ 설명
└─ 참고 디자인
```

Section은 관련된 여러 종류의 디자인 요소를 하나의 영역으로 묶을 수 있습니다.

Figma에서는 Section이 기본적으로 캔버스의 **top-level 요소**이고 Frame뿐 아니라 다양한 레이어와 다른 Section도 포함할 수 있습니다. 반대로 Section을 Frame 안에 넣을 수는 없습니다. ([Figma 도움말 센터][4])

# 13. Frame과 Section을 판단하는 가장 쉬운 질문

실제로 작업하다 헷갈린다면 다음 질문 하나를 해보면 됩니다.

> **“이 영역 자체가 웹이나 앱에서 실제 UI로 구현되어야 하는가?”**

그렇다면 **Frame**입니다.

예:

```text
로그인 화면       → Frame
상품 카드         → Frame
Header            → Frame
Sidebar           → Frame
Navigation        → Frame
Modal             → Frame
Button            → Frame 가능
```

반대로

> **“실제 UI가 아니라 여러 디자인을 정리하기 위한 영역인가?”**

라면 **Section**입니다.

예:

```text
회원 관련 화면       → Section
상품 관련 화면       → Section
결제 관련 화면       → Section
디자인 시안 A        → Section
개발 완료 화면       → Section
관리자 화면 모음      → Section
```

# 14. 웹 개발 관점에서는 이렇게 생각하면 가장 쉽습니다

```text
Figma

Section : 쇼핑몰 주문
│
├─ Frame : Cart
│
├─ Frame : Checkout
│
└─ Frame : Complete
```

이것을 실제 프로젝트 구조에 비유하면:

```text
shopping/
│
├─ cart.html
├─ checkout.html
└─ complete.html
```

와 유사합니다.

즉:

```text
Figma Section
≈ 프로젝트 폴더 / 기능 영역

Figma Frame
≈ 실제 웹 페이지 / UI Component
```

라고 설명하면 비전공자도 이해하기 쉽습니다.

## 수업에서 강조할 핵심 기준

학생들에게는 다음 세 문장만 확실히 기억시키는 것이 좋습니다.

> **1. 실제 화면이나 UI를 만들면 Frame을 사용한다.**
> **2. 여러 화면이나 작업 영역을 정리하려면 Section을 사용한다.**
> **3. HTML의 `<section>`은 Figma의 Section보다 오히려 Figma Frame에 가깝다.**

그래서 일반적인 웹 프로젝트의 Figma 구조는 다음처럼 설계하면 상당히 깔끔합니다.

```text
Page
│
├─ Section : 회원
│    ├─ Frame : 로그인
│    ├─ Frame : 회원가입
│    └─ Frame : 마이페이지
│
├─ Section : 상품
│    ├─ Frame : 상품 목록
│    └─ Frame : 상품 상세
│
└─ Section : 주문
     ├─ Frame : 장바구니
     ├─ Frame : 결제
     └─ Frame : 주문 완료
```

그리고 각각의 Frame 내부를 다시 **Header → Main → Card → Button처럼 Frame과 Auto Layout으로 세분화**하는 것이 Figma에서 HTML/CSS 구조로 넘어가기에 가장 자연스럽습니다. ([Figma 도움말 센터][3])
