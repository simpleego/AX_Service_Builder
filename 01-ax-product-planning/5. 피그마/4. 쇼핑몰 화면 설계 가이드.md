# 4. 쇼핑몰 화면 설계 가이드

- 쇼핑몰처럼 기능이 많은 서비스는 Figma에서 단순히 화면을 나열하기보다 **`Page → Section → Frame → Component` 계층**으로 설계하면 HTML/CSS/React 개발 단계까지 연결하기 좋습니다.
- Figma에서도 Page는 파일을 큰 단위로 조직하고, Section은 관련 Frame이나 사용자 흐름을 묶으며, Frame은 실제 화면이나 UI를 구성하는 컨테이너로 사용하는 방식이 자연스럽습니다. ([Figma 도움말 센터][1])

## 1. 쇼핑몰 전체 Figma 구조

저라면 다음 정도로 구성하는 것을 권합니다.

```text
쇼핑몰 Figma File
│
├─ Page 00. Overview
│    └─ 전체 서비스 구조 / User Flow
│
├─ Page 01. Design System
│    ├─ Section : Colors & Typography
│    ├─ Section : Buttons
│    ├─ Section : Inputs
│    ├─ Section : Cards
│    ├─ Section : Tables
│    ├─ Section : Modal
│    └─ Section : Navigation
│
├─ Page 02. Customer
│    ├─ Section : 회원
│    ├─ Section : 상품
│    ├─ Section : 장바구니
│    ├─ Section : 주문/결제
│    ├─ Section : 배송
│    └─ Section : 마이페이지
│
├─ Page 03. Admin
│    ├─ Section : 회원관리
│    ├─ Section : 상품관리
│    ├─ Section : 주문관리
│    ├─ Section : 배송관리
│    └─ Section : 대시보드
│
└─ Page 04. Prototype
     ├─ Section : 회원가입 Flow
     ├─ Section : 상품구매 Flow
     ├─ Section : 주문취소 Flow
     └─ Section : 배송/반품 Flow
```

이 구조에서 가장 중요한 것은 **고객 화면과 관리자 화면을 분리하는 것**입니다.

---

# 2. Design System을 먼저 만드는 것이 좋습니다

실무적으로는 회원관리 화면부터 바로 만드는 것보다 공통 UI를 먼저 Component로 만들어 두는 것이 좋습니다.

예를 들면:

```text
Page : Design System

Section : Button
    Component : Button
        ├─ Primary
        ├─ Secondary
        ├─ Danger
        └─ Disabled

Section : Input
    Component : Text Input
    Component : Password Input
    Component : Search Input
    Component : Select

Section : Status
    Component : Badge
        ├─ 정상
        ├─ 대기
        ├─ 완료
        ├─ 취소
        └─ 오류

Section : Table
    Component : Table Header
    Component : Table Row
    Component : Pagination

Section : Navigation
    Component : Header
    Component : Sidebar
    Component : Breadcrumb
```

Figma의 Component/Variant를 사용하면 같은 버튼을 상태와 크기별로 중복 제작하지 않고 관리할 수 있습니다. 예를 들어 `size=small/medium/large`, `state=default/hover/disabled`처럼 정의할 수 있습니다. ([Figma 도움말 센터][2])

이것은 나중에 React의

```jsx
<Button type="primary" size="medium">
    저장
</Button>
```

같은 구조와도 매우 잘 연결됩니다.

# 3. 회원관리 설계

관리자 화면의 회원관리 Section을 생각해 보겠습니다.

```text
Section : 회원관리

├─ Frame : 회원 목록
├─ Frame : 회원 상세
├─ Frame : 회원 수정
├─ Frame : 회원 상태 변경
└─ Frame : 회원 탈퇴/정지 확인 Modal
```

회원 목록 화면 내부는 다시 Frame으로 구성합니다.

```text
Frame : 회원 목록
│
├─ Frame : Header
│
├─ Frame : Sidebar
│
└─ Frame : Main
     │
     ├─ Frame : Page Title
     │
     ├─ Frame : Search Filter
     │    ├─ 검색어
     │    ├─ 회원상태
     │    └─ 가입일
     │
     ├─ Frame : Member Table
     │    ├─ 회원번호
     │    ├─ 이름
     │    ├─ 이메일
     │    ├─ 가입일
     │    ├─ 상태
     │    └─ 관리
     │
     └─ Frame : Pagination
```

실제 관리자 화면은 대략 다음과 같은 형태가 됩니다.

```text
┌───────────────────────────────────────────────┐
│ 쇼핑몰 관리자                         관리자 ▼ │
├──────────┬────────────────────────────────────┤
│ 대시보드 │ 회원 관리                          │
│ 회원관리 │                                    │
│ 상품관리 │ [검색_______] [상태▼] [검색]       │
│ 주문관리 │                                    │
│ 배송관리 │ ┌──────────────────────────────┐   │
│          │ │번호 이름 이메일 상태 관리    │   │
│          │ │001 김철수 ... 정상 [상세]    │   │
│          │ │002 이영희 ... 정지 [상세]    │   │
│          │ └──────────────────────────────┘   │
└──────────┴────────────────────────────────────┘
```

이때 검색창, Select, Button, Badge, Table Row 등은 새로 그리지 않고 **Design System의 Component Instance**를 가져와 사용하는 방식이 좋습니다.

# 4. 상품관리

상품관리에는 CRUD 화면이 핵심입니다.

```text
Section : 상품관리

├─ Frame : 상품 목록
├─ Frame : 상품 등록
├─ Frame : 상품 상세
├─ Frame : 상품 수정
├─ Frame : 재고 관리
└─ Frame : 상품 삭제 Modal
```

상품 목록은:

```text
상품명 검색

카테고리 ▼
판매상태 ▼
재고상태 ▼

─────────────────────────────────────────
이미지 │ 상품명 │ 가격 │ 재고 │ 상태 │ 관리
─────────────────────────────────────────
 👕    │ 셔츠   │39000 │ 25   │판매중│ 수정
 👟    │ 운동화 │89000 │  0   │품절  │ 수정
─────────────────────────────────────────
```

상품 등록 Frame에서는 다음과 같이 그룹화하는 것이 좋습니다.

```text
Frame : 상품 등록
│
├─ Frame : 기본정보
│    ├─ 상품명
│    ├─ 카테고리
│    ├─ 상품코드
│    └─ 설명
│
├─ Frame : 가격정보
│    ├─ 판매가격
│    ├─ 할인율
│    └─ 최종가격
│
├─ Frame : 재고정보
│    ├─ 재고수량
│    └─ 품절여부
│
├─ Frame : 이미지
│    └─ Image Upload
│
└─ Frame : Actions
     ├─ 취소
     └─ 상품등록
```

이렇게 만들어 놓으면 HTML에서도 자연스럽게:

```html
<form>
    <section class="basic-info"></section>
    <section class="price-info"></section>
    <section class="stock-info"></section>
    <section class="image-info"></section>
</form>
```

구조로 연결됩니다.

# 5. 주문관리는 특히 상태 중심으로 설계

쇼핑몰에서 가장 복잡한 부분이 주문관리입니다.

따라서 화면을 단순히 CRUD 중심으로 설계하기보다 **상태(State) 중심으로 설계하는 것이 좋습니다.**

```text
Section : 주문관리

├─ Frame : 전체 주문
├─ Frame : 결제대기
├─ Frame : 결제완료
├─ Frame : 상품준비중
├─ Frame : 배송준비
├─ Frame : 배송중
├─ Frame : 배송완료
├─ Frame : 주문취소
├─ Frame : 반품/교환
└─ Frame : 주문 상세
```

다만 실제로 화면 9개를 모두 별도로 만들 필요는 없습니다.

더 좋은 방법은:

```text
Frame : 주문 목록

상태 Filter

[전체]
[결제완료]
[상품준비]
[배송중]
[배송완료]
[취소]
```

처럼 하나의 화면에서 상태를 변경하도록 설계하는 것입니다.

그리고 `Order Status Badge`를 Component로 만듭니다.

```text
Component : OrderStatus

Variant

status = PAYMENT_WAIT
status = PAID
status = PREPARING
status = SHIPPING
status = DELIVERED
status = CANCELLED
status = RETURNED
```

이 방식은 Figma의 Variant가 상태·크기·스타일 등의 예측 가능한 차이를 하나의 Component Set으로 관리하도록 설계된 방식과도 잘 맞습니다. ([Figma 도움말 센터][3])

# 6. 배송관리

배송관리는 주문관리와 연결되지만 별도의 Section으로 분리하는 것이 좋습니다.

```text
Section : 배송관리

├─ Frame : 배송대기 목록
├─ Frame : 배송등록
├─ Frame : 배송중 목록
├─ Frame : 배송완료 목록
├─ Frame : 배송 상세
└─ Frame : 배송조회 Modal
```

배송 상세에서는 상태 흐름을 시각화하면 좋습니다.

```text
주문완료
   ↓
상품준비
   ↓
배송준비
   ↓
택배사 인계
   ↓
배송중
   ↓
배송완료
```

Figma에서는 이것을 Stepper Component로 만들 수 있습니다.

```text
Component : Delivery Step

○ 주문완료
│
● 배송준비
│
○ 배송중
│
○ 배송완료
```

그리고 Variant를:

```text
currentStep = order
currentStep = preparing
currentStep = shipping
currentStep = delivered
```

처럼 구성합니다.

# 7. 고객 화면은 관리자 화면과 별도로 구성

같은 회원·상품·주문이라도 사용자 입장에서는 화면 구조가 완전히 다릅니다.

```text
Page : Customer

Section : 회원
├─ Frame : 로그인
├─ Frame : 회원가입
├─ Frame : 비밀번호 찾기
└─ Frame : 개인정보 수정


Section : 상품
├─ Frame : 메인
├─ Frame : 상품 목록
├─ Frame : 검색 결과
└─ Frame : 상품 상세


Section : 주문
├─ Frame : 장바구니
├─ Frame : 주문서
├─ Frame : 결제
└─ Frame : 주문완료


Section : 마이페이지
├─ Frame : 주문내역
├─ Frame : 주문상세
├─ Frame : 배송조회
├─ Frame : 주문취소
└─ Frame : 반품/교환
```

이것이 관리자 화면과 중요한 차이입니다.

관리자는:

```text
목록 → 검색 → 상세 → 수정 → 상태변경
```

중심이고,

고객은:

```text
검색 → 상품선택 → 장바구니
        ↓
      주문 → 결제 → 배송조회
```

라는 **사용자 흐름(User Flow)** 중심입니다.

Figma에서도 e-commerce 프로토타입에서 `Browse`, `Cart`, `Checkout`처럼 동일한 사용자 흐름에 속하는 Frame을 Section으로 묶는 방식을 권장합니다. ([Figma 도움말 센터][4])

# 8. Prototype Page에서는 업무 흐름을 검증

별도의 Prototype Page를 만들어 다음처럼 연결하는 것도 좋습니다.

```text
Section : 상품구매 Flow


[상품목록]
     │
     ▼
[상품상세]
     │
     ▼
[장바구니]
     │
     ▼
[주문서]
     │
     ▼
[결제]
     │
     ▼
[주문완료]
     │
     ▼
[배송조회]
```

이렇게 해놓으면 학생들에게도 매우 좋은 교육 자료가 됩니다.

단순히

> "예쁜 화면을 만들었다."

에서 끝나지 않고

> "사용자가 어떤 순서로 화면을 이용하는가?"

까지 검증할 수 있기 때문입니다.

# 9. Figma와 HTML/CSS까지 연결하면

앞에서 다룬 내용을 쇼핑몰 구조에 적용하면 다음과 같습니다.

| Figma       | 쇼핑몰 예    | HTML/CSS               |
| ----------- | -------- | ---------------------- |
| Page        | Admin    | 프로젝트/화면군               |
| Section     | 주문관리     | 기능 영역                  |
| Frame       | 주문목록 화면  | 페이지                    |
| Frame       | 검색 영역    | `<section>`, `<div>`   |
| Frame       | 주문 테이블   | `<section>`, `<table>` |
| Component   | Button   | `<button>` + CSS       |
| Component   | Input    | `<input>` + CSS        |
| Component   | Badge    | `<span>` + CSS         |
| Auto Layout | 검색폼 정렬   | Flex                   |
| Layout Grid | 상품 목록    | CSS Grid               |
| Variant     | 주문상태     | 클래스/상태값                |
| Prototype   | 주문→배송 흐름 | Link/JS/Router         |

여기서 특히 **Figma Section이 HTML `<section>`과 대응하지 않는다는 것**을 다시 확인할 수 있습니다.

# 10. 제가 추천하는 최종 구조

실제 AX/풀스택 교육용 쇼핑몰이라면 다음 구조가 가장 실용적입니다.

```text
Shopping Mall.fig
│
├─ 00_Overview
│     └─ 전체 Sitemap / User Flow
│
├─ 01_Design_System
│     ├─ Colors
│     ├─ Typography
│     ├─ Button
│     ├─ Input
│     ├─ Select
│     ├─ Badge
│     ├─ Card
│     ├─ Table
│     ├─ Modal
│     └─ Navigation
│
├─ 02_Customer
│     ├─ Section 회원
│     ├─ Section 상품
│     ├─ Section 장바구니
│     ├─ Section 주문/결제
│     └─ Section 마이페이지/배송
│
├─ 03_Admin
│     ├─ Section Dashboard
│     ├─ Section 회원관리
│     ├─ Section 상품관리
│     ├─ Section 주문관리
│     └─ Section 배송관리
│
└─ 04_Prototype
      ├─ 회원가입 Flow
      ├─ 상품구매 Flow
      ├─ 주문취소 Flow
      └─ 반품/배송 Flow
```

이 구조의 핵심은 **`Section = 업무 영역`, `Frame = 실제 화면`, `Component = 반복되는 UI`, `Variant = 상태 변화`, `Prototype = 업무 흐름`**으로 역할을 명확하게 나누는 것입니다.

특히 수업에서는 **회원관리 → 상품관리 → 주문관리 → 배송관리** 순서보다, 먼저 **Design System에서 Button/Input/Table/Badge/Modal을 Component로 만들고 → 각 관리 Section에서 Instance를 조립해 화면을 만드는 방식**으로 실습시키는 것이 좋습니다. 이렇게 하면 학생들이 나중에 HTML/CSS에서 재사용 클래스, Bootstrap Component, React Component를 배우는 과정까지 자연스럽게 연결할 수 있습니다. ([Figma 도움말 센터][5])
