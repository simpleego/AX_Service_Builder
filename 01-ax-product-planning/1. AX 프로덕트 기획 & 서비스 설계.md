아래와 같이 **72시간 = 8시간 × 9일**로 구성하면, 단순히 Figma 사용법을 배우는 과정이 아니라 **AI 서비스 아이디어 정의 → 사용자 문제 분석 → 기능 설계 → 사용자 흐름 → 와이어프레임 → 프로토타입 → 검증**까지 하나의 서비스 기획 사이클을 경험할 수 있습니다.

비전공자 중심 과정이라면 **이론 28시간 : 실습 44시간 정도**가 적절합니다. 특히 Figma 자체 기능보다 **“왜 이런 화면과 기능이 필요한가”를 먼저 판단하는 능력**에 비중을 두는 것이 좋습니다.

# 2일차. 사용자 분석과 문제 정의 — 8시간

## 이론 3시간

 ├─ 연령
 ├─ 직업
 ├─ 목표
 ├─ 행동
 ├─ 불편함
 └─ 요구사항

### Pain Point

사용자가 서비스를 이용하면서 경험하는 구체적인 문제를 찾습니다.

예:

> 취업 준비생은 여러 취업 사이트에서 매일 새로운 공고를 직접 검색해야 한다.

이를 AI 서비스 문제로 변환하면:

> AI가 사용자 경력과 희망 직무를 분석하여 적합한 채용정보를 추천할 수 있을까?

## 실습 5시간

### Persona 작성

예:

```text
Persona

이름 : 김민준
나이 : 27세
상태 : 취업 준비생

목표
- AI 개발 직무 취업

문제
- 채용정보가 너무 많음
- 자신에게 적합한 공고를 판단하기 어려움

필요 기능
- AI 채용공고 추천
- 직무 적합도 분석
- 자기소개서 도움
```

### 문제정의문 작성

이렇게 구성하면 세부 내용인 **“AI 기반 서비스의 방향을 스스로 정의하고, Figma로 와이어프레임을 완성하는 방법을 습득한다”**와 정확히 연결되며, 이후 실제 웹/AI 서비스 개발 프로젝트의 **기획 단계 산출물**로도 그대로 활용할 수 있습니다.
