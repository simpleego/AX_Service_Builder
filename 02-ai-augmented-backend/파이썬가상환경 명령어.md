파이썬 기본 가상환경은 보통 표준 모듈인 **`venv`**를 사용합니다. Windows 11 + VS Code 환경 기준으로 먼저 정리하고, macOS/Linux 명령도 함께 보면 좋습니다.

### 1. 가장 많이 사용하는 기본 명령어

| 목적              | Windows                           | macOS / Linux              |
| --------------- | --------------------------------- | -------------------------- |
| Python 버전 확인    | `python --version`                | `python3 --version`        |
| 가상환경 생성         | `python -m venv venv`             | `python3 -m venv venv`     |
| 가상환경 활성화        | `venv\Scripts\activate`           | `source venv/bin/activate` |
| 가상환경 종료         | `deactivate`                      | `deactivate`               |
| 패키지 설치          | `pip install 패키지명`                | 동일                         |
| 설치 목록 확인        | `pip list`                        | 동일                         |
| 패키지 삭제          | `pip uninstall 패키지명`              | 동일                         |
| requirements 생성 | `pip freeze > requirements.txt`   | 동일                         |
| requirements 설치 | `pip install -r requirements.txt` | 동일                         |

가장 기본적인 흐름은 아래 정도만 기억해도 됩니다.

```bash
# 1. 프로젝트 폴더 생성
mkdir myproject
cd myproject

# 2. 가상환경 생성
python -m venv venv

# 3. 가상환경 활성화
venv\Scripts\activate

# 4. 필요한 패키지 설치
pip install fastapi uvicorn

# 5. 현재 설치된 패키지 확인
pip list

# 6. 설치 환경 저장
pip freeze > requirements.txt

# 7. 가상환경 종료
deactivate
```

가상환경이 활성화되면 보통 터미널 앞에 다음처럼 표시됩니다.

```text
(venv) C:\project\myproject>
```

즉, **`(venv)`가 나타나면 현재 가상환경 안에서 작업 중**이라고 이해하면 됩니다.

---

### 2. 가상환경 이름은 꼭 `venv`일 필요는 없음

다음은 모두 가능합니다.

```bash
python -m venv venv
```

```bash
python -m venv .venv
```

```bash
python -m venv myenv
```

최근에는 프로젝트 폴더 안에서 가상환경이라는 것을 쉽게 구별하기 위해 다음 이름도 많이 사용합니다.

```text
.venv
```

예:

```bash
python -m venv .venv
```

활성화:

```bash
.venv\Scripts\activate
```

프로젝트 구조는 다음처럼 됩니다.

```text
myproject/
├── .venv/
├── main.py
└── requirements.txt
```

`.venv` 폴더는 GitHub에 올릴 필요가 없기 때문에 `.gitignore`에 보통 다음을 추가합니다.

```text
.venv/
venv/
```

### 3. Windows에서 CMD와 PowerShell 활성화 명령 차이

**CMD**

```cmd
venv\Scripts\activate
```

또는

```cmd
venv\Scripts\activate.bat
```

**PowerShell**

```powershell
.\venv\Scripts\Activate.ps1
```

PowerShell에서 다음과 같은 오류가 발생할 수 있습니다.

```text
이 시스템에서 스크립트를 실행할 수 없으므로
Activate.ps1 파일을 로드할 수 없습니다.
```

이 경우 현재 사용자에 대해 실행 정책을 설정할 수 있습니다.

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

설정 확인:

```powershell
Get-ExecutionPolicy
```

### 4. 현재 어떤 Python을 사용하고 있는지 확인

가상환경 문제를 찾을 때 상당히 중요한 명령입니다.

Windows:

```cmd
where python
```

macOS/Linux:

```bash
which python
```

가상환경이 활성화되어 있다면 Windows에서는 대략 다음처럼 나와야 합니다.

```text
C:\project\myproject\venv\Scripts\python.exe
```

반대로 다음처럼 시스템 Python이 나오면 가상환경이 제대로 활성화되지 않은 것입니다.

```text
C:\Users\user\AppData\Local\Programs\Python\Python313\python.exe
```

pip 위치도 확인할 수 있습니다.

```cmd
where pip
```

### 5. `pip`보다 안전한 패키지 설치 방법

다음도 가능하지만:

```bash
pip install fastapi
```

여러 Python이 설치되어 있는 경우에는 다음 방식이 더 명확합니다.

```bash
python -m pip install fastapi
```

즉,

```text
현재 사용 중인 python으로 pip를 실행하라
```

라는 의미입니다.

따라서 수업에서는 다음처럼 설명해도 좋습니다.

```bash
python -m pip install fastapi
python -m pip install uvicorn
```

업데이트:

```bash
python -m pip install --upgrade pip
```

### 6. `requirements.txt` 사용법

현재 가상환경에 설치되어 있는 패키지를 저장합니다.

```bash
pip freeze > requirements.txt
```

예를 들어:

```text
fastapi==0.116.1
pydantic==2.11.7
uvicorn==0.35.0
```

다른 PC에서 프로젝트를 내려받았다면:

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

이렇게 하면 필요한 라이브러리를 다시 설치할 수 있습니다.

핵심은 **가상환경 자체를 복사하는 것이 아니라 `requirements.txt`를 이용하여 재생성**하는 것입니다.

---

### 7. 가상환경을 삭제하는 방법

별도의 Python 명령이 필요 없습니다.

가상환경은 그냥 폴더이므로 활성화를 해제한 뒤 폴더를 삭제하면 됩니다.

```bash
deactivate
```

Windows:

```cmd
rmdir /s /q venv
```

또는 탐색기에서 `venv` 폴더를 삭제해도 됩니다.

다시 만들려면:

```bash
python -m venv venv
```

### 8. VS Code에서 사용할 때

가상환경을 만든 다음 VS Code에서 Python 인터프리터를 지정합니다.

```text
Ctrl + Shift + P
```

입력:

```text
Python: Select Interpreter
```

그리고 다음과 비슷한 것을 선택합니다.

```text
Python 3.x.x ('.venv': venv)
```

실제로 선택되는 파일은 Windows 기준:

```text
프로젝트폴더\.venv\Scripts\python.exe
```

VS Code에서 새 터미널을 열면 대부분 자동으로:

```text
(.venv)
```

가 활성화됩니다.

### 수업용으로 최소한 이것만 기억하면 됩니다

```bash
# 생성
python -m venv .venv

# 활성화 - Windows
.venv\Scripts\activate

# 활성화 - macOS/Linux
source .venv/bin/activate

# 설치
python -m pip install 패키지명

# 설치 확인
pip list

# 패키지 목록 저장
pip freeze > requirements.txt

# 패키지 목록으로 설치
pip install -r requirements.txt

# 종료
deactivate
```

학생들에게는 **`가상환경 = 프로젝트마다 독립적인 Python + 라이브러리 공간`**이라고 설명하면 가장 이해하기 쉽습니다.

예를 들어 **A 프로젝트는 FastAPI 0.115, B 프로젝트는 FastAPI 0.120을 사용해도 서로 충돌하지 않게 만드는 것**이 가상환경의 핵심 목적입니다.
