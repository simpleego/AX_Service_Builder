# 예외처리
> **“오류를 없애는 기술”이 아니라 “오류가 발생해도 프로그램이 통제 가능한 상태로 동작하게 만드는 기술”** 

## 1. 예외처리가 왜 필요한가?

먼저 예외처리가 없는 코드를 보여주는 것이 좋습니다.

```python
num1 = int(input("첫 번째 숫자: "))
num2 = int(input("두 번째 숫자: "))

result = num1 / num2

print("결과:", result)
print("프로그램 종료")
```

정상 입력:

```text
첫 번째 숫자: 10
두 번째 숫자: 2
결과: 5.0
프로그램 종료
```

하지만 사용자가 다음과 같이 입력하면 문제가 발생합니다.

```text
첫 번째 숫자: 10
두 번째 숫자: 0
```

결과:

```text
ZeroDivisionError: division by zero
```

프로그램 자체가 중단됩니다.

또는

```text
첫 번째 숫자: hello
```

를 입력하면:

```text
ValueError: invalid literal for int()
```

가 발생합니다.

즉 실제 프로그램에서는 개발자가 예상하지 못한 입력이나 환경 문제가 언제든 발생할 수 있습니다.

예를 들어:

- 사용자가 숫자 대신 문자를 입력
- 0으로 나눗셈
- 파일이 존재하지 않음
- 인터넷 연결 실패
- DB 서버 연결 실패
- API 서버 응답 실패
- 권한 부족
- JSON 데이터 형식 오류

이런 상황에서 프로그램을 그냥 종료시키지 않고 **문제를 감지하고 적절하게 대응하기 위해 예외처리가 필요합니다.**

---

# 2. 기본적인 예외처리

Python 예외처리의 기본 구조는 다음과 같습니다.

```python
try:
    문제가 발생할 수 있는 코드

except:
    문제가 발생했을 때 실행할 코드
```

가장 간단한 예:

```python
try:
    num = int(input("숫자를 입력하세요: "))
    print("입력한 숫자:", num)

except:
    print("숫자를 입력해야 합니다.")
```

실행:

```text
숫자를 입력하세요: abc
숫자를 입력해야 합니다.
```

프로그램이 비정상 종료되지 않습니다.

---

# 3. 특정 예외를 처리하는 것이 중요하다

실무에서는 다음과 같은 코드는 권장하지 않습니다.

```python
try:
    num = int(input("숫자: "))
except:
    print("오류 발생")
```

왜냐하면 어떤 오류가 발생했는지 알 수 없기 때문입니다.

가능하면 **예외 종류를 명확하게 지정**합니다.

```python
try:
    num = int(input("숫자를 입력하세요: "))

except ValueError:
    print("숫자 형식이 아닙니다.")
```

여기에서 `ValueError`는 값의 변환이 불가능할 때 발생합니다.

---

# 4. 여러 종류의 예외 처리

다음 코드가 학생들에게 가장 좋은 기본 예제입니다.

```python
try:
    num1 = int(input("첫 번째 숫자: "))
    num2 = int(input("두 번째 숫자: "))

    result = num1 / num2

    print("결과:", result)

except ValueError:
    print("숫자만 입력해주세요.")

except ZeroDivisionError:
    print("0으로 나눌 수 없습니다.")
```

실행 예:

```text
첫 번째 숫자: 10
두 번째 숫자: abc
숫자만 입력해주세요.
```

또는

```text
첫 번째 숫자: 10
두 번째 숫자: 0
0으로 나눌 수 없습니다.
```

이 예제가 중요한 이유는 학생들이 다음 구조를 이해할 수 있기 때문입니다.

```text
문제 발생
   ↓
예외 종류 확인
   ↓
적절한 except 실행
```

---

# 5. `else`

예외가 발생하지 않았을 때 실행할 코드를 `else`에 작성할 수도 있습니다.

```python
try:
    num1 = int(input("첫 번째 숫자: "))
    num2 = int(input("두 번째 숫자: "))

    result = num1 / num2

except ValueError:
    print("숫자를 입력하세요.")

except ZeroDivisionError:
    print("0으로 나눌 수 없습니다.")

else:
    print("계산 성공")
    print("결과:", result)
```

구조는 다음과 같습니다.

```text
try 성공
   ↓
else 실행

try 실패
   ↓
except 실행
```

---

# 6. `finally`

`finally`는 예외 발생 여부에 관계없이 실행됩니다.

```python
try:
    num = int(input("숫자: "))
    print(100 / num)

except ValueError:
    print("숫자를 입력해야 합니다.")

except ZeroDivisionError:
    print("0은 사용할 수 없습니다.")

finally:
    print("프로그램 종료")
```

정상 입력:

```text
숫자: 10
10.0
프로그램 종료
```

예외 발생:

```text
숫자: abc
숫자를 입력해야 합니다.
프로그램 종료
```

`finally`는 특히 다음과 같은 자원을 정리할 때 사용합니다.

```text
파일 닫기
DB 연결 종료
네트워크 연결 종료
잠금 해제
임시파일 삭제
```

---

# 7. 기본 예외처리 전체 구조

학생들에게 다음 형태를 기억시키면 좋습니다.

```python
try:
    # 문제가 발생할 가능성이 있는 코드

except ValueError:
    # ValueError 처리

except ZeroDivisionError:
    # ZeroDivisionError 처리

else:
    # 오류가 없는 경우

finally:
    # 무조건 실행
```

단, `else`, `finally`는 반드시 사용할 필요는 없습니다.

# 8. 예외 객체를 확인하기

실무에서는 실제 오류 메시지가 필요한 경우가 많습니다.

```python
try:
    num = int(input("숫자 입력: "))

except ValueError as e:
    print("오류가 발생했습니다.")
    print(e)
```

예:

```text
숫자 입력: hello

오류가 발생했습니다.
invalid literal for int() with base 10: 'hello'
```

여기서

```python
except ValueError as e:
```

의 `e`는 발생한 예외 객체입니다.

# 9. 파일 처리 예외

학생들이 실무적인 필요성을 이해하기 좋은 예입니다.

예외처리 없는 코드:

```python
f = open("student.txt", "r")

data = f.read()

print(data)

f.close()
```

파일이 없으면:

```text
FileNotFoundError
```

프로그램이 종료됩니다.

예외처리를 적용하면:

```python
try:
    f = open("student.txt", "r", encoding="utf-8")

    data = f.read()

    print(data)

except FileNotFoundError:
    print("student.txt 파일이 존재하지 않습니다.")
```

---

# 10. `with`와 예외처리를 함께 사용하기

실무에서는 파일 처리 시 다음 방식이 더 좋습니다.

```python
try:
    with open("student.txt", "r", encoding="utf-8") as f:
        data = f.read()

    print(data)

except FileNotFoundError:
    print("파일을 찾을 수 없습니다.")

except PermissionError:
    print("파일 접근 권한이 없습니다.")
```

`with`를 사용하면 파일을 직접 닫지 않아도 자동으로 닫힙니다.

---

# 11. 기본 단계와 실무 단계의 차이

학생들에게는 다음과 같이 구분하면 명확합니다.

| 구분 | 기본 학습 | 실무 수준 |
|---|---|---|
| 목적 | 예외 문법 이해 | 서비스 안정성 |
| except | 단순 처리 | 예외별 구분 |
| 메시지 | print | 로그 기록 |
| 오류 전달 | 거의 없음 | 상위 계층으로 전달 |
| 사용자 메시지 | 개발자 오류 노출 가능 | 사용자용 메시지 분리 |
| 자원관리 | 단순 | 파일·DB·네트워크 정리 |
| 사용자 정의 예외 | 거의 사용 안 함 | 적극 사용 |
| 로깅 | 사용 안 함 | 필수에 가까움 |

# 12. 실무 수준 ① `except Exception`

실무에서 가끔 다음 패턴을 사용합니다.

```python
try:
    num = int(input("숫자: "))
    result = 100 / num

except ValueError:
    print("숫자를 입력해주세요.")

except ZeroDivisionError:
    print("0으로 나눌 수 없습니다.")

except Exception as e:
    print("예상하지 못한 오류가 발생했습니다.")
    print(e)
```

여기서 중요한 것은 순서입니다.

```python
except ValueError:
except ZeroDivisionError:
except Exception:
```

구체적인 예외를 먼저 작성하고 가장 넓은 예외인 `Exception`은 마지막에 작성합니다.

# 13. 실무 수준 ② 오류를 숨기지 않는다

다음 코드는 좋지 않습니다.

```python
try:
    result = 10 / 0

except:
    pass
```

오류가 발생했는데 아무것도 하지 않습니다.

개발자는 오류가 발생했는지 알 수도 없습니다.

더 위험한 예:

```python
try:
    save_data()

except:
    pass

print("저장 성공")
```

실제로 저장에 실패했는데 화면에는

```text
저장 성공
```

이 표시될 수 있습니다.

따라서 **예외를 무시하는 것은 매우 위험합니다.**

# 14. 실무 수준 ③ 로그 남기기

실제 프로그램에서는 `print()`보다 `logging`을 사용합니다.

```python
import logging

logging.basicConfig(level=logging.INFO)

try:
    num = int(input("숫자: "))
    result = 100 / num

except ValueError as e:
    logging.error("숫자 변환 오류: %s", e)

except ZeroDivisionError as e:
    logging.error("0으로 나누기 오류: %s", e)
```

실행 결과:

```text
ERROR:root:숫자 변환 오류: invalid literal for int() with base 10: 'abc'
```

실제 서버에서는 이런 로그를 파일이나 로그 서버에 저장합니다.

# 15. 사용자 메시지와 개발자 로그는 다르게 한다

이 부분은 실무 교육에서 특히 중요합니다.

좋지 않은 방법:

```python
except Exception as e:
    print(e)
```

사용자에게 다음과 같은 내부 정보가 그대로 노출될 수 있습니다.

```text
ConnectionError...
database server 192.168...
password authentication failed...
```

실무에서는 보통 이렇게 합니다.

```python
import logging

try:
    result = 10 / 0

except Exception as e:

    logging.exception("계산 처리 중 오류 발생")

    print("처리 중 문제가 발생했습니다.")
```

사용자:

```text
처리 중 문제가 발생했습니다.
```

개발자 로그:

```text
ZeroDivisionError: division by zero
```

즉,

```text
사용자 메시지
≠
개발자 오류 정보
```

입니다.

# 16. 실무 수준 ④ 함수 단위 예외처리

예를 들어 학생 정보를 저장한다고 가정해보겠습니다.

```python
def save_student(name, score):

    if not name:
        raise ValueError("학생 이름이 없습니다.")

    if score < 0 or score > 100:
        raise ValueError("점수는 0~100 사이여야 합니다.")

    print("학생 저장 완료")
```

호출:

```python
try:
    save_student("홍길동", 120)

except ValueError as e:
    print("입력 오류:", e)
```

결과:

```text
입력 오류: 점수는 0~100 사이여야 합니다.
```

여기서는 개발자가 직접 예외를 발생시켰습니다.

```python
raise ValueError(...)
```

# 17. `raise`가 중요한 이유

예외는 단순히 Python이 만들어내는 것만 있는 것이 아닙니다.

프로그램의 업무 규칙을 위반했을 때 개발자가 직접 예외를 발생시킬 수 있습니다.

쇼핑몰 예를 들어보겠습니다.

```python
def order_product(stock, order_count):

    if order_count <= 0:
        raise ValueError("주문 수량은 1개 이상이어야 합니다.")

    if order_count > stock:
        raise ValueError("재고가 부족합니다.")

    return stock - order_count
```

사용:

```python
try:
    remain_stock = order_product(5, 10)

except ValueError as e:
    print("주문 실패:", e)
```

결과:

```text
주문 실패: 재고가 부족합니다.
```

이것이 실무 예외처리의 중요한 개념입니다.

```text
기술적인 오류
+
업무 규칙 위반
```

둘 다 예외가 될 수 있습니다.

# 18. 실무 수준 ⑤ 사용자 정의 예외

실무에서는 의미를 명확하게 하기 위해 사용자 정의 예외를 만들기도 합니다.

```python
class OutOfStockError(Exception):
    pass
```

사용:

```python
class OutOfStockError(Exception):
    pass


def order_product(stock, order_count):

    if order_count > stock:
        raise OutOfStockError("상품 재고가 부족합니다.")

    return stock - order_count
```

호출:

```python
try:
    remain = order_product(3, 5)

except OutOfStockError as e:
    print("주문 실패:", e)
```

이렇게 하면

```python
ValueError
```

보다

```python
OutOfStockError
```

가 훨씬 업무적으로 명확합니다.

# 19. 실무 수준 ⑥ 여러 계층에서 예외를 처리하는 방법

실무 프로그램은 보통 다음과 같은 구조를 가집니다.

```text
사용자
 ↓
API
 ↓
Service
 ↓
Database
```

예를 들어:

```python
def find_student(student_id):

    if student_id != 1:
        raise ValueError("학생이 존재하지 않습니다.")

    return {
        "id": 1,
        "name": "홍길동"
    }
```

상위 코드:

```python
try:
    student = find_student(10)

    print(student)

except ValueError as e:
    print("조회 실패:", e)
```

실무에서는 하위 함수가 문제를 발견하고

```python
raise
```

하고 상위 계층이 사용자에게 어떻게 보여줄지 결정하는 경우가 많습니다.

# 20. 예외를 다시 발생시키기

다음 패턴도 실무에서 많이 사용됩니다.

```python
def divide(a, b):

    try:
        return a / b

    except ZeroDivisionError:
        print("divide 함수에서 오류 확인")

        raise
```

호출:

```python
try:
    divide(10, 0)

except ZeroDivisionError:
    print("메인 프로그램에서 최종 처리")
```

결과:

```text
divide 함수에서 오류 확인
메인 프로그램에서 최종 처리
```

즉,

```text
오류 감지
 ↓
로그 기록
 ↓
다시 전달
 ↓
상위 계층 처리
```

구조를 만들 수 있습니다.

# 21. 실무적인 예: 학생 성적관리 프로그램

학생들이 이미 파일 입출력과 성적관리를 학습했다면 다음 예제가 상당히 좋습니다.

```python
def input_score():

    try:
        score = int(input("점수를 입력하세요: "))

        if score < 0 or score > 100:
            raise ValueError("점수는 0~100 사이여야 합니다.")

        return score

    except ValueError as e:
        print("입력 오류:", e)
        return None
```

사용:

```python
score = input_score()

if score is not None:
    print("입력된 점수:", score)
```

하지만 이것도 아직 기초적인 수준입니다.

조금 더 실무적으로 바꾸면:

```python
class ScoreError(Exception):
    pass


def validate_score(score):

    if score < 0 or score > 100:
        raise ScoreError(
            "점수는 0~100 사이여야 합니다."
        )


def input_score():

    text = input("점수를 입력하세요: ")

    try:
        score = int(text)

    except ValueError:
        raise ScoreError(
            "점수는 숫자로 입력해야 합니다."
        )

    validate_score(score)

    return score
```

메인 프로그램:

```python
try:
    score = input_score()

    print("입력 완료:", score)

except ScoreError as e:
    print("점수 입력 실패:", e)
```

이제 역할이 분리되었습니다.

```text
input_score()
    입력

    검증

ScoreError
    성적 관련 예외

main
    사용자 대응
```

이런 구조가 실무에 훨씬 가깝습니다.

# 22. 실무적인 FastAPI 예외처리

FastAPI를 배우는 학생이라면 다음 예제가 매우 중요합니다.

```python
from fastapi import FastAPI, HTTPException

app = FastAPI()


students = {
    1: "홍길동",
    2: "이순신"
}


@app.get("/students/{student_id}")
def get_student(student_id: int):

    if student_id not in students:

        raise HTTPException(
            status_code=404,
            detail="학생을 찾을 수 없습니다."
        )

    return {
        "id": student_id,
        "name": students[student_id]
    }
```

요청:

```text
GET /students/10
```

응답:

```json
{
  "detail": "학생을 찾을 수 없습니다."
}
```

이 경우 예외는 단순히 프로그램 오류를 처리하는 것이 아니라

```text
Python Exception
→ HTTP 상태코드
```

로 변환됩니다.

# 23. FastAPI에서 실무적으로 구성하면

예를 들어 서비스 계층을 분리합니다.

```python
class StudentNotFoundError(Exception):
    pass
```

서비스:

```python
def find_student(student_id):

    students = {
        1: "홍길동",
        2: "이순신"
    }

    if student_id not in students:
        raise StudentNotFoundError(
            "학생을 찾을 수 없습니다."
        )

    return students[student_id]
```

API:

```python
from fastapi import FastAPI, HTTPException

app = FastAPI()


@app.get("/students/{student_id}")
def get_student(student_id: int):

    try:
        name = find_student(student_id)

        return {
            "id": student_id,
            "name": name
        }

    except StudentNotFoundError as e:

        raise HTTPException(
            status_code=404,
            detail=str(e)
        )
```

이 구조가 중요한 이유는

```text
Service 계층
    업무 처리

API 계층
    HTTP 처리
```

가 분리되기 때문입니다.

# 24. 실무에서는 어떤 예외를 잡아야 하는가?

원칙적으로는 **내가 처리할 수 있는 예외만 잡는 것이 좋습니다.**

좋은 코드:

```python
try:
    age = int(input("나이: "))

except ValueError:
    print("나이는 숫자로 입력하세요.")
```

좋지 않은 코드:

```python
try:
    age = int(input("나이: "))

except Exception:
    print("뭔가 오류 발생")
```

더 안 좋은 코드:

```python
try:
    age = int(input("나이: "))

except:
    pass
```

예외를 무조건 잡는 것이 예외처리를 잘하는 것이 아닙니다.

# 25. 예외처리에서 학생들이 반드시 이해해야 할 핵심

저라면 학생들에게 다음 5가지를 강조하겠습니다.

1. **예외는 프로그램 실행 중 발생하는 문제다.**
2. **예외처리는 프로그램이 무조건 종료되는 것을 방지한다.**
3. **모든 오류를 `except`로 숨기면 안 된다.**
4. **처리할 수 있는 예외만 잡아야 한다.**
5. **실무에서는 로그를 남기고 사용자 메시지와 내부 오류를 분리한다.**

그리고 가장 중요한 한 문장을 다음과 같이 정리할 수 있습니다.

> **예외처리는 오류가 발생하지 않게 만드는 기술이 아니라, 오류가 발생했을 때 프로그램이 어떻게 행동할지를 설계하는 기술이다.**

# 26. 학생용 단계별 학습 순서

수업은 다음 순서로 진행하면 효과적입니다.

```text
1단계
오류 발생 프로그램 실행

        ↓

2단계
try-except

        ↓

3단계
여러 종류의 except

        ↓

4단계
else / finally

        ↓

5단계
Exception 객체

        ↓

6단계
raise

        ↓

7단계
사용자 정의 Exception

        ↓

8단계
logging

        ↓

9단계
함수 / Service 계층 예외처리

        ↓

10단계
FastAPI 예외처리
```

특히 **`try-except → raise → 사용자 정의 예외 → FastAPI HTTPException`**의 흐름까지 연결해서 설명하면 학생들이 예외처리를 단순한 파이썬 문법이 아니라 **서비스 안정성과 관련된 프로그래밍 설계 기술**로 이해하게 됩니다.
