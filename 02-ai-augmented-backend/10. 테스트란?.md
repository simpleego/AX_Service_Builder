<a id="1-테스트의-목적과-종류"></a>
### 1. 테스트의 목적과 종류

테스트는 **실제 결과가 요구사항에서 정한 예상 결과와 같은지 확인하는 코드**입니다.

예를 들어 성적 관리에서는 “화면에 평균이 표시되는가?”뿐 아니라, “90·80·70점을 입력하면 평균이 정확히 80인가?”까지 확인해야 합니다.

| 종류 | 확인 대상 | 과정에서의 예시 |
|---|---|---|
| 단위 테스트 | 함수 등 작은 기능 | 총점·평균·학점 계산 |
| 통합 테스트 | 여러 구성요소의 연결 | API로 등록한 회원이 DB에 저장되는지 |
| API 테스트 | HTTP 요청과 응답 | 상태 코드, JSON, 입력 검증 |
| E2E 테스트 | 사용자 전체 흐름 | 로그인 → 상품 선택 → 주문 완료 |
| 회귀 테스트 | 수정 후 기존 기능 | 로그인 수정 후 회원 조회도 정상인지 |

**API 테스트는 범위에 따라 단위 테스트 또는 통합 테스트가 될 수 있습니다.** 회귀 테스트는 기존 테스트를 다시 실행해 변경의 영향을 확인하는 용도입니다.

과정에서는 함수·API·DB 테스트를 먼저 다루고, 브라우저 E2E 테스트는 프로젝트 후반에 추가하면 좋습니다.

<a id="2-필요한-python-테스트-기능"></a>
### 2. 필요한 Python 테스트 기능

`pytest`는 테스트를 찾아 실행하고, 실패한 조건을 보여주는 도구입니다. 매개변수화와 fixture를 통해 여러 입력 및 공통 준비 작업도 처리할 수 있습니다. [pytest documentation](https://docs.pytest.org/en/stable/contents.html?utm_source=chatgpt.com)

| 우선순위 | 기능·도구 | 역할 | 적용 예 |
|---|---|---|---|
| 필수 | `assert` | 실제 결과와 예상 결과 비교 | 평균이 80인지 |
| 필수 | `pytest` | 테스트 자동 수집·실행 | 전체 기능 일괄 검사 |
| 필수 | `pytest.mark.parametrize` | 입력을 바꿔 같은 테스트 반복 | 학점 경계값 검사 |
| 필수 | `pytest.raises` | 예상한 예외가 발생하는지 확인 | 음수 금액 입력 |
| 필수 | `pytest.fixture` | 테스트 준비와 정리 재사용 | API 클라이언트 준비 |
| 필수 | `TestClient` | FastAPI 요청·응답 검사 | GET·POST·PUT·DELETE |
| 필수 | 테스트 DB·의존성 교체 | DB 연결을 테스트 환경으로 전환 | CRUD·제약조건 검사 |
| 필수 | `Mock`·`monkeypatch` | 외부 동작을 통제된 결과로 대체 | LLM 오류·타임아웃 |
| 권장 | `tmp_path` | 임시 파일·폴더 제공 | CSV 저장·파일 업로드 |
| 권장 | `caplog` | 로그 기록 확인 | 예외 발생 로그 |
| 권장 | `pytest.approx` | 소수점 결과의 허용 오차 비교 | 평균·통계 계산 |
| 권장 | `pytest-cov` | 실행된 코드 범위 측정 | 테스트 누락 확인 |
| 확장 | 비동기 테스트 | 비동기 함수를 직접 검사 | 비동기 DB·외부 호출 |
| 확장 | Playwright | 브라우저 사용자 동작 검사 | 로그인·주문 흐름 |

`unittest`는 Python 기본 테스트 도구이므로 개념을 소개하되, 실습은 `pytest`로 통일하는 구성을 권합니다. `unittest.mock`은 `pytest`에서도 사용할 수 있습니다.

# 테스트 무엇을 공부해야 하나?

**학생들이 공부해야 하는 내용은 다음과 같습니다.**

| 공부할 내용 | 학생이 판단해야 할 질문 | 위 함수에서의 적용 |
|---|---|---|
| **① 요구사항 파악** | 무엇이 올바른 동작인가? | 학점 기준에 D가 있는가? 평균은 반올림하는가? |
| **② 테스트 사례 설계** | 어떤 입력을 넣어야 오류를 찾는가? | 정상값·경계값·잘못된 값 |
| **③ 예상 결과 계산** | 결과가 얼마여야 하는가? | 90·80·70 → 총점 240, 평균 80, B |
| **④ 테스트 코드 읽기** | 이 코드는 무엇을 검증하는가? | `assert`, `parametrize`, `raises` |
| **⑤ 실패 원인 분석** | 구현이 틀렸나, 테스트가 틀렸나? | 계산식·학점 조건·예상값 확인 |
| **⑥ 테스트 범위 판단** | 아직 검증하지 않은 문제가 있는가? | 문자열·소수·누락값 입력 |

위 함수에서는 다음처럼 직접 테스트 사례를 정할 수 있어야 합니다.

| 입력 | 예상 결과 또는 확인 사항 | 선정 이유 |
|---|---|---|
| `90, 80, 70` | 총점 240, 평균 80, B | 일반적인 정상 입력 |
| `90, 90, 90` | A | A 기준점 |
| `89, 89, 89` | B | A 기준 바로 아래 |
| `100, 100, 100` | 총점 300, A | 허용 최댓값 |
| `0, 0, 0` | 총점 0, F | 허용 최솟값 |
| `-1, 80, 70` | `ValueError` | 허용 범위 아래 |
| `101, 80, 70` | `ValueError` | 허용 범위 위 |
| `"90", 80, 70` | 요구사항에 따라 처리 결정 | 숫자 문자열을 허용하는가? |
| `89.5, 90, 90` | 요구사항에 따라 처리 결정 | 소수 점수를 허용하는가? |

**마지막 두 사례는 먼저 정책을 정해야 합니다.** 현재 코드가 어떻게 동작하는지를 확인하는 것과, 서비스가 어떻게 동작해야 하는지를 정하는 것은 별개의 작업입니다.

Python 문법은 AI가 만든 테스트를 읽고 수정할 정도로 공부하면 됩니다.

```python
def test_calculate_scores():
    result = calculate_scores(90, 80, 70)  # 검사할 함수 실행

    assert result["total"] == 240         # 총점 검증
    assert result["average"] == 80        # 평균 검증
    assert result["grade"] == "B"         # 학점 검증
```

이 코드를 보고 학생이 설명할 수 있어야 합니다.

- 어떤 입력으로 함수를 실행했는가?
- 무엇을 정답으로 가정했는가?
- 무엇을 검증했고, 무엇은 검증하지 않았는가?
- 실패했다면 어디를 확인해야 하는가?

수업도 **사례 설계 → AI 코드 생성 → 실행 → 실패 분석 → 수정** 순서로 진행하면 좋습니다. 평가에서는 테스트 코드 작성량보다, **빠진 사례를 찾아내는지와 요구사항 오류를 발견하는지**에 비중을 두면 됩니다.

즉, 학생이 배워야 할 핵심은 **“AI에게 테스트를 만들게 하는 능력”과 “그 테스트가 제품의 정확성을 제대로 확인하는지 검토하는 능력”**입니다.


**테스트 입력은 다음 세 가지를 함께 준비해야 합니다.**

| 구분 | 성적 입력 예 | 확인 목적 |
|---|---|---|
| 정상값 | 80 | 일반적인 처리 |
| 경계값 | 0, 100, 학점 기준점 | 조건식의 범위 |
| 잘못된 값 | -1, 101, `"abc"` | 거부·예외 처리 |

`assert`는 테스트용 검증에 사용하고, 실제 서비스 입력 검증은 Pydantic이나 명시적인 조건·예외 처리로 구현합니다.

### 3. 함수 테스트 예제

기존 성적 관리 실습을 다음처럼 테스트할 수 있습니다.

**설치**

```powershell
python -m pip install pytest
```

**계산 함수: `scores.py`**

```python
def calculate_scores(korean, english, math):
    scores = [korean, english, math]

    if any(score < 0 or score > 100 for score in scores):
        raise ValueError("점수는 0~100이어야 합니다.")

    total = sum(scores)
    average = total / 3

    if average >= 90:
        grade = "A"
    elif average >= 80:
        grade = "B"
    elif average >= 70:
        grade = "C"
    else:
        grade = "F"

    return {
        "total": total,
        "average": average,
        "grade": grade,
    }
```

**테스트: `test_scores.py`**

```python
import pytest
from scores import calculate_scores


# 1. 정상 결과 검사
def test_calculate_scores():
    result = calculate_scores(90, 80, 70)

    assert result["total"] == 240
    assert result["average"] == 80
    assert result["grade"] == "B"


# 2. 학점 기준과 경계값 검사
@pytest.mark.parametrize(
    "score, expected_grade",
    [
        (100, "A"),
        (90, "A"),
        (89, "B"),
        (80, "B"),
        (79, "C"),
        (70, "C"),
        (69, "F"),
        (0, "F"),
    ],
)
def test_grade_boundary(score, expected_grade):
    result = calculate_scores(score, score, score)

    assert result["grade"] == expected_grade


# 3. 잘못된 입력의 예외 검사
@pytest.mark.parametrize("score", [-1, 101])
def test_invalid_score(score):
    with pytest.raises(ValueError, match="0~100"):
        calculate_scores(score, 80, 70)
```

각 테스트는 **준비 → 실행 → 검증** 순서로 작성합니다. 매개변수화는 하나의 검증을 여러 입력에 반복 적용하고, `pytest.raises`는 예외 발생을 검증합니다. [pytest documentation](https://www.pytest.org/en/latest/example/parametrize.html?utm_source=chatgpt.com)

**실행 명령**

```powershell
# 전체 테스트
python -m pytest

# 간결한 결과
python -m pytest -q

# 개별 테스트 이름까지 표시
python -m pytest -v

# 특정 파일만 실행
python -m pytest test_scores.py

# 이름에 grade가 포함된 테스트만 실행
python -m pytest -k grade
```

<a id="4-fastapi-테스트-예제"></a>
### 4. FastAPI 테스트 예제

FastAPI의 `TestClient`를 이용하면 별도로 Uvicorn 서버를 실행하지 않고 요청과 응답을 검사할 수 있습니다. [FastAPI](https://fastapi.tiangolo.com/tutorial/testing/?utm_source=chatgpt.com)

**설치**

```powershell
python -m pip install fastapi httpx pytest
```

**API: `main.py`**

```python
from fastapi import FastAPI
from pydantic import BaseModel, Field
from scores import calculate_scores

app = FastAPI()


class Scores(BaseModel):
    korean: int = Field(ge=0, le=100)
    english: int = Field(ge=0, le=100)
    math: int = Field(ge=0, le=100)


@app.post("/scores")
def create_scores(data: Scores):
    return calculate_scores(
        data.korean,
        data.english,
        data.math,
    )
```

**API 테스트: `test_api.py`**

```python
import pytest
from fastapi.testclient import TestClient
from main import app


@pytest.fixture
def client():
    with TestClient(app) as test_client:
        yield test_client


def test_create_scores(client):
    response = client.post(
        "/scores",
        json={"korean": 90, "english": 80, "math": 70},
    )

    assert response.status_code == 200
    assert response.json() == {
        "total": 240,
        "average": 80.0,
        "grade": "B",
    }


def test_out_of_range(client):
    response = client.post(
        "/scores",
        json={"korean": 101, "english": 80, "math": 70},
    )

    assert response.status_code == 422


def test_missing_field(client):
    response = client.post(
        "/scores",
        json={"korean": 90, "english": 80},
    )

    assert response.status_code == 422
```

여기에서는 다음을 구분해서 검사합니다.

| 검증 대상 | 검사 내용 |
|---|---|
| HTTP | 요청에 맞는 상태 코드인지 |
| 데이터 | 총점·평균·학점이 정확한지 |
| 입력 검증 | 범위 초과와 필수 항목 누락을 거부하는지 |

**상태 코드가 200이라는 사실만으로 기능이 정확하다고 판단하면 안 됩니다.** 응답 데이터도 함께 확인해야 합니다.

**DB 테스트**

테스트 전용 DB를 준비하고, 각 테스트 후 데이터를 정리해 서로 영향을 주지 않게 합니다. FastAPI에서는 `app.dependency_overrides`로 DB 의존성을 교체할 수 있으며, 테스트가 끝나면 교체 설정을 복구해야 합니다. [FastAPI](https://fastapi.tiangolo.com/advanced/testing-dependencies/?utm_source=chatgpt.com)

MariaDB·PostgreSQL을 사용하는 프로젝트라면 주요 통합 테스트도 같은 DB 엔진에서 수행해야 SQL 문법과 제약조건 차이를 확인할 수 있습니다.

**외부 AI 서비스 테스트**

두 가지로 나누면 효율적입니다.

| 구분 | 검증 방법 |
|---|---|
| 서비스 연결·오류 처리 | Mock으로 응답과 실패 상황을 고정 |
| 실제 AI 출력 품질 | 별도 평가 데이터로 정확성·관련성·근거 확인 |

LLM의 자연어 답변은 매번 달라질 수 있으므로, 실제 호출 테스트에서는 문장 전체 일치보다 **필수 항목·출력 구조·근거·업무 기준 충족 여부**를 검사하는 것이 적절합니다.

### 6. 학습 순서와 AI 활용

별도 테스트 수업으로는 **기초 8시간**, 프로젝트 연결까지는 **총 12시간** 구성을 권합니다.

AI 코딩 에이전트와 협업할 때에는 **사람이 요구사항과 예상 결과를 먼저 정하고, AI가 테스트 코드를 작성하게 하는 방식**이 중요합니다. 구현 코드만 보여주고 테스트를 만들게 하면, 잘못 구현된 동작을 정답으로 굳힐 수 있습니다.

예를 들어 다음처럼 요청합니다.

> 성적 계산 요구사항을 기준으로 pytest 테스트를 작성해줘. 정상값, 0·100 경계값, 학점 기준점 전후, 범위 초과를 포함해줘. 예상 결과는 요구사항에서 계산하고, 테스트가 실패하면 구현 오류인지 테스트 오류인지 구분해서 설명해줘.
