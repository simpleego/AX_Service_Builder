# 쓰레드란 ?
> 전체 흐름은 **“혼자 일하기 → 여러 명이 동시에 일하기 → 결과 받기 → 공유 자원 → 락 → ThreadPoolExecutor”** 순서입니다.

 # 🐍 파이썬 스레드 실습: 카페 직원들로 이해하기

 먼저 하나의 상황을 생각해봅시다.

 > ☕ 카페에 주문이 3개 들어왔습니다.\
>  주문 하나를 처리하는 데 2초가 걸립니다.

 직원이 한 명이라면 3개 주문을 순서대로 처리해야 합니다.

```
주문 A ── 2초 ──>
주문 B ── 2초 ──>
주문 C ── 2초 ──>

총 6초
```

 직원 3명이 동시에 처리한다면?

```
직원 1 ─ 주문 A ── 2초 ──>
직원 2 ─ 주문 B ── 2초 ──>
직원 3 ─ 주문 C ── 2초 ──>

총 약 2초
```

 이것이 \*\*스레드(thread)\*\*를 이해하는 가장 쉬운 출발점입니다.

---

 ## 1단계 — 스레드 없이 먼저 실행해보기

 먼저 일반적인 파이썬 코드입니다.

```
import time

def make_coffee(name):
    print(f"{name} 커피 만드는 중...")
    time.sleep(2)
    print(f"{name} 커피 완성!")

start = time.time()

make_coffee("아메리카노")
make_coffee("카페라떼")
make_coffee("카푸치노")

end = time.time()

print(f"걸린 시간: {end - start:.2f}초")
```

 실행해 보면 대략:

```
아메리카노 커피 만드는 중...
아메리카노 커피 완성!

카페라떼 커피 만드는 중...
카페라떼 커피 완성!

카푸치노 커피 만드는 중...
카푸치노 커피 완성!

걸린 시간: 6.00초
```

 ### 왜 6초일까요?

 `time.sleep(2)`가 끝나야 다음 함수로 넘어가기 때문입니다.

```
make_coffee("아메리카노")
        ↓
      2초 대기
        ↓
make_coffee("카페라떼")
        ↓
      2초 대기
        ↓
make_coffee("카푸치노")
        ↓
      2초 대기
```

 즉, **순차 실행**입니다.

---

 # 2단계 — 첫 번째 스레드 만들기

 이제 `threading`을 사용해봅니다.

```
import threading
import time

def make_coffee(name):
    print(f"{name} 커피 만드는 중...")
    time.sleep(2)
    print(f"{name} 커피 완성!")

thread = threading.Thread(
    target=make_coffee,
    args=("아메리카노",)
)

thread.start()

print("메인 프로그램도 일하는 중!")

thread.join()

print("모든 작업 완료!")
```

 여기서 중요한 것은 딱 3개입니다.

```
threading.Thread(...)
```

 → **스레드를 만든다.**

```
thread.start()
```

 → **스레드를 시작한다.**

```
thread.join()
```

 → **스레드가 끝날 때까지 기다린다.**

---

 # 3단계 — 스레드 3개를 동시에 실행하기

 이제 재미있는 부분입니다.

```
import threading
import time

def make_coffee(name):
    print(f"{name} 만드는 중...")
    time.sleep(2)
    print(f"{name} 완성!")

threads = []

for coffee in ["아메리카노", "카페라떼", "카푸치노"]:
    thread = threading.Thread(
        target=make_coffee,
        args=(coffee,)
    )

    threads.append(thread)
    thread.start()

for thread in threads:
    thread.join()

print("☕ 모든 커피 완성!")
```

 실행하면 순서가 조금씩 달라질 수 있습니다.

```
아메리카노 만드는 중...
카페라떼 만드는 중...
카푸치노 만드는 중...

아메리카노 완성!
카푸치노 완성!
카페라떼 완성!

☕ 모든 커피 완성!
```

 그리고 걸리는 시간은 대략 **2초**입니다.

---

 ## 여기서 가장 중요한 개념

 스레드를 만들었다고 해서 바로 실행되는 것이 아닙니다.

```
thread = threading.Thread(...)
```

 이건 **직원 고용**입니다.

```
thread.start()
```

 이건 **직원에게 일을 시키는 것**입니다.

```
thread.join()
```

 이건 **직원이 일을 끝낼 때까지 기다리는 것**입니다.

 따라서 다음과 같이 기억하면 쉽습니다.

```
Thread()
   ↓
직원 만들기

start()
   ↓
일 시키기

join()
   ↓
퇴근할 때까지 기다리기
```

 # 4단계 — 스레드의 실행 순서는 왜 뒤죽박죽일까?

 다음 코드를 실행해보세요.

```
import threading
import time

def work(name):
    for i in range(5):
        print(f"{name}: {i}")
        time.sleep(0.1)

t1 = threading.Thread(target=work, args=("👨‍🍳 직원 A",))
t2 = threading.Thread(target=work, args=("👩‍🍳 직원 B",))

t1.start()
t2.start()

t1.join()
t2.join()

print("끝!")
```

 결과가 이렇게 나올 수도 있습니다.

```
👨‍🍳 직원 A: 0
👩‍🍳 직원 B: 0
👨‍🍳 직원 A: 1
👩‍🍳 직원 B: 1
👩‍🍳 직원 B: 2
👨‍🍳 직원 A: 2
👨‍🍳 직원 A: 3
👩‍🍳 직원 B: 3
...
```

 또는 순서가 다르게 나올 수도 있습니다.

 이게 \*\*동시성(concurrency)\*\*의 핵심입니다.

 > 여러 작업이 서로 번갈아가며 실행될 수 있기 때문에 실행 순서를 우리가 정확하게 예측할 수 없습니다.

 # 5단계 — 스레드에게 값을 받아보기

 이번에는 스레드가 계산한 결과를 받아봅시다.

```
import threading

def calculate():
    print("계산 중...")
    return 10 + 20

result = None

def worker():
    global result
    result = calculate()

thread = threading.Thread(target=worker)

thread.start()
thread.join()

print("계산 결과:", result)
```

 결과:

```
계산 중...
계산 결과: 30
```

 하지만 `global`을 사용하는 방식은 여러 스레드가 데이터를 공유할 때 문제가 생기기 쉬워서 좋은 설계라고 하기는 어렵습니다.

 그래서 실무에서는 다음 단계에서 배우게 될 `queue`나 `concurrent.futures` 등을 자주 사용합니다.

---

 # 6단계 — 여러 스레드가 하나의 변수를 수정하면?

 여기서부터 진짜 재미있어집니다.

```
import threading

count = 0

def increase():
    global count

    for _ in range(100_000):
        count += 1

t1 = threading.Thread(target=increase)
t2 = threading.Thread(target=increase)

t1.start()
t2.start()

t1.join()
t2.join()

print("최종 값:", count)
```

 우리는 당연히

```
200000
```

 을 기대합니다.

 그런데 여기서 중요한 개념이 등장합니다.

 ## 🔒 Race Condition

 여러 스레드가 **같은 데이터를 동시에 변경**하면 실행 타이밍에 따라 문제가 발생할 수 있습니다.

 이를 \*\*경쟁 상태(Race Condition)\*\*라고 합니다.

 그래서 공유 데이터를 보호해야 할 때 사용하는 것이 바로 `Lock`입니다.

---

 # 7단계 — Lock으로 금고 잠그기 🔐

 은행 금고를 생각하면 쉽습니다.

```
직원 A ──┐
         ├── 🔐 금고
직원 B ──┘
```

 한 명이 금고를 사용하는 동안 다른 사람은 기다려야 합니다.

 파이썬에서는:

```
threading.Lock()
```

 을 사용할 수 있습니다.

```
import threading

count = 0
lock = threading.Lock()

def increase():
    global count

    for _ in range(100_000):
        with lock:
            count += 1

t1 = threading.Thread(target=increase)
t2 = threading.Thread(target=increase)

t1.start()
t2.start()

t1.join()
t2.join()

print("최종 값:", count)
```

 핵심은 이것입니다.

```
with lock:
    count += 1
```

 이 부분에서는 한 번에 하나의 스레드만 접근하도록 보호합니다.

 # 8단계 — ThreadPoolExecutor 사용하기 ⭐

 지금까지는 직접 `Thread`를 만들었습니다.

 그런데 실제 프로그램에서는 다음처럼 `Thread`를 직접 관리하는 것보다 `ThreadPoolExecutor`를 사용하는 경우가 많습니다.

```
from concurrent.futures import ThreadPoolExecutor
import time

def make_coffee(name):
    print(f"{name} 만드는 중...")
    time.sleep(2)
    return f"{name} 완성!"

with ThreadPoolExecutor(max_workers=3) as executor:

    futures = [
        executor.submit(make_coffee, coffee)
        for coffee in ["아메리카노", "카페라떼", "카푸치노"]
    ]

    for future in futures:
        print(future.result())
```

 여기서:

```
ThreadPoolExecutor(max_workers=3)
```

 는

 > 최대 3명의 직원을 준비해 둔다.

 라고 생각하면 됩니다.

 그리고:

```
executor.submit(...)
```

 은

 > 직원에게 일을 맡긴다.

 입니다.

 마지막으로:

```
future.result()
```

 은

 > 그 직원이 일을 끝내고 결과를 가져올 때까지 기다린다.

 라고 생각하면 쉽습니다.

 # 9단계 — 스레드가 특히 유용한 상황

 스레드는 모든 프로그램을 빠르게 만들어주는 만능 도구는 아닙니다.

 특히 다음과 같은 **I/O 작업**에서 유용합니다.

```
인터넷 요청
    ↓
서버 응답 기다림
    ↓
파일 읽기
    ↓
DB 응답 기다림
    ↓
다른 작업
```

 예를 들어:

```
import time
from concurrent.futures import ThreadPoolExecutor

def download(file):
    print(f"{file} 다운로드 시작")
    time.sleep(2)  # 네트워크 대기라고 가정
    print(f"{file} 다운로드 완료")

files = [
    "image1.jpg",
    "image2.jpg",
    "image3.jpg",
    "image4.jpg",
]

start = time.time()

with ThreadPoolExecutor(max_workers=4) as executor:
    executor.map(download, files)

print(f"걸린 시간: {time.time() - start:.2f}초")
```

 순차적으로 했다면 대략:

```
2초 × 4개 = 8초
```

 하지만 4개의 작업을 동시에 진행하면 대략:

```
약 2초
```

 가 됩니다.

 # 🎮 최종 미션

 지금까지 배운 것을 이용해서 **게임 다운로드 시뮬레이터**를 만들어보세요.

 조건은 다음과 같습니다.

```
게임 1 다운로드 → 3초
게임 2 다운로드 → 2초
게임 3 다운로드 → 4초
게임 4 다운로드 → 1초
```

 ### 미션 1

 스레드 없이 순서대로 다운로드하세요.

 ### 미션 2

 `threading.Thread`를 이용해서 동시에 다운로드하세요.

 ### 미션 3

 `ThreadPoolExecutor`를 이용해서 다시 만들어보세요.

 ### 미션 4

 각 다운로드가 끝날 때마다 다음처럼 출력되도록 만들어보세요.

```
🎮 게임 1 다운로드 시작
🎮 게임 2 다운로드 시작
🎮 게임 3 다운로드 시작
🎮 게임 4 다운로드 시작

✅ 게임 4 다운로드 완료
✅ 게임 2 다운로드 완료
✅ 게임 1 다운로드 완료
✅ 게임 3 다운로드 완료

🎉 모든 게임 다운로드 완료!
```

 여기까지 직접 만들어 보면 \*\*`Thread → start → join → 공유 데이터 → Lock → ThreadPoolExecutor`\*\*의 흐름이 상당히 자연스럽게 잡힙니다.

 특히 다음 단계에서는 **`queue.Queue`를 이용한 생산자-소비자 패턴**을 실습해보면 스레드가 실제 프로그램에서 어떻게 쓰이는지 훨씬 잘 이해할 수 있습니다.
