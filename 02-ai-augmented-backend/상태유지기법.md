FastAPI 수업에서는 상태유지를 처음부터 복잡하게 설명하기보다 **“상태를 어디에 저장하느냐”**를 기준으로 실습시키면 이해가 빠릅니다.

핵심 흐름은 다음 정도면 좋습니다.

```text
1. 서버 메모리 변수
2. Cookie
3. Session
4. JWT Token
5. Redis Session
```

아래 예제들은 모두 짧게 실습할 수 있습니다.

---

# 1. 가장 기초: 서버 변수에 상태 저장

먼저 상태가 무엇인지 이해시키기 좋은 예입니다.

```python
from fastapi import FastAPI

app = FastAPI()

count = 0


@app.get("/count")
def get_count():
    global count

    count += 1

    return {
        "방문횟수": count
    }
```

실행:

```bash
uvicorn main:app --reload
```

브라우저에서 여러 번 호출합니다.

```text
http://127.0.0.1:8000/count
```

결과:

```json
{
    "방문횟수": 1
}
```

다시 호출하면:

```json
{
    "방문횟수": 2
}
```

### 중요한 설명

```text
count
   ↓
FastAPI 서버 메모리에 저장
```

문제점도 바로 설명할 수 있습니다.

```text
서버 재시작 → 데이터 사라짐
사용자를 구분하지 못함
서버가 여러 대이면 상태 공유 안 됨
```

따라서 실제 서비스에서는 거의 이렇게 상태를 관리하지 않습니다.

# 2. Cookie로 상태 저장

Cookie는 **클라이언트 브라우저에 상태를 저장**합니다.

예를 들어 사용자의 이름을 저장해 보겠습니다.

```python
from fastapi import FastAPI, Response, Cookie

app = FastAPI()


@app.get("/login")
def login(response: Response):

    response.set_cookie(
        key="username",
        value="hong"
    )

    return {
        "message": "쿠키 저장 완료"
    }


@app.get("/mypage")
def mypage(username: str | None = Cookie(default=None)):

    return {
        "username": username
    }
```

먼저:

```text
/login
```

호출 후:

```text
/mypage
```

를 호출하면:

```json
{
    "username": "hong"
}
```

이 됩니다.

구조:

```text
Browser
 └─ Cookie
      username=hong
          ↓
        HTTP
          ↓
       FastAPI
```

# 3. Cookie를 직접 확인하는 실습

프론트엔드에서도 확인할 수 있습니다.

```html
<!DOCTYPE html>
<html>
<body>

<button onclick="login()">로그인</button>
<button onclick="mypage()">내 정보</button>

<p id="result"></p>

<script>

async function login() {

    const response = await fetch(
        "http://127.0.0.1:8000/login",
        {
            credentials: "include"
        }
    );

    const data = await response.json();

    document.getElementById("result").innerText =
        JSON.stringify(data);
}


async function mypage() {

    const response = await fetch(
        "http://127.0.0.1:8000/mypage",
        {
            credentials: "include"
        }
    );

    const data = await response.json();

    document.getElementById("result").innerText =
        JSON.stringify(data);
}

</script>

</body>
</html>
```

이때 학생들에게:

```text
credentials: "include"
```

가 쿠키 전송과 관련 있다는 것을 보여주면 좋습니다.

프론트엔드와 FastAPI가 다른 Origin이라면 CORS 설정도 필요합니다.

# 4. Session을 이용한 로그인 상태 유지

학생들이 웹의 상태유지를 이해하는 데 가장 좋은 실습입니다.

설치:

```bash
pip install itsdangerous
```

FastAPI의 기반인 Starlette의 `SessionMiddleware`를 사용할 수 있습니다.

```python
from fastapi import FastAPI, Request
from starlette.middleware.sessions import SessionMiddleware

app = FastAPI()


app.add_middleware(
    SessionMiddleware,
    secret_key="my-secret-key"
)


@app.get("/login")
def login(request: Request):

    request.session["username"] = "홍길동"

    return {
        "message": "로그인 성공"
    }


@app.get("/mypage")
def mypage(request: Request):

    username = request.session.get("username")

    if username is None:
        return {
            "message": "로그인이 필요합니다."
        }

    return {
        "username": username
    }


@app.get("/logout")
def logout(request: Request):

    request.session.clear()

    return {
        "message": "로그아웃"
    }
```

실습 순서:

```text
① /mypage

→ 로그인이 필요합니다.


② /login

→ 로그인 성공


③ /mypage

→ 홍길동


④ /logout


⑤ /mypage

→ 로그인이 필요합니다.
```

이 예제가 상태유지를 가르치기에 매우 좋습니다.

# 5. Session의 동작 구조

학생들에게 다음 그림으로 설명하면 됩니다.

```text
로그인

Browser
   ↓
/login
   ↓
FastAPI
   ↓
session["username"] = "홍길동"
   ↓
Session Cookie 생성
   ↓
Browser 저장
```

다음 요청:

```text
Browser

Session Cookie
     ↓
HTTP Request
     ↓
FastAPI
     ↓
request.session
     ↓
로그인 사용자 확인
```

주의할 점은 `SessionMiddleware`의 기본 세션은 **서버 DB 세션이 아니라 서명된 쿠키 기반**이라는 점입니다. 서명되어 변조를 탐지할 수 있지만 암호화된 비밀 저장소로 생각하면 안 됩니다.

# 6. 로그인 사용자마다 다른 상태 유지

조금 더 현실적인 예제입니다.

```python
from fastapi import FastAPI, Request
from starlette.middleware.sessions import SessionMiddleware

app = FastAPI()

app.add_middleware(
    SessionMiddleware,
    secret_key="secret"
)


users = {
    "hong": "1234",
    "kim": "5678"
}


@app.get("/login")
def login(
    request: Request,
    username: str,
    password: str
):

    if username not in users:
        return {
            "message": "사용자가 없습니다."
        }

    if users[username] != password:
        return {
            "message": "비밀번호 오류"
        }

    request.session["username"] = username

    return {
        "message": "로그인 성공"
    }


@app.get("/mypage")
def mypage(request: Request):

    username = request.session.get("username")

    if username is None:
        return {
            "message": "로그인이 필요합니다."
        }

    return {
        "로그인 사용자": username
    }
```

요청:

```text
/login?username=hong&password=1234
```

이후:

```text
/mypage
```

결과:

```json
{
    "로그인 사용자": "hong"
}
```

# 7. 최근 API 서비스에서 많이 사용하는 JWT

웹페이지 기반 서비스에서는 Session도 많이 사용하지만, API 중심 서비스에서는 JWT 같은 토큰 방식도 많이 사용합니다.

설치:

```bash
pip install pyjwt
```

간단한 실습:

```python
from fastapi import FastAPI, Header, HTTPException
import jwt
import datetime

app = FastAPI()

SECRET_KEY = "my-secret-key"


@app.get("/login")
def login():

    payload = {
        "username": "hong",
        "exp": datetime.datetime.now(
            datetime.timezone.utc
        ) + datetime.timedelta(minutes=30)
    }

    token = jwt.encode(
        payload,
        SECRET_KEY,
        algorithm="HS256"
    )

    return {
        "access_token": token
    }
```

로그인하면 서버에서 토큰을 반환합니다.

```json
{
    "access_token": "eyJhbGciOiJIUzI1Ni..."
}
```

# 8. JWT로 사용자 확인

클라이언트가 다음 요청부터 토큰을 보냅니다.

```text
Authorization: Bearer 토큰
```

FastAPI:

```python
@app.get("/mypage")
def mypage(
    authorization: str | None = Header(default=None)
):

    if authorization is None:
        raise HTTPException(
            status_code=401,
            detail="로그인이 필요합니다."
        )

    token = authorization.replace(
        "Bearer ",
        ""
    )

    try:

        payload = jwt.decode(
            token,
            SECRET_KEY,
            algorithms=["HS256"]
        )

    except jwt.InvalidTokenError:

        raise HTTPException(
            status_code=401,
            detail="잘못된 토큰입니다."
        )

    return {
        "username": payload["username"]
    }
```

# 9. JavaScript에서 JWT 전송

```html
<script>

let token = "";


async function login() {

    const response =
        await fetch(
            "http://127.0.0.1:8000/login"
        );

    const data =
        await response.json();

    token = data.access_token;
}


async function mypage() {

    const response =
        await fetch(
            "http://127.0.0.1:8000/mypage",
            {
                headers: {
                    "Authorization":
                        "Bearer " + token
                }
            }
        );

    const data =
        await response.json();

    console.log(data);
}

</script>
```

흐름:

```text
① 로그인

Client
  ↓
Server
  ↓
JWT 발급


② 이후 요청

Client
 JWT
  ↓
Authorization Header
  ↓
FastAPI
  ↓
JWT 검증
  ↓
사용자 확인
```

# 10. Cookie / Session / JWT 차이

수업에서는 이 비교표가 중요합니다.

| 방법 | 상태 저장 위치 | 특징 |
|---|---|---|
| Python 변수 | Server Memory | 학습용 |
| Cookie | Browser | 클라이언트 저장 |
| Session | 쿠키 또는 서버 세션 저장소 | 로그인 상태 관리에 편리 |
| JWT | Client | API 인증에 많이 사용 |
| Redis Session | Redis Server | 분산 서비스에 적합 |

---

# 11. 실무 수준: Redis Session

서버가 한 대라면:

```text
Client
 ↓
FastAPI
 ↓
Memory
```

도 가능해 보입니다.

하지만 서버가 여러 대라면:

```text
             ┌─ FastAPI 1
Client ──────┤
             ├─ FastAPI 2
             └─ FastAPI 3
```

각 서버의 메모리가 다릅니다.

그래서:

```text
             ┌─ FastAPI 1 ─┐
Client ──────┼─ FastAPI 2 ─┼→ Redis
             └─ FastAPI 3 ─┘
```

처럼 공통 상태 저장소를 사용할 수 있습니다.

Redis는 수강생들에게는 **Session 다음 단계** 정도로 소개하면 충분합니다.

# 12. 학생 실습은 이 3개만 해도 충분하다

첫 수업에서는 모든 것을 구현할 필요가 없습니다.

### 실습 1 — 서버 변수

```python
count = 0
```

목표:

> 서버도 값을 기억할 수 있다.

### 실습 2 — Session

```python
request.session["username"] = username
```

목표:

> 여러 HTTP 요청 사이에서 로그인 상태를 유지한다.

### 실습 3 — JWT

```text
로그인
 ↓
Token 발급
 ↓
Client 저장
 ↓
Authorization Header
 ↓
API 호출
```

목표:

> REST API에서 로그인 상태를 어떻게 유지하는지 이해한다.

# 13. 수업에서 반드시 짚어야 할 핵심

HTTP 자체는 기본적으로:

```text
Stateless
무상태
```

입니다.

예를 들어:

```text
요청 1
GET /login

요청 2
GET /mypage
```

HTTP 자체만 보면 두 요청이 같은 사용자가 보낸 것인지 알지 못합니다.

그래서 상태를 연결하는 장치가 필요합니다.

```text
                 HTTP
                  │
         원래는 Stateless
                  │
       ┌──────────┴─────────┐
       │                    │
     Cookie               Token
       │                    │
    Session                JWT
       │                    │
       └──── 사용자 식별 ────┘
```

수강생들에게는 **“상태를 유지한다 = 이전 요청의 사용자가 누구였고, 어떤 상태였는지를 다음 요청에서도 알아내는 것”**이라고 설명하면 가장 이해하기 쉽습니다.

교육 순서는 **서버 변수 → Cookie → Session → JWT → Redis**가 가장 자연스럽고, FastAPI 실무로 넘어갈 때는 **Session 방식과 JWT 기반 인증 방식의 차이**를 집중적으로 비교하면 좋습니다.
