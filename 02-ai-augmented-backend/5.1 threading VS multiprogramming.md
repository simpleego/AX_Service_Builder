## 1. 핵심 개념

`threading`과 `multiprocessing`은 여러 작업을 함께 진행할 때 사용하는 파이썬 표준 라이브러리입니다.

- `threading`: 하나의 프로세스 안에서 여러 스레드가 작업합니다.
- `multiprocessing`: 여러 프로세스를 만들어 작업을 나눕니다.

일반적으로 다음과 같이 선택합니다.

> 대기 시간이 많은 작업 → threading  
> 파이썬 계산이 많은 작업 → multiprocessing

### 프로세스와 스레드

**프로세스(Process)**는 실행 중인 프로그램의 단위입니다.

**스레드(Thread)**는 프로세스 안에서 작업을 수행하는 실행 흐름입니다.

식당에 비유하면 다음과 같습니다.

| 개념 | 식당 비유 |
|---|---|
| 프로세스 | 하나의 주방 |
| 스레드 | 주방에서 일하는 직원 |
| 메모리 | 주방에서 사용하는 식재료와 작업 공간 |
| threading | 한 주방에서 여러 직원이 함께 작업 |
| multiprocessing | 여러 주방에서 각각 작업 |

여러 스레드는 같은 주방의 재료를 함께 사용합니다. 여러 프로세스는 각자의 주방에서 재료를 관리합니다.

### 동시성과 병렬성

| 구분 | 의미 | 예시 |
|---|---|---|
| 동시성 | 여러 작업을 겹치는 시간 동안 진행 | A의 응답을 기다리는 동안 B의 요청 처리 |
| 병렬성 | 같은 순간에 여러 작업을 실제로 실행 | 여러 CPU 코어에서 각각 계산 |

### GIL이란?

GIL(Global Interpreter Lock)은 일반적인 CPython에서 한 프로세스 안의 여러 스레드가 파이썬 바이트코드를 동시에 실행하지 못하도록 하는 잠금 장치입니다.

따라서 순수 파이썬 계산을 여러 스레드로 나눠도 CPU 코어를 활용한 속도 향상이 제한됩니다.

반면 입출력을 기다리는 동안에는 다른 스레드가 실행될 수 있어, 대기 시간이 많은 작업에는 스레드가 유용합니다.

`multiprocessing`은 프로세스별로 파이썬 인터프리터를 사용하므로 이러한 GIL 제약을 피할 수 있습니다.

※ 이 문서는 GIL이 활성화된 일반적인 CPython을 기준으로 설명합니다. GIL을 비활성화한 free-threaded 빌드나 GIL을 해제하는 일부 외부 라이브러리는 특성이 다릅니다.

## 2. 두 모듈의 차이

| 비교 항목 | threading | multiprocessing |
|---|---|---|
| 실행 단위 | 스레드 | 프로세스 |
| 실행 구조 | 한 프로세스 안에서 여러 실행 흐름 | 여러 프로세스에서 작업 수행 |
| 메모리 | 같은 프로세스의 메모리 공유 | 기본적으로 서로 분리 |
| 생성 비용 | 상대적으로 작음 | 상대적으로 큼 |
| 메모리 사용량 | 상대적으로 적음 | 상대적으로 많음 |
| 순수 파이썬 계산 | GIL로 병렬 실행 제한 | 여러 CPU 코어 활용 가능 |
| 적합한 작업 | 네트워크 등 입출력 대기 | 대량 반복 계산 |
| 데이터 전달 | 공유 변수, queue.Queue 등 | multiprocessing.Queue, Pipe 등 |
| 주의할 점 | 공유 데이터 변경 시 동기화 | 프로세스 생성·데이터 전달 비용 |

두 모듈 모두 파이썬 표준 라이브러리이므로 별도 설치가 필요하지 않습니다.

```python
import threading
import multiprocessing
```

## 3. 대기 작업과 threading

### 상황

세 곳의 서버에서 데이터를 내려받습니다.

각 서버의 응답을 기다리는 데 2초가 걸린다고 가정합니다.

- 순차 실행: A가 끝나면 B, B가 끝나면 C를 처리합니다.
- 스레드 실행: A, B, C 요청을 시작하고 대기 시간이 겹치도록 합니다.

실제 네트워크 요청 대신 `time.sleep()`으로 대기 시간을 표현합니다.

### 예제 코드

파일명: `compare_wait.py`

```python
import threading
import time


def download(name):
    print(f"{name}: 요청 시작")

    # 서버 응답을 기다리는 상황을 흉내 냅니다.
    time.sleep(2)

    print(f"{name}: 다운로드 완료")


if __name__ == "__main__":
    names = ["서버 A", "서버 B", "서버 C"]

    # ① 순차 실행
    print("===== 순차 실행 =====")

    start = time.perf_counter()

    for name in names:
        download(name)

    elapsed = time.perf_counter() - start
    print(f"순차 실행 시간: {elapsed:.2f}초")

    # ② 스레드 실행
    print("\n===== 스레드 실행 =====")

    start = time.perf_counter()

    threads = [
        threading.Thread(
            target=download,
            args=(name,)
        )
        for name in names
    ]

    # 모든 스레드를 먼저 시작합니다.
    for thread in threads:
        thread.start()

    # 모든 스레드의 작업이 끝날 때까지 기다립니다.
    for thread in threads:
        thread.join()

    elapsed = time.perf_counter() - start
    print(f"스레드 실행 시간: {elapsed:.2f}초")
```

### 실행 방법

```bash
python compare_wait.py
```

### 예상 결과

| 실행 방식 | 작업 진행 | 예상 시간 |
|---|---|---:|
| 순차 실행 | A 완료 후 B 시작, B 완료 후 C 시작 | 약 6초 |
| 스레드 실행 | A·B·C의 대기 시간이 겹침 | 약 2초 |

실제 시간과 메시지 출력 순서는 실행 환경에 따라 달라집니다.

### 주요 코드 설명

| 코드 | 의미 |
|---|---|
| `Thread(...)` | 스레드 객체 생성 |
| `target=download` | 스레드에서 실행할 함수 지정 |
| `args=(name,)` | 함수에 전달할 인자 지정 |
| `start()` | 별도의 실행 흐름으로 작업 시작 |
| `join()` | 해당 작업이 끝날 때까지 현재 실행 흐름 대기 |

#### target에는 함수 자체를 전달합니다.

```python
# 올바른 사용
threading.Thread(target=download, args=("서버 A",))
```

다음처럼 작성하면 스레드가 시작되기 전에 함수가 호출됩니다.

```python
# 잘못된 사용
threading.Thread(target=download("서버 A"))
```

#### 인자가 하나인 튜플에는 쉼표가 필요합니다.

```python
args=("서버 A",)
```

#### start()와 join()의 반복문은 분리합니다.

```python
for thread in threads:
    thread.start()

for thread in threads:
    thread.join()
```

다음 코드는 한 작업이 끝나야 다음 작업을 시작하므로 작업들이 겹쳐 실행되지 않습니다.

```python
for thread in threads:
    thread.start()
    thread.join()
```

### 왜 빨라질까요?

스레드가 대기 자체를 짧게 만드는 것은 아닙니다.

A가 응답을 기다리는 동안 B와 C도 응답을 기다리도록 하여 전체 대기 시간을 겹치는 것입니다.

## 4. 계산 작업과 multiprocessing

### 상황

정수의 제곱을 반복해서 더하는 계산을 수행합니다.

```python
total += i * i
```

이 작업은 외부 응답을 기다리는 시간이 거의 없고 CPU가 계속 계산해야 합니다.

같은 계산을 네 번 수행하면서 다음 세 방식을 비교합니다.

1. 순차 실행
2. 스레드 네 개로 실행
3. 프로세스 네 개로 실행

### 예제 코드

파일명: `compare_cpu.py`

```python
import multiprocessing
import threading
import time


def calculate(n):
    total = 0

    for i in range(n):
        total += i * i

    return total


def run_workers(worker_class, count, n):
    workers = [
        worker_class(
            target=calculate,
            args=(n,)
        )
        for _ in range(count)
    ]

    # 모든 작업 시작
    for worker in workers:
        worker.start()

    # 모든 작업 완료 대기
    for worker in workers:
        worker.join()


if __name__ == "__main__":
    task_count = 4
    n = 10_000_000

    # ① 순차 실행
    start = time.perf_counter()

    for _ in range(task_count):
        calculate(n)

    elapsed = time.perf_counter() - start
    print(f"순차 실행: {elapsed:.2f}초")

    # ② 스레드 실행
    start = time.perf_counter()

    run_workers(
        threading.Thread,
        task_count,
        n
    )

    elapsed = time.perf_counter() - start
    print(f"스레드 실행: {elapsed:.2f}초")

    # ③ 프로세스 실행
    start = time.perf_counter()

    run_workers(
        multiprocessing.Process,
        task_count,
        n
    )

    elapsed = time.perf_counter() - start
    print(f"프로세스 실행: {elapsed:.2f}초")
```

### 실행 방법

VS Code에서 `.py` 파일로 저장한 후 터미널에서 실행합니다.

```bash
python compare_cpu.py
```

이 예제는 속도 비교용이므로 `calculate()`의 반환값을 수집하지 않습니다.

`Thread`나 `Process`의 `join()`은 작업 종료를 기다릴 뿐, 작업 함수의 반환값을 반환하지 않습니다.

### 결과 해석

| 실행 방식 | 예상 경향 | 이유 |
|---|---|---|
| 순차 실행 | 비교 기준 | 한 작업씩 계산 |
| 스레드 실행 | 순차와 비슷하거나 더 느릴 수 있음 | GIL 제약과 스레드 관리 비용 |
| 프로세스 실행 | 여러 코어에서 빨라질 수 있음 | 프로세스별로 계산 수행 |

프로세스가 항상 더 빠른 것은 아닙니다.

- 계산량이 적으면 프로세스 생성 비용이 더 클 수 있습니다.
- 사용할 수 있는 CPU 코어 수에 영향을 받습니다.
- 다른 프로그램의 CPU 사용량에도 영향을 받습니다.
- 프로세스 사이에 큰 데이터를 전달하면 통신 비용이 증가합니다.

### 왜 __main__ 조건이 필요할까요?

```python
if __name__ == "__main__":
```

이 조건은 해당 파일을 직접 실행했을 때만 내부 코드를 실행하도록 합니다.

Windows에서는 새 프로세스가 작업 함수를 가져오기 위해 파이썬 파일을 다시 불러옵니다.

프로세스 생성 코드가 보호되어 있지 않으면 새 프로세스가 다시 프로세스를 생성하려고 시도하여 오류가 발생할 수 있습니다.

따라서 다음 구조를 사용합니다.

```python
import multiprocessing


# 작업 함수는 파일 최상위에 정의합니다.
def work():
    print("작업 실행")


# 프로세스 시작 코드는 이 조건 안에 작성합니다.
if __name__ == "__main__":
    process = multiprocessing.Process(target=work)

    process.start()
    process.join()
```

멀티프로세싱 실습은 Jupyter나 Colab의 셀보다 `.py` 파일로 저장해서 실행하는 방식이 적합합니다.

## 5. 메모리 공유 차이

### 상황

빈 리스트를 작업 함수에 전달하고, 함수에서 `100`을 추가합니다.

- 스레드가 수정한 결과가 부모 실행 흐름에도 보일까요?
- 프로세스가 수정한 결과도 부모 프로세스에 보일까요?

### 예제 코드

파일명: `compare_memory.py`

```python
import multiprocessing
import threading


def add_score(scores):
    scores.append(100)


if __name__ == "__main__":
    # ① 스레드에 리스트 전달
    thread_scores = []

    thread = threading.Thread(
        target=add_score,
        args=(thread_scores,)
    )

    thread.start()
    thread.join()

    print("스레드 실행 후:", thread_scores)

    # ② 프로세스에 리스트 전달
    process_scores = []

    process = multiprocessing.Process(
        target=add_score,
        args=(process_scores,)
    )

    process.start()
    process.join()

    print("프로세스 실행 후:", process_scores)
```

### 출력 결과

```text
스레드 실행 후: [100]
프로세스 실행 후: []
```

### 결과 설명

| 실행 방식 | 설명 |
|---|---|
| 스레드 | 같은 리스트를 공유하므로 변경 결과가 보임 |
| 프로세스 | 자식 프로세스가 자신의 리스트를 수정하므로 부모 리스트는 그대로 유지 |

**일반 리스트나 전역변수는 여러 프로세스 사이에서 자동으로 공유되지 않습니다.**

프로세스끼리 데이터를 주고받으려면 `Queue`, `Pipe` 등의 통신 수단을 사용합니다.

공유 상태가 필요하면 `Value`, `Array`, `Manager` 등의 별도 기능을 사용할 수 있습니다.

## 6. 프로세스의 결과 전달

### 상황

자식 프로세스에서 계산한 합계를 부모 프로세스가 받아 출력합니다.

`multiprocessing.Queue`를 결과를 넣고 꺼내는 전달 상자로 사용합니다.

### 예제 코드

파일명: `process_queue.py`

```python
import multiprocessing


def calculate_sum(n, result_queue):
    total = sum(range(1, n + 1))

    # 계산 결과를 큐에 넣습니다.
    result_queue.put(total)


if __name__ == "__main__":
    result_queue = multiprocessing.Queue()

    process = multiprocessing.Process(
        target=calculate_sum,
        args=(100, result_queue)
    )

    process.start()

    # 자식 프로세스가 보낸 결과를 받습니다.
    # 결과가 아직 없으면 들어올 때까지 기다립니다.
    result = result_queue.get()

    process.join()

    print("1부터 100까지 합계:", result)

    result_queue.close()
    result_queue.join_thread()
```

### 출력 결과

```text
1부터 100까지 합계: 5050
```

### 주요 코드 설명

| 코드 | 의미 |
|---|---|
| `multiprocessing.Queue()` | 프로세스 사이에서 사용할 큐 생성 |
| `put(value)` | 큐에 데이터 넣기 |
| `get()` | 큐에서 데이터 꺼내기 |
| `join()` | 프로세스 종료 대기 |

이 예제는 자식 프로세스가 정상적으로 결과를 보내는 상황을 가정합니다. 실제 서비스에서는 작업 실패에 대비한 오류 처리와 결과 대기 시간 제한도 필요합니다.

## 7. 공유 데이터와 Lock

### 상황

두 스레드가 하나의 카운터를 각각 10,000번 증가시킵니다.

```python
count += 1
```

이 코드는 개념적으로 다음 과정으로 이루어집니다.

1. 기존 값 읽기
2. 1 더하기
3. 결과 저장하기

여러 스레드가 공유 데이터를 읽고 수정하는 작업이 겹치면 의도한 결과를 보장하기 어려울 수 있습니다.

이때 `Lock`으로 수정 구간을 보호합니다.

### 예제 코드

파일명: `thread_lock.py`

```python
import threading


count = 0
lock = threading.Lock()


def increase():
    global count

    for _ in range(10_000):
        # 한 번에 하나의 스레드만 실행합니다.
        with lock:
            count += 1


if __name__ == "__main__":
    threads = [
        threading.Thread(target=increase)
        for _ in range(2)
    ]

    for thread in threads:
        thread.start()

    for thread in threads:
        thread.join()

    print("최종 카운트:", count)
```

### 출력 결과

```text
최종 카운트: 20000
```

### Lock의 역할

`Lock`은 공용 창고의 열쇠와 비슷합니다.

- 한 직원이 열쇠를 가지고 창고를 사용하는 동안 다른 직원은 기다립니다.
- 사용을 마치면 열쇠를 반납합니다.
- 다음 직원이 열쇠를 받아 사용합니다.

```python
with lock:
    count += 1
```

`with` 구문은 잠금을 획득하고, 해당 구간을 벗어날 때 해제합니다.

GIL이 있다고 해서 여러 단계로 이루어진 공유 데이터 변경이 모두 안전해지는 것은 아닙니다.

또한 Lock 없이 실행해도 특정 환경에서는 우연히 원하는 결과가 나올 수 있습니다. 한 번의 실행 결과만으로 안전하다고 판단하면 안 됩니다.

## 8. 작업에 따른 선택 기준

| 작업 | 우선 고려할 방식 | 이유 |
|---|---|---|
| 여러 서버의 응답 기다리기 | threading | 대기 시간 활용 |
| 여러 파일 다운로드 | threading | 네트워크 대기 겹치기 |
| 순수 파이썬으로 대량 반복 계산 | multiprocessing | 여러 CPU 코어 활용 |
| 서로 독립적인 계산 작업 수행 | multiprocessing | 프로세스별 계산 분담 |
| 매우 짧고 단순한 작업 | 순차 실행 | 작업 생성·관리 비용 절약 |
| 외부 라이브러리의 연산 | 라이브러리 특성 확인 | GIL 해제 및 자체 병렬 처리 여부가 다름 |

### 기억할 핵심

1. `threading`은 한 프로세스 안에서 여러 작업을 진행합니다.
2. `multiprocessing`은 여러 프로세스로 작업을 분담합니다.
3. 스레드는 같은 메모리를 공유하므로 동기화에 주의합니다.
4. 프로세스의 일반 변수는 자동으로 공유되지 않습니다.
5. 입출력 대기는 스레드, 순수 파이썬 계산은 프로세스를 우선 고려합니다.
6. 작업이 작으면 순차 실행이 더 효율적일 수 있습니다.
7. 실제 성능은 실행 환경에서 측정하여 판단합니다.
