# 테스트 무엇을 공부해야 하나?

**학생들이 공부해야 하는 내용은 다음과 같습니다.**

| 공부할 내용 | 학생이 판단해야 할 질문 | 위 함수에서의 적용 |
|---|---|---|
| **① 요구사항 파악** | 무엇이 올바른 동작인가? | 학점 기준에 D가 있는가? 평균은 반올림하는가? |
| **② 테스트 사례 설계** | 어떤 입력을 넣어야 오류를 찾는가? | 정상값·경계값·잘못된 값 |
| **③ 예상 결과 계산** | 결과가 얼마여야 하는가? | 90·80·70 → 총점 240, 평균 80, B |
| **④ 테스트 코드 읽기** | 이 코드는 무엇을 검증하는가? | `assert`, `parametrize`, `raises` |
| **⑤ 실패 원인 분석** | 구현이 틀렸나, 테스트가 틀렸나? | 계산식·학점 조건·예상값 확인 |
| **⑥ 테스트 범위 판단** | 아직 검증하지 않은 문제가 있는가? | 문자열·소수·누락값 입력 |

위 함수에서는 다음처럼 직접 테스트 사례를 정할 수 있어야 합니다.

| 입력 | 예상 결과 또는 확인 사항 | 선정 이유 |
|---|---|---|
| `90, 80, 70` | 총점 240, 평균 80, B | 일반적인 정상 입력 |
| `90, 90, 90` | A | A 기준점 |
| `89, 89, 89` | B | A 기준 바로 아래 |
| `100, 100, 100` | 총점 300, A | 허용 최댓값 |
| `0, 0, 0` | 총점 0, F | 허용 최솟값 |
| `-1, 80, 70` | `ValueError` | 허용 범위 아래 |
| `101, 80, 70` | `ValueError` | 허용 범위 위 |
| `"90", 80, 70` | 요구사항에 따라 처리 결정 | 숫자 문자열을 허용하는가? |
| `89.5, 90, 90` | 요구사항에 따라 처리 결정 | 소수 점수를 허용하는가? |

**마지막 두 사례는 먼저 정책을 정해야 합니다.** 현재 코드가 어떻게 동작하는지를 확인하는 것과, 서비스가 어떻게 동작해야 하는지를 정하는 것은 별개의 작업입니다.

Python 문법은 AI가 만든 테스트를 읽고 수정할 정도로 공부하면 됩니다.

```python
def test_calculate_scores():
    result = calculate_scores(90, 80, 70)  # 검사할 함수 실행

    assert result["total"] == 240         # 총점 검증
    assert result["average"] == 80        # 평균 검증
    assert result["grade"] == "B"         # 학점 검증
```

이 코드를 보고 학생이 설명할 수 있어야 합니다.

- 어떤 입력으로 함수를 실행했는가?
- 무엇을 정답으로 가정했는가?
- 무엇을 검증했고, 무엇은 검증하지 않았는가?
- 실패했다면 어디를 확인해야 하는가?

수업도 **사례 설계 → AI 코드 생성 → 실행 → 실패 분석 → 수정** 순서로 진행하면 좋습니다. 평가에서는 테스트 코드 작성량보다, **빠진 사례를 찾아내는지와 요구사항 오류를 발견하는지**에 비중을 두면 됩니다.

즉, 학생이 배워야 할 핵심은 **“AI에게 테스트를 만들게 하는 능력”과 “그 테스트가 제품의 정확성을 제대로 확인하는지 검토하는 능력”**입니다.
