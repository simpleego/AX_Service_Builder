### 전제 기술 스택

이 실습지는 **프런트는 Next.js, 백엔드는 FastAPI**로 나눈 구조를 전제로 합니다. 원본 가이드의 `CLAUDE.md`와 `TRD.md`는 Next.js API를 전제로 쓰였으므로, STEP 11의 첫 프롬프트(P11-1)에서 문서를 먼저 FastAPI 기준으로 바꿉니다.

| 영역 | 기술 | 위치 | 실행 / 테스트 |
| --- | --- | --- | --- |
| 프런트 | Next.js 15, React 19, TypeScript, Tailwind, Jest + RTL | 프로젝트 최상위 | `npm run dev` (3000번 포트) / `npm test` |
| 백엔드 | Python 3.12, FastAPI, Pydantic v2, uv | `backend/` | `uv run fastapi dev app/main.py` (8000번 포트) / `uv run pytest` |
| DB (v0.3부터) | Neon Postgres, SQLAlchemy 2.0, Alembic, psycopg | `backend/` | `uv run alembic upgrade head` |

```text
todo-app/
├─ app/              # Next.js 페이지 (API 라우트는 만들지 않음)
├─ src/
│  ├─ components/    # 화면 컴포넌트
│  ├─ lib/todoApi.ts # FastAPI를 부르는 함수 모음
│  └─ types/
├─ docs/
└─ backend/
   ├─ app/
   │  ├─ main.py          # FastAPI 앱, CORS, 에러 핸들러
   │  ├─ schemas.py       # Pydantic 요청/응답 모델
   │  ├─ repository.py    # 저장소 Protocol + 메모리 구현
   │  ├─ deps.py          # get_repo 의존성
   │  └─ routers/todos.py # /api/todos 엔드포인트
   ├─ tests/
   └─ pyproject.toml
```

**추가 설치:** Python 3.12 이상(`python --version`)과 uv(`uv --version`)가 필요합니다. STEP 11 전에 확인하세요.

**공통 프롬프트 사용법:** 백엔드 작업에서는 TDD 공통 프롬프트의 `npm test`를 `backend 폴더에서 uv run pytest`로, 테스트 파일 이름을 `backend/tests/test_○○.py`로 바꿔서 보냅니다.


```text
[Green] Green 단계로 진행해줘.
- 테스트 파일은 한 글자도 수정하지 마.

- npm test 전체를 실행해서 결과를 보여줘.
```

```text

- 고칠 것이 없으면 "정리할 것 없음"이라고 말해도 돼.
- 끝나면 npm test 전체를 다시 실행하고, 바꾼 내용을 3줄로 요약해줘.
```

## STEP 11. v0.2 — FastAPI 백엔드 만들고 연결하기

**목표:** `backend/` 폴더에 FastAPI 서버를 만들고, 화면이 `http://localhost:8000/api/todos`로 데이터를 주고받게 합니다. 저장은 아직 서버 메모리입니다. 화면 동작은 v0.1과 같고 내부만 바뀝니다.

핵심 설계는 **저장소(Repository) 분리 + FastAPI 의존성 주입**입니다. 라우터는 `Depends(get_repo)`로 받은 저장소만 씁니다. 그래서 테스트에서는 메모리 저장소를, STEP 12에서는 DB 저장소를 끼워 넣기만 하면 되고 라우터와 API 테스트는 그대로 둡니다.

**이번 STEP에서 쓰는 테스트 ID(예시)**

| ID | 대상 | 상황 → 기대 결과 |
| --- | --- | --- |
| VAL-01 | TodoCreate | "우유 사기" → 통과, 앞뒤 공백 제거 |
| VAL-02 | TodoCreate | 빈 문자열, 공백만, 101자 → 실패 |
| VAL-03 | TodoUpdate | `title`만, `completed`만 → 통과 / 빈 객체 → 실패 |
| API-01 | POST /api/todos | 제목 "우유 사기" → 201, `completed=false`, 키는 camelCase |
| API-02 | POST /api/todos | 빈 제목 → 400, `VALIDATION_ERROR` |
| API-03 | POST /api/todos | 101자 제목 → 400, `VALIDATION_ERROR` |
| API-04 | GET /api/todos | 2개 추가 후 조회 → 200, 최신순 |
| API-05 | DELETE /api/todos/999 | 없는 id → 404, `NOT_FOUND` |
| API-06 | PATCH /api/todos/{id} | `completed: true` → 200, 값 바뀜, `updatedAt` 갱신 |
| API-07 | PATCH /api/todos/999 | 없는 id → 404, `NOT_FOUND` |
| API-08 | DELETE /api/todos/{id} | 있는 id → 204, 이후 GET에 없음 |
| API-09 | PATCH /api/todos/abc | 숫자가 아닌 id → 400, `VALIDATION_ERROR` |

### P11-1 문서부터 FastAPI로 바꾸기

기술 스택이 바뀌는 것도 "새 기능"과 같습니다. 원칙대로 **문서를 먼저** 고칩니다.

```text
백엔드를 Next.js API 라우트에서 FastAPI로 바꾸기로 했어. 코드는 아직 쓰지 마.
아래 결정 사항을 반영하려면 어떤 문서의 어디를 바꿔야 하는지 목록으로만 보여줘.

[결정 사항]
- 백엔드는 프로젝트 안 backend/ 폴더, Python 3.12, 패키지 관리는 uv
- FastAPI + Pydantic v2, 테스트는 pytest + FastAPI TestClient
```

비밀 값이 한 번이라도 커밋된 적이 있으면, 지금 지워도 기록에 남습니다. 올리기 전에 기록 전체를 검사합니다.

```text
GitHub에 올리기 전에 커밋 기록 전체를 검사해줘. 수정은 하지 마.
- .env, .env.local, backend/.env 파일이 커밋된 적이 있는지 (git log --all -- 경로)
- 코드나 문서에 postgresql:// 로 시작하는 주소가 들어간 적이 있는지
결과만 알려줘. 찾은 값은 출력하지 말고 파일과 커밋 번호만 알려줘.
```

문제가 없으면 GitHub에서 새 저장소를 만들고 올립니다.

```text
GitHub에 새로 만든 저장소 주소는 https://github.com/○○/todo-app 이야.
원격 저장소를 연결하고 main 브랜치와 태그를 모두 올리는 명령을 하나씩 설명하면서 실행해줘.
```

**주의:** 검사에서 비밀 값이 나오면 올리지 말고, Neon 대시보드에서 **DB 비밀번호부터 바꿉니다**(Reset password). 기록 정리는 그다음에 강사와 함께 합니다.

### P14-5 백엔드 배포 (Render)

학생이 `render.com`에서 직접 합니다. GitHub로 가입한 뒤 New → Web Service → 내 저장소를 고르고 아래처럼 입력합니다.

| 항목 | 입력 값 |
| --- | --- |
| Root Directory | `backend` |
| Runtime / Language | Python 3 |
| Build Command | `pip install uv && uv sync --frozen` |
| Start Command | `uv run uvicorn app.main:app --host 0.0.0.0 --port $PORT` |
| Instance Type | Free |
| Health Check Path | `/health` (Advanced 메뉴) |
| 환경 변수 `DATABASE_URL` | Neon main 브랜치 주소 (`postgresql+psycopg://` 형식) |
| 환경 변수 `CORS_ORIGINS` | 일단 `http://localhost:3000` (P14-7에서 바꿈) |

**확인할 것**

- [ ] Render 로그에 빌드 성공과 서버 시작 메시지가 보인다.
- [ ] `https://○○.onrender.com/health`에서 `{"status":"ok"}`가 보인다.
- [ ] `https://○○.onrender.com/docs`에서 GET /api/todos를 실행하면 로컬에서 넣은 데이터가 보인다. (같은 Neon main을 쓰기 때문)

**팁:** DB 테이블은 STEP 12에서 이미 main 브랜치에 만들었으므로 따로 마이그레이션할 필요가 없습니다. 나중에 테이블 구조를 바꾸면(STEP 15) 배포 전에 로컬에서 main 브랜치를 대상으로 `uv run alembic upgrade head`를 먼저 실행합니다.

### P14-6 프런트 배포 (Vercel)

`vercel.com`에서 GitHub로 가입한 뒤 Add New → Project → 내 저장소를 Import합니다.

| 항목 | 입력 값 |
| --- | --- |
| Framework Preset | Next.js (자동 인식) |
| Root Directory | 그대로 (프로젝트 최상위) |
| 환경 변수 `NEXT_PUBLIC_API_URL` | `https://○○.onrender.com` (끝에 `/` 없이) |

Deploy를 누르고 받은 주소(`https://○○.vercel.app`)를 메모합니다. 이 단계에서는 아직 화면에 에러가 보이는 것이 정상입니다. CORS를 연결하지 않았기 때문입니다.

**주의:** `NEXT_PUBLIC_`로 시작하는 변수는 **빌드할 때 코드에 박힙니다.** 나중에 값을 바꾸면 Vercel의 Deployments에서 Redeploy를 해야 반영됩니다.

### P14-7 CORS 연결하고 최종 확인

Render 대시보드 → 내 서비스 → Environment에서 `CORS_ORIGINS`를 아래처럼 바꾸고 저장 후 재배포합니다.

```text
CORS_ORIGINS=https://○○.vercel.app,http://localhost:3000
```

주소 끝에 `/`를 붙이지 않습니다. 붙이면 브라우저가 보내는 주소와 글자가 달라 CORS 에러가 납니다.

**확인할 것 (배포 주소에서)**

- [ ] `https://○○.vercel.app`에서 추가·완료·삭제·필터·제목 수정이 모두 된다.
- [ ] 새로고침해도, 다른 브라우저나 휴대폰으로 접속해도 데이터가 같다.
- [ ] F12 → Console에 CORS 에러가 없고, Network 탭의 요청이 `onrender.com`으로 간다.
- [ ] 휴대폰 화면에서 깨지지 않는다.
- [ ] 태그를 남긴다: `git tag v1.0 && git push --tags`
